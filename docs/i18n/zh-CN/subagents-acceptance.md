# Subagent 验收场景

[English](../../subagents-acceptance.md) · 英文为准.

状态: [#64](https://github.com/jczhang02/pi-stuff/issues/64) 中待维护者确认的验收覆盖. [设计记录](subagents-design.md)包含已确认的 F01-F33 范围和 Q3-Q60 规则. 下表描述未来要执行的操作与通过条件, 所有场景均尚未执行或通过.

## 使用方式

按[质量保证规则](quality-assurance.md), 在支持的实际 Pi 宿主中使用隔离的项目, 配置和会话数据执行场景. 一份临时开发项目应包含可复现的登录问题, 失败测试, 独立的支付任务和可整合的分支. 上下文与工具检查使用无害的测试指令和数据.

记录被测提交, 宿主与环境, 实际配置, 操作, 任务身份, 观察结果及相关成果. 可用受控模型提供方稳定复现调度, 错误和中断, 但要注明该环境, 不作为真实提供方行为的证据. 超时场景使用较短的配置值, 另行核对文档默认值. 此处不确定 UI 展示和具体工具名.

每一行 F 功能都需要证据, B01-B12 边界场景补充这些功能行. 一个综合开发流程不能替代并行, 串行和依赖图的分别验收. 环境或证据缺失时记为未验证. 下表是后续验证要求, 不要求在本次设计讨论中执行产品代码.

## 执行与任务控制

| 能力                 | 实际操作                                                                              | 通过条件                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| F01 单独委派         | 让一名研究员定位登录失败, 不复制父历史.                                               | 它有独立上下文和任务记录, 中间工作留在自己的会话中, 父代理可取得最终结果.                                                           |
| F02 并行执行         | 有两个执行名额时, 同时派发登录和支付调查.                                             | 两项工作在重叠的执行时段内推进, 结果分别保存, 并发不超过上限.                                                                       |
| F03 串行执行         | 按调查, 修复, 审查建立串行任务.                                                       | 前一项完成后下一项才启动, 并获得所需报告和代码成果.                                                                                 |
| F04 依赖图           | API 实现只依赖较快的 API 调查, 整合任务同时依赖 API 和较慢的数据库分支.               | API 依赖满足且有名额即可开始, 整合等待两份输入. 无效图和依赖失败按 B01, B03 处理.                                                   |
| F05 传递上游结果     | 交给实现代理一份长研究报告及文件和提交引用.                                           | 默认收到最终报告和成果引用, 不附全部过程日志. 超过配置长度时明确标注截断预览, 完整内容仍可读取.                                     |
| F06 后台与前台等待   | 分别后台派发和派发后等待结果; 后台任务执行时让主代理结束一轮回复.                     | 后台派发在任务完成前返回可用身份, 等待可观察对应任务, 主代理结束回复不会停止后台工作.                                               |
| F07 状态与结果       | 在排队, 执行, 等待, 取消中和结束后查询整次派发及单项任务, 续聊后再查旧结果.           | 查询能区分当前情况和任务身份, 提供对应结果与成果引用, 旧结果仍然保留.                                                               |
| F08 限时等待         | 用较短配置等待慢研究员, 到期后再次等待.                                               | 首次等待到期返回当前状态, 子代理继续执行. 完成, 提问和失败可唤醒相关等待. 主代理单次等待默认六十秒.                                 |
| F09 通知             | 主代理处理其他工作时, 让一名研究员完成, 另一名失败.                                   | 父代理收到关联正确任务的完成与失败通知, 能查到对应记录; 失败通知不等无关工作结束才发送, 整次派发结束的通知则在其全部任务结束后发送. |
| F10 取消             | 取消拥有活跃数据库和 API 下级的后端负责人.                                            | 整个分支不再创建下级; 确认执行停止后才完成取消或回收工作区. 已有记录与代码仍可查看, 详见 B04.                                       |
| F11 失败或中止后继续 | 修复代理已经改动文件时让它失败, 随后显式让同一子代理继续; 另执行取消后继续的变体.     | 使用可用的原上下文与部分成果, 新交办独立记录, 原结果保留. 旧图中其他节点不自动重跑, 详见 B03, B09.                                  |
| F12 运行中补充指令   | 工具执行期间要求实现代理优先修登录, 暂缓支付; 另向同次派发的全部运行中子代理补充指令. | 当前轮工具结束后, 下一次模型调用前处理 steering, 仍属于同一任务. 对已结束任务的 steering 明确拒绝.                                  |

## 通信与配置

| 能力                  | 实际操作                                                                  | 通过条件                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| F13 向父代理提问      | 数据库下级向直接父代理询问字段含义, 分别执行及时答复, 无人答复和迟到答复. | 等待时释放名额, 及时答复后重新排队执行; 到期返回未答复, 不猜答案或自动判定整个任务失败. 默认等待十分钟, 迟到回复仍关联原问题. |
| F14 报告发现          | 研究员报告可能出错的文件, 随后继续调查.                                   | 父代理可读取发现, 子代理无须等待答复即可继续工作.                                                                             |
| F15 代理收件箱        | 数据库代理向同次派发中另一层级的 API 代理发送字段约定.                    | 按已知 ID 在派发范围内投递, 接收者下次模型处理前读到消息. 已结束任务和消息范围见 B06, 管理权限见 B10.                         |
| F16 临时角色          | 临时定义一个有专用指令和有限工具的发布说明调查员.                         | 无须先创建角色文件即可使用该定义, 工具仍受父级范围限制.                                                                       |
| F17 角色文件          | 发现项目和用户角色文件, 显式选择 reviewer, 再执行一次不指定角色的派发.    | 使用选中的角色, 未指定时使用通用角色; 不因任务提到数据库而自动选换角色.                                                       |
| F18 模型与思考强度    | 调用, 角色, 项目, 用户和父级配置分别设置不同值, 再逐层移除高优先级设置.   | 实际值遵循 Q42 优先级. 角色文件修改后, 已排队任务保留接受时的配置, 后续续聊重新解析.                                          |
| F19 工具选择          | 分别派只读研究员, 可写实现代理, 再让下级请求父级没有的工具.               | 各自只获得允许的工具. 默认研究员没有任意 shell 或写入型扩展, 下级不能扩大父级范围, 详见 B10.                                  |
| F20 工作目录          | 派发到 API 子目录, 再显式指定非 Git 文档目录执行写任务.                   | 相对路径对应所选基线中的目标位置. 非 Git 直接写入必须显式选择, 不能作为隔离失败的退路.                                        |
| F21 项目规则与 skills | 在所选项目放置无害的项目指令和相关已配置 skill, 再委派匹配工作.           | 子代理按预期工作目录加载资源, 上下文与工作能体现取得了指令和 skill. 仅加载 skill 不会授予扩展工具.                            |

## 限制, 代码与记录

| 能力              | 实际操作                                                                    | 通过条件                                                                                                                                                             |
| ----------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F22 资源限制      | 跨两次顶层派发占满主会话名额, 再创建接近限制的下级和续聊任务.               | 默认主会话并发八项, 每次顶层派发累计六十四项, 深度三层且主代理为零层. 初始任务, 递归和续聊计数, Pi 请求重试不计为新任务. 修改配置后限制同样有效, 详见 B01-B02.       |
| F23 执行超时      | 用较短执行时限运行实现任务, 包含工具调用和显式等待阶段.                     | 只有 Q27 规定的执行阶段消耗时限; 超时停止该任务与下级, 保留成果和原因, 不自动重跑. 默认执行时限三十分钟, 详见 B05.                                                   |
| F24 提供方重试    | 制造可重试的提供方或网络响应, 再单独制造代码测试失败.                       | 提供方请求按 Pi 配置在同一任务内重试. 失败测试或任意失败交办不会自动作为新任务重跑.                                                                                  |
| F25 用量统计      | 运行一个负责人, 两个下级和一次后续交办, 其中包含提供方重试.                 | 能查看每项任务可获得的输入, 输出, 缓存 token, 费用和轮数; 汇总不重复计算下级, 不覆盖旧任务. 提供方未给出的数据明确标为缺失, 不编造数值, 不宣称硬性 token 或金额预算. |
| F26 Worktree 管理 | 从有未提交修改的 Git 工作区派两名写入者, 收取代码后回收符合条件的 worktree. | 各自有独立基线和成果, 返回提交, 差异与检查情况, 由主代理决定应用. 原工作区保持原样. 初始化失败, 未跟踪文件和清理变体见 B07-B08.                                      |
| F27 分支继承      | 修复后安排审查, 另用整合任务合并两条写入分支.                               | 单一输入直接看到上游分支, 多条代码分支显式整合并处理冲突, 后续任务继承整合成果.                                                                                      |
| F28 持久化与恢复  | 一批任务运行中关闭或中断主会话, 重开后查看已完成和未完成任务.               | 恢复可用记录与上下文. 未完成工作记为中断并等待显式继续, 已保存写操作不自动重放. 缺失或损坏记录及成果按 B09 处理.                                                     |
| F29 生命周期事件  | 用扩展观察任务事件, 再让监听器抛错.                                         | 事件能对应生命周期活动, 监听失败记录为扩展错误, 不改变任务结果或干扰调度.                                                                                            |

## 新增能力

| 能力               | 实际操作                                                                                  | 通过条件                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| F30 完成后续聊     | 让同一 reviewer 复查修改后的成果, 分别在主会话重开前后执行.                               | 保留身份与上下文, 每次交办独立记录结果; 写任务续聊从所选旧成果新建任务分支. 旧报告可查, 不自动重跑已使用它的下游任务.             |

| F32 递归委派       | 后端负责人派数据库与 API 下级, 其中一个较晚交付, 一个失败, 再尝试超限派发.                | 共享额度, 深度和工具范围有效; 等待释放名额, 负责人处理失败并汇总下级结果后最终交付. 分支取消和管理权限见 B04, B10.                |
| F33 子代理扩展工具 | 两名研究员使用本项目网页工具, 清空父代理内容, 再取消其中一名子代理的请求.                 | 按各自白名单独立初始化所需工具. 清空父内容和取消某子代理不能清除或取消其他会话的内容与工作. 第三方全局状态隔离仍需单独的实现证据. |

## 边界场景

| 场景               | 实际操作与必须观察到的结果                                                                                                                                                                                                                               | 设计规则                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| B01 派发检查       | 分别提交依赖循环, 不存在的依赖, 缺失角色和无效工具选择. 每次均不启动任务或消耗累计额度. 再检查深度与累计数量边界; 有效任务仅缺并发名额时进入队列.                                                                                                        | Q18, Q24, Q26, Q28, Q50          |
| B02 等待与额度     | 配置两个执行名额, 两名负责人派下级后等待. 下级必须能运行, 负责人恢复时重新排队. 增加另一次顶层派发, 检查主会话共享并发而各次累计额度独立; 续聊计入对应额度.                                                                                              | Q15, Q21, Q24, Q26               |
| B03 失败与队列     | 调查 A 失败时依赖它的 B 尚未启动, 无关 C 继续. B 以跳过结束并保留原因. 显式补救产生新结果, 旧 B 不自动重跑. 在成功任务后排入续聊, 确认先后执行且同一子代理不重叠执行. 另让有后续排队工作的子代理失败, 取消或超时, 队列必须等待调用方明确继续或取消.      | Q14, Q20, Q22-Q23, Q29, Q32, Q56 |
| B04 取消时机       | 分别在排队, 初始化, 工具执行和显式等待下级时取消. 被取消分支不能再派下级, 取消完成后不能恢复运行. 工具延迟停止时保留正在取消及活跃名额, 下一任务与清理须等待, 未保存的部分成果保留. 另取消包含多个独立顶层任务的整次派发.                                | Q17, Q36, Q47                    |
| B05 三种超时       | 结果等待到期而子代理继续; 问题无人回答但仍可做独立工作; 执行时限耗尽而下级还在运行. 分别验证对应结果, 排队与等待时间的排除, 可配置数值和原因记录.                                                                                                        | Q27, Q40, Q46, Q48               |
| B06 消息时机与范围 | 工具执行时发普通消息和 steering, 再向已结束任务发送两者. 普通消息保留并在下次模型处理机会送达; 已结束任务收到消息只通知主代理, steering 则拒绝. 检查同级, 跨层级和跨派发联系; 跨派发只能由主代理转交.                                                    | Q38-Q40, Q49                     |
| B07 基线与配置     | 从有已跟踪未提交修改的目录派发, 显式选入一个未跟踪文件, 留下另一个未选文件. 检查快照内容及原目录不变. 排队或执行时修改主代码与角色配置, 已接受快照保持稳定; 显式实时读取与新续聊使用各自选定输入.                                                        | Q19, Q33-Q34, Q41-Q42, Q51-Q52   |
| B08 交接与清理     | 制造 worktree 创建失败, 再执行两名独立写入者与有冲突的显式整合. 初始化失败不能退回原目录. 先查看返回成果再明确应用. 回收已保存且无活跃任务的 worktree, 保留分支记录, 未保存修改阻止自动删除. 非 Git 写入仅在显式选择后执行.                              | Q30-Q31, Q35-Q37                 |
| B09 会话与成果恢复 | 有子任务时正常切换或退出后重开; 另分别在任务创建, 状态变化和结果交付后, 整批结束前中断 Pi. 检查恢复记录和显式继续. 测试 worktree 缺失但提交存在, 原提交缺失, 上下文缺失, 以及多份可用记录中一份损坏. 可恢复部分继续恢复, 缺口明确报告, 不偷换会话或基线. | Q25, Q44, Q53, Q57               |
| B10 工具与管理权限 | 只读研究员为下级请求写工具, 同级尝试取消, steering 和续聊自己下级分支之外的任务. 请求须被拒绝且目标不受影响, 有权限的上级可在自身范围内安排工作. 检查默认只读工具和各子会话扩展状态; 工具白名单本身不作为操作系统沙箱证据.                               | Q18, Q45, Q58-Q59                |
| B11 最终交付含义   | 负责人先报告, 下级随后给出新发现. 负责人等待时不占名额, 最终交付前在同一任务内汇总. 对比成功复现失败测试的调查和未修好问题的实现: 只有完成交办者放行依赖, 代码验收与测试证据分别可查.                                                                    | Q16, Q23, Q55, Q60               |
| B12 证据与结果保留 | 交付长报告, 让同一 reviewer 续聊, 记录提供方重试和用量, 再触发监听器失败. 读取完整新旧报告, 对照单任务与汇总数据, 确认监听错误不改结果. 同时检查复制历史内容和独立子会话网页缓存, 不只看任务记录.                                                        | Q14, Q19, Q35, Q43, Q45, Q54     |

## 确认与后续实现工作

维护者已确认至 Q60 的行为决定, 本场景覆盖及双方整体理解仍待确认. 确认后按约定进入独立 UI 设计, 若具体 UI 场景暴露问题, 可以重新讨论对应行为.

工具名称和参数, 源码布局, 调度与会话接入, 存储格式, 扩展隔离及停止进程的机制仍需实现设计与证据. 本规格不代表这些机制已经存在, 也不代表任意第三方状态或外部副作用已经能隔离或撤销. F01-F33 以外的范围继续以设计记录为准.
