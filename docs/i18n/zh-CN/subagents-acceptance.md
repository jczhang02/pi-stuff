# Subagent 验收场景

[English](../../subagents-acceptance.md) · 英文为准.

状态: [#64](https://github.com/jczhang02/pi-stuff/issues/64) 中待维护者确认的验收覆盖. [设计记录](subagents-design.md)保留已确认的 F01-F33 范围, 并合入 Q1-Q60 的[源码审查修订](subagents-decision-review.md). 修订属于建议, 尚未获得新的批准. 下表描述未来要执行的操作与通过条件, 所有场景均尚未执行或通过.

## 使用方式

按[质量保证规则](quality-assurance.md), 在支持的实际 Pi 宿主中使用隔离的项目, 配置和会话数据执行场景. 一份临时开发项目应包含可复现的登录问题, 失败测试, 独立的支付任务和可整合的分支. 上下文与工具检查使用无害的测试指令和数据.

记录被测提交, 宿主与环境, 实际配置, 操作, 任务身份, 观察结果及相关成果. 可用受控模型提供方稳定复现调度, 错误和中断, 但要注明该环境, 不作为真实提供方行为的证据. 超时场景使用较短的配置值, 另行核对文档默认值. 对模型的入口确定为单一 `subagent` 工具; 检查暴露的工具列表, 通过其命令执行由模型调用的子代理操作. UI 展示及具体命令名和参数仍待确定.

每一行 F 功能都需要证据, B01-B12 边界场景补充这些功能行. 一个综合开发流程不能替代并行, 串行和依赖图的分别验收. 环境或证据缺失时记为未验证. 下表是后续验证要求, 不要求在本次设计讨论中执行产品代码.

## 执行与任务控制

| 能力                 | 实际操作                                                                              | 通过条件                                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| F01 单独委派         | 让一名研究员定位登录失败, 不复制父历史.                                               | 它有独立上下文和任务记录, 中间工作留在自己的会话中, 父代理可取得最终结果.                                                               |
| F02 并行执行         | 有两个执行名额时, 同时派发登录和支付调查.                                             | 两项工作在重叠的执行时段内推进, 结果分别保存, 并发不超过上限.                                                                           |
| F03 串行执行         | 按调查, 修复, 审查建立串行任务.                                                       | 前一项完成后下一项才启动, 并获得所需报告和代码成果.                                                                                     |
| F04 依赖图           | API 实现只依赖较快的 API 调查, 整合任务同时依赖 API 和较慢的数据库分支.               | API 依赖满足且有名额即可开始, 整合等待两份输入. 无效图和依赖失败按 B01, B03 处理.                                                       |
| F05 传递上游结果     | 交给实现代理一份长研究报告及文件和提交引用.                                           | 默认收到最终报告和成果引用, 不附全部过程日志. 超过配置长度时明确标注截断预览, 完整内容仍可读取.                                         |
| F06 后台与前台等待   | 分别后台派发和派发后等待结果; 后台任务执行时让主代理结束一轮回复.                     | 后台派发在任务完成前返回可用身份, 等待可观察对应任务, 主代理结束回复不会停止其顶层后台派发. 下级使用后台派发仍拥有对应下级任务并须汇合. |
| F07 状态与结果       | 在排队, 执行, 等待, 取消中和结束后查询整次派发及单项任务, 续聊后再查旧结果.           | 查询区分执行状态, 交办结果声明和主代理验收, 明确任务与代理归属, 续聊后保留固定旧结果引用.                                               |
| F08 限时等待         | 用较短配置等待慢研究员, 到期后再次等待.                                               | 等待到期返回当前状态, 子代理继续. 完成, 提问与失败唤醒相关等待. 可配置的六十秒试用值限制单次等待, 不代表自动轮询周期.                   |
| F09 通知             | 主代理处理其他工作时, 让一名研究员完成, 另一名失败.                                   | 父代理收到关联正确任务的完成与失败通知, 能查到对应记录; 失败通知不等无关工作结束才发送, 整次派发结束的通知则在其全部任务结束后发送.     |
| F10 取消             | 取消拥有活跃数据库和 API 下级的后端负责人.                                            | 整个分支不再创建下级; 确认执行停止后才完成取消或回收工作区. 已有记录与代码仍可查看, 详见 B04.                                           |
| F11 失败或中止后继续 | 修复代理已经改动文件时让它失败, 随后显式让同一子代理继续; 另执行取消后继续的变体.     | 使用可用的原上下文与部分成果, 新交办独立记录, 原结果保留. 旧图中其他节点不自动重跑, 详见 B03, B09.                                      |
| F12 运行中补充指令   | 工具执行期间要求实现代理优先修登录, 暂缓支付; 另向同次派发的全部运行中子代理补充指令. | 当前轮工具结束后, 下一次模型调用前处理 steering, 仍属于同一任务. 对已结束任务的 steering 明确拒绝.                                      |

## 通信与配置

| 能力                  | 实际操作                                                                  | 通过条件                                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F13 向父代理提问      | 数据库下级向直接父代理询问字段含义, 分别执行及时答复, 无人答复和迟到答复. | 等待且其他活跃执行结束后释放名额, 见 B02; 及时答复后重新排队执行; 到期返回未答复, 不猜答案或自动判定整个任务失败. 默认等待十分钟, 迟到回复仍关联原问题. |
| F14 报告发现          | 研究员报告可能出错的文件, 随后继续调查.                                   | 父代理可读取发现, 子代理无须等待答复即可继续工作.                                                                                                       |
| F15 代理收件箱        | 数据库代理向同次派发中另一层级的 API 代理发送字段约定.                    | 按已知 ID 在派发范围内投递, 接收者下次模型处理前读到消息. 已结束任务和消息范围见 B06, 管理权限见 B10.                                                   |
| F16 临时角色          | 临时定义一个有专用指令和有限工具的发布说明调查员.                         | 无须先创建角色文件即可使用该定义, 工具仍受父级范围限制.                                                                                                 |
| F17 角色文件          | 发现项目和用户角色文件, 显式选择 reviewer, 再执行一次不指定角色的派发.    | 使用选中的角色, 未指定时使用通用角色; 不因任务提到数据库而自动选换角色.                                                                                 |
| F18 模型与思考强度    | 调用, 角色, 项目, 用户和父级配置分别设置不同值, 再逐层移除高优先级设置.   | 新代理遵循 Q42 优先级. 角色文件修改后, 排队任务与已保留代理的续聊沿用保存值. 显式受支持覆盖被记录且仍受上限约束, 新建代理使用修改后的角色.              |
| F19 工具选择          | 分别派只读研究员, 可写实现代理, 再让下级请求父级没有的工具.               | 工具暴露和实际执行权限受父级上限限制. 续聊前收紧继承限制, 保存配置不能绕过它. 默认只读角色没有任意 shell 或写扩展, 详见 B10.                            |
| F20 工作目录          | 派发到 API 子目录, 再显式指定非 Git 文档目录执行写任务.                   | 相对路径对应所选基线中的目标位置. 非 Git 直接写入必须显式选择, 不能作为隔离失败的退路.                                                                  |
| F21 项目规则与 skills | 在所选项目放置无害的项目指令和相关已配置 skill, 再委派匹配工作.           | 子代理按预期工作目录加载资源, 上下文与工作能体现取得了指令和 skill. 仅加载 skill 不会授予扩展工具.                                                      |

## 限制, 代码与记录

| 能力              | 实际操作                                                                    | 通过条件                                                                                                                                                                                                                    |
| ----------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F22 资源限制      | 跨两次顶层派发占满主会话名额, 再创建接近限制的下级和续聊任务.               | 可配置试用值为主会话八个执行名额, 单次派发累计六十四项已接受任务, 主代理零层且最大三层. 等待或上下文保留不返还累计数或深度, 续聊计入原派发, 提供方重试不新建任务. 用小配置验证 B01-B02, 记录资源消耗但不宣称默认值已经优化. |
| F23 执行超时      | 用较短执行时限运行实现任务, 包含工具调用和显式等待阶段.                     | 仅 Q27 执行阶段消耗配置期限. 到期请求分支取消, 保留成果和原因, 按实际停止规则收尾且不重跑. 未配置任务没有累计执行期限, 工具和提供方自身超时另算, 详见 B05.                                                                  |
| F24 提供方重试    | 制造可重试的提供方或网络响应, 再单独制造代码测试失败.                       | 提供方请求按 Pi 配置在同一任务内重试. 失败测试或任意失败交办不会自动作为新任务重跑.                                                                                                                                         |
| F25 用量统计      | 运行一个负责人, 两个下级和一次后续交办, 其中包含提供方重试.                 | 能查看每项任务可获得的输入, 输出, 缓存 token, 费用和轮数; 汇总不重复计算下级, 不覆盖旧任务. 提供方未给出的数据明确标为缺失, 不编造数值, 不宣称硬性 token 或金额预算.                                                        |
| F26 Worktree 管理 | 从有未提交修改的 Git 工作区派两名写入者, 收取代码后回收符合条件的 worktree. | 独立写入者各有 worktree, 同一保留代理跨交办复用工作区. 返回固定提交, 差异与检查供明确应用, 原目录不变. 明确释放工作区并保存内容后才自动回收, 详见 B07-B08.                                                                  |
| F27 分支继承      | 修复后安排审查, 另用整合任务合并两条写入分支.                               | 单一输入读取固定上游提交. 多份代码成果显式整合并处理冲突. 后续续聊推进原分支, 不能默默改变已接受下游的输入.                                                                                                                 |
| F28 持久化与恢复  | 一批任务运行中关闭或中断主会话, 重开后查看已完成和未完成任务.               | 恢复可用记录, 上下文和固定成果; 未完工作记为中断并显式继续, 不重放写操作. 终态可靠保存与通知, 可选监听错误分开. 状态缺失与外部活动不明按 B09 处理.                                                                          |
| F29 生命周期事件  | 用扩展观察任务事件, 再让监听器抛错.                                         | 可选观察者失败被记录, 不改结果或阻塞调度. 必需持久化或成果保存失败仍是核心错误, 不能套用观察者规则隐藏.                                                                                                                     |

## 新增能力

| 能力               | 实际操作                                                                                  | 通过条件                                                                                                                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F30 完成后续聊     | 让同一 reviewer 复查修改后的成果, 分别在主会话重开前后执行.                               | 保留逻辑身份, 可恢复历史与工作区, 包括卸载并重建活跃运行对象后, 每次交办独立记录并固定成果. 写续聊默认复用保留工作区, 改基线须明确; 工作区已释放或缺失时按 Q53 恢复或明确失败. 早先父任务和使用者维持终态, 补救或换基线不能默默丢弃部分成果. |
| F31 复制父历史     | 分别派新上下文子代理和复制历史子代理, 历史含工具结果及压缩摘要; 派发后再给父代理补充信息. | 在合法分叉边界复制已完成可见历史及已有摘要. 加测派发时有未完成工具调用, 子请求仍须合法, 分叉控制记录明确标识. 不隐含复制活跃句柄, 权限, 工作区修改或之后的父消息.                                                                            |
| F32 递归委派       | 后端负责人派数据库与 API 下级, 其中一个较晚交付, 一个失败, 再尝试超限派发.                | 共享额度, 深度和权限有效, 安全等待释放名额. 负责人汇合自己派出的任务并处理未读下级结果. 日后给保留下级另派工作不重新打开旧父任务. 已显式汇合时不要求多一轮重复总结, 详见 B04/B10/B11.                                                        |
| F33 子代理扩展工具 | 两名研究员使用本项目网页工具, 清空父代理内容, 再取消其中一名子代理的请求.                 | 按选定扩展入口为子会话初始化并过滤工具暴露. 父缓存清理与单子代理取消不影响其他会话. 加测包含多个工具和 factory 钩子的入口, 证明过滤不等于阻止初始化副作用. 不支持或全局状态不安全的入口明确失败, 不宣称普遍隔离.                             |

## 边界场景

| 场景               | 实际操作与必须观察到的结果                                                                                                                                                                                                                                             | 设计规则                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| B01 派发检查       | 启动前拒绝无效图, 角色, 工具, 深度与数量输入, 不建任务或消耗额度. 并发接受有效派发不能超订累计额度, 仅执行名额不足时排队. 有效接受后让一个 worktree 初始化失败, 记录启动失败, 保留已接受计数, 无关已启动工作继续.                                                      | Q18, Q24, Q26, Q28, Q50          |
| B02 等待与额度     | 配置两个执行名额, 两名负责人委派并等待, 下级能运行, 负责人恢复时重新取得名额. 等待时另保留活跃工具, 不得提前释放名额. 保留上下文不占执行名额, 等待或新的续聊调用不重置原派发累计数或深度. 跨派发共享并发.                                                              | Q15, Q21, Q24, Q26               |
| B03 失败与队列     | A 失败且依赖它的 B 未启动, B 跳过而无关 C 继续. 显式补救产生新结果, 旧 B 不重跑. 成功交办使同代理队列串行推进, 异常暂停未被取消的后续工作; 有权限调用方可明确先运行补救再释放队列. 普通消息不能释放队列. 补救可放行独立未取消项, 不能重新放行被取消分支拥有的排队任务. | Q14, Q20, Q22-Q23, Q29, Q32, Q56 |
| B04 取消时机       | 分别在排队, 初始化, 工具执行和显式等待下级时取消. 被取消分支不能再派下级, 取消完成后不能恢复运行. 工具延迟停止时保留正在取消及活跃名额, 下一任务与清理须等待, 未保存的部分成果保留. 另取消包含多个独立顶层任务的整次派发.                                              | Q17, Q36, Q47                    |
| B05 三种超时       | 结果等待到期而下级继续; 问题超时但仍有独立工作; 下级运行时配置的执行期限到达. 检查不同结果, 计时排除, 实际停止确认且不自动重跑. 未配置任务无累计期限, 重复未变化等待不构成自动唤醒策略.                                                                                | Q27, Q40, Q46, Q48               |
| B06 消息时机与范围 | 工具调用中发消息和 steering, 再向结束任务发送. 区分保存接收与模型消费. 已结束任务消息通知主代理但不重启, steering 被拒绝. 测试同级, 跨层级和跨派发转交. 显式续聊须另外具备管理权限并新建记录, 与普通消息不同.                                                          | Q38-Q40, Q49                     |
| B07 基线与配置     | 捕获已跟踪未提交修改和一个选定未跟踪文件, 原暂存区与工作目录不变. 捕获中改变源代码时重试或失败, 不默默混合版本. 接受后修改源代码与角色文件, 代码输入及保存配置维持稳定. 续聊复用工作区和配置, 明确换基线或模型时记录. 加测有未完成工具调用的分叉及显式实时读代码.      | Q19, Q33-Q34, Q41-Q42, Q51-Q52   |
| B08 交接与清理     | 隔离失败不退回原目录. 独立写入者通过显式整合处理冲突, 消费固定提交而非移动分支头. 闲置工作区保留供续聊. 明确释放后仅在内容已保存时清理, 加测未跟踪和忽略成果及运行进程. 非 Git 直接写入仍显式选择. 推进旧分支后检查旧结果不变.                                         | Q30-Q31, Q35-Q37                 |
| B09 会话与成果恢复 | 有下级时真正切换或退出 Pi 会话后重开, 回复结束与 UI 焦点变化不停止它们. 在创建, 状态变化与结果保存后中断, 恢复可用记录并报告缺口. 测试工作区缺失但提交存在, 未保存内容, 上下文或提交缺失, 损坏记录及外部活动不明. 恢复会话重新绑定, 显式继续, 不替换成父目录.          | Q25, Q44, Q53, Q57               |
| B10 工具与管理权限 | 拒绝只读父级向下授予更宽工具或权限, 拒绝同级越过归属取消, steering 或续聊. 续聊前收紧继承权限, 保存配置不能恢复旧授权. 检查独立扩展初始化, 多工具 factory, 共享全局和缓存取消. 工具名, worktree cwd 和复制历史不等于操作系统沙箱.                                      | Q18, Q45, Q58-Q59                |
| B11 最终交付含义   | 负责人报告后下级才给出发现, 在同一任务内汇合并处理. 另测已经显式汇合时无须额外总结轮次. 给保留下级后续交办, 旧父任务维持终态. 比较正常执行但声明无法完成, 没有声明和声明已复现问题: 仅收尾且声明完成者放行依赖, 错误的完成声明仍可被主代理验收否决.                    | Q16, Q23, Q55, Q60               |
