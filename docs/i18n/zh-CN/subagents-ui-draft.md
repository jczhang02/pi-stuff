[English](../../subagents-ui-draft.md) · 英文为规范版本.

状态: 2026-09-14 在 [#64](https://github.com/jczhang02/pi-stuff/issues/64#issuecomment-5663486691) 授权制作的讨论草案. 三张图是生成的概念图, 任务, 路径, 用量与提交均为虚构示例, 不是运行中扩展的截图. [行为设计](subagents-design.md), [验收场景](subagents-acceptance.md)和 [Pi 宿主设计规则](design.md)继续约束本草案. 本文不新增已批准功能, 也不确定工具参数.

## 建议的交互方式

主对话继续承担交办和沟通. 平时只显示简短的协作摘要, 需要检查时打开任务列表, 再展开某个任务的记录, 成果或操作. 查看任务不会悄悄改变主输入区的发送对象. 专门操作某个任务时, 输入区先标出操作类型和目标任务.

列表按当前任务归属组织. 同一个代理以前做过的工作放在历史中, 不会重新成为旧任务的活动下级. 同一个代理先后替不同父任务工作时, 这样才能看懂取消分支究竟会影响谁.

### 主对话

![主对话中的协作摘要及主代理转交的问题](../../assets/subagents-ui/chat.png)

例子是修复登录态失效: API 与数据库并行调查, 然后实现和审查. 每一行回答三个问题: 谁在做什么, 处于什么状态, 在等什么. 提问, 失败和交付形成有用的对话事件; 普通工具活动更新现有摘要. 图中四行是小规模示例. 更多任务显示有长度限制的预览, 明示隐藏数量, 并提供完整列表入口.

图中的问题由主代理决定转交给用户. 子代理通常先问直接父代理, 父代理根据已有信息回答, 不会每问一次就打断人. 此处主输入区仍写着 "发送给: 主代理". 分镜中的定向答复输入区需要单独进入.

### 任务列表与选中任务详情

![按任务归属排列的列表, 选中集成任务及其固定输入成果, 保留主对话草稿](../../assets/subagents-ui/inspector.png)

第二张图是同一例子的稍后时刻. T1 与 T2 已交付调查报告. 负责人 T3 派出 T3.1 与 T3.2, 此时等待 T3.2; 审查员 T4 仍在等 T3. T3.2 使用 T3.1 已保存的成果. 选中 T3.2 后, 能看到父任务, 当前工具, 最近进展和输入提交, 不必把每次工具调用都塞进主对话.

详情分为概况, 记录, 成果和配置. 代理身份可以进入它的历次交办与排队任务. 状态更新保留选中项和滚动位置. "需要处理"筛选可以找到问题和失败, 不会在用户移动光标时持续重排列表. 列表获得焦点时, 主对话草稿保留但不接收输入.

### 需要介入的场景

![回答问题, 纠正当前任务, 取消分支和向同一代理续聊的四个独立场景](../../assets/subagents-ui/interventions.png)

四格是不同时间的独立场景, 不是同时弹出四个对话框. 前两格区分回答已有问题和纠正当前工作. 第三格呈现尚未停妥的取消过程. 第四格向保留的审查员交办新任务, 旧报告保持不变. 图表达操作意图; 操作样式, 最终文案和快捷键仍是提案.

## 场景交互过程

| 场景                                | 像真实使用那样走一遍                                                                                                                                   | 反馈与返回行为                                                                                                                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S01. 派发与依赖推进                 | 让主代理并行调查 API 和数据库, 再实现并审查. 主代理派发后, 摘要显示 T1/T2 活动, T3/T4 等待明确的依赖. 纯串行场景只显示一个活动任务和后续依赖.          | 某任务自身依赖和资源就绪即可启动. 一次结果等待结束, 后台工作仍可继续. 显示真实状态与原因, 不编造完成百分比.                                                                                |
| S02. 查看但不切换发送对象           | 打开任务列表, 选中集成任务 T3.2, 查看最近活动, 再进入记录或成果. 用任务 ID, 代理或标题搜索/筛选保留的交办记录.                                         | 标题中的选中任务与主输入区接收者分开显示. 返回后恢复主草稿, 光标和焦点. 关闭查看不会取消已在后台运行的任务.                                                                                |
| S03. 回答下级问题                   | 数据库任务 T2 向直接父代理询问旧客户端是否保留七天有效期. 父代理回答, 或将无法确定的选择交给用户. 定向答复区写明 "答复 T2 / Q1", 输入框上方保留原问题. | 收到答复与用于模型输入分开呈现. 回复始终属于 Q1. 超时提示未收到回答; 晚到的回复不启动新任务. 等下级的负责人会被问题唤醒, 在同一父任务内回答.                                               |
| S04. 纠正当前工作                   | 审查员 T4 正在读文件, 选择 "纠正当前任务", 补充检查刷新令牌竞争的要求. 草稿标明 T4 和操作类型.                                                         | 使用前显示 "已接纳, 等待本轮工具结束". 已接纳的纠正必须在 T4 内处理后才能完成. 若 T4 先结束, 拒绝纠正, 提供显式续聊草稿入口. 若取消或失败阻止处理, 在 T4 保留并报告未处理指令.             |
| S05. 传递一个发现                   | 数据库子代理将约定字段名告诉 API 同级, 父代理可在记录里查看交流. 用户选择普通消息时, 能看到目标代理和任务.                                             | "已保存, 尚未使用"不等于 "已理解". 已结束任务收到的消息保留为该任务未使用消息, 不释放暂停队列, 也不自动变成后来任务的输入. 跨派发通信经主代理转交.                                         |
| S06. 请同一个审查员复查             | T4 交付后, 在保留的审查员上选择 "交办新任务", 要求第二次审查. 显示保存的上下文/配置和实际起始代码基线; 显式换基线时可见.                               | 创建独立记录 T5, 保留 T4 报告和固定成果. 审查员忙时 T5 排队. 前次异常导致队列暂停时, 显示暂停原因和明确的补救/放行选择, 不显示成执行中.                                                    |
| S07. 取消一个分支                   | 选中负责人 T3, 选择 "取消此任务及下级", 查看受影响的未结束所属任务. 已完成的 T3.1 保持完成; 同一批代理后来承接的无关任务不属于这个分支.                | 接纳后显示取消中及未停妥工具, 例如 T3.2 的测试. 阻止分支启动新工作. 停妥前不显示已停止, 不释放执行名额, 不启动同代理下一任务, 不提供工作区清理. 取消期间仍可返回主对话.                    |
| S08. 中断后恢复                     | 重开主会话, 查看恢复的任务记录, 上下文, 代码基线和缺失内容. 确认现有执行归属后, 才将未完成工作呈现为中断或允许继续.                                    | 另一个实例仍有效, 或进程活动不明, 都显示为接管阻碍. 核对后仍需显式继续, 不自动重放写操作. 区分已重建的提交代码和无法恢复的未保存内容.                                                      |
| S09. 查看交付的代码                 | 打开工作代理的成果: 报告, 固定提交, 修改文件, diff 和检查证据. 每项输入可追到来源任务. 请主代理检查或应用选定成果.                                     | "已交付"表示声明完成且必要成果已保存可读, 与 "主代理尚未验收"分开. 多份写成果需显式集成任务. 后来分支前进不能改变旧输入. 未保存内容显示未保存, 不冒充交付提交.                             |
| S10. 看懂失败和阻塞                 | 调查失败, 未启动的消费者显示跳过及依赖原因, 无关工作继续. 随后补救调查成功.                                                                            | 旧失败/跳过图保留. 主代理显式引用新结果派发后续工作. 区分启动/记录保存错误, 无法完成声明和提供方重试. 提供方重试不代表任意失败任务都自动重跑.                                              |
| S11. 查看配置与限制                 | 配置页显示角色文件来源或内联角色, 模型/思考级别, 历史复制选项, 工具, 扩展, 规则/技能, 工作区, 生效限制和用量. 只读审查员可以解释为什么没有写工具.      | 保存的接纳配置与当前限制及显式变更分开. 权限收紧可请求取消受影响的在途工作, 未停妥就如实显示. 等执行名额, 等回答, 配置的执行超时分别解释. 金额/token 是统计, 不是硬预算.                   |
| S12. 离开视图, 释放工作区, 退出会话 | 从详情返回聊天; 另行请求交付后的工作区释放; 另行切换或退出 Pi 会话.                                                                                    | 关闭查看恢复焦点. 显式清理报告阻止删除的未保存, 未跟踪或忽略内容. 真正离开会话时持续显示停止/保存, 两者都完成后才成功; 保存失败或工具慢停会阻止成功离开. 仅结束主回复仍保留会话内后台工作. |

## 状态与操作

列表使用容易读懂的状态词并附具体原因. 排查问题所需的细分信息保留在记录里.

| 界面状态                                   | 用户能知道什么                                | 有用的操作                        |
| ------------------------------------------ | --------------------------------------------- | --------------------------------- |
| 排队中                                     | 等执行名额, 或等同一代理的前次交办.           | 查看队列及排序原因.               |
| 等待依赖 / 回答 / 下级                     | 哪个任务, 问题或下级尚未结束.                 | 查看依赖, 回答问题或检查下级.     |
| 执行中                                     | 当前模型/工具阶段, 最近报告的进展.            | 读记录, 发消息, 纠正或请求取消.   |
| 取消中                                     | 已接纳取消, 哪些活动尚未确认停妥.             | 查看剩余活动或返回聊天.           |
| 已交付                                     | 必要成果已保存可读并声明完成, 主代理验收另计. | 查看成果或续聊.                   |
| 失败 / 无法完成 / 已取消 / 已跳过 / 已中断 | 实际结束或恢复原因, 保留成果及队列影响.       | 查看证据, 选择适用的补救或新工作. |
| 活动不明 / 恢复受阻                        | 执行归属或必要的保存材料尚未确认.             | 查看阻碍, 此时不能继续执行.       |

操作遵守当前权限, 不从历史代理血缘推断. 原负责人可能有资格复用旧子代理, 但无权纠正它当前由主代理拥有的任务. 如果选中后状态已变化, 执行操作时重新检查并说明不再适用的原因. 不悄悄将纠正转为续聊, 不将取消改写为其他终态. 必需记录保存失败醒目显示; 可选观察者错误属于诊断信息, 不能改写任务结果.

对模型仍只暴露一个 `subagent` 工具, 用 `command` 选择操作. 上述人机界面的按钮文字不规定工具命令名或 JSON 参数. 列表, 详情和定向输入区是同一能力的不同视图, 不代表增加模型工具.

## Pi 适配与小终端

- 沿用 Pi 主题和配置后的输入/选择/返回动作. 不直接照搬其他产品快捷键: Pi 已用 `Ctrl+O` 展开工具, `Ctrl+T` 展开思考, `Shift+Tab` 切换思考级别. 可运行原型应显示解析后的实际提示.
- 状态同时有文字与语义颜色, 保留宿主编辑器和状态栏. 图中深色只是主题示例, 不替换 Pi 主题系统.
- 宽裕时可像第二张图那样同时展示列表和选中详情. 较小时改成先列表, 后详情的两级页面. 保留 ID, 标题, 状态和原因, 把长路径, 模型和用量移入详情, 不靠缩小文字塞满.
- 长记录可滚动并回到最新活动. 预览截断, 旧记录加载中或数据缺失都明示, 可读取的完整成果始终有入口.
- 空列表说明当前会话没有子代理任务. 读取失败仍保留任务身份并显示可处理的错误. 终端过小时给出解释和可用返回动作. 最小尺寸与行数限制留给真实 Pi 原型验证.
- 查看界面中的返回动作只关闭本视图. 前台等待需要区分 "停止等待"和 "取消任务". 宿主中断键的具体路由必须通过原型检验, 不能由图片认定已经可用.

## 交付与下一轮验证

[生成记录](../../assets/subagents-ui/generation.json)保存内置 ImageGen 的提示词和选定输出. 原创生成图片随本文保存, 未复制上游源码或截图. 图片中的中文文字在两语言文档都有对应解释.

下一步用真实 Pi TUI 组件和宿主编辑器/状态栏做一次性原型, 检查选中稳定性, 草稿/接收者分离, 宽窄布局, 记录滚动, 纠正时任务恰好结束, 取消尚未停妥, 退出被停止/保存阻塞等路径. 在此之前, 快捷键实际路由, 组件可行性, 终端字符宽度, 浅色主题对比度和交互性能均未验证. 当前交付是供讨论的图片与场景草案.
