# 网页访问规格

[English](../../web-access.md) · 英文为准。

术语遵循[术语表](CONTEXT.md)和[独立维护决策](adr/0003-web-access-fork.md)。

## 问题陈述

维护者在 Pi 中开发时，需要查找最新文档和其他来源材料、读取有用的公开页面，并在对话中继续查阅已获取内容。上游 pi-web-access 包含许多本项目不需要的流程和后端，增加了源码及维护负担。Pi Stuff 还需要统一的独立工具开关，适用于网页访问和后续其他功能。

## 解决方案

基于 pi-web-access 0.28.0 独立维护精简重写版本，提供 web_search、fetch_content 和 get_search_content，搜索后端只保留 OpenAI/Codex 与 Exa。模型在 Pi 内自动完成搜索、选择链接和读取。保留单一公开文本提取流程、有容量限制的当前会话内容存储，以及通过 /reload 生效的全局独立工具开关。删除已约定的上游功能，遵守已确认的边界，保留来源和许可声明，使用仓库规定的 TypeScript、Bun 和 Effect v4。

## 实现决策

- **职责与模块**：网页访问能力负责搜索、公开文本读取、已保留内容及相应规则；精简的通用工具开关能力负责所有 Pi Stuff 工具的全局可用性。Pi 集成层组合这些能力与宿主模型、认证、生命周期服务，网络边界处理后端和页面 I/O。优先使用已有宿主边界，不增加通用框架或转发层。新抽象须按仓库规则与内联或更简单方案比较。
- **工具契约**：web_search 接受非空 queries 数组及可选 maxResults、includeDomains、excludeDomains。fetch_content 接受非空 urls 数组及可选 mode，取 readable 或 raw，默认 readable。get_search_content 接受 contentId，以及可选 offset／limit 或单个 find 字符串，查找和分页参数混用无效。单条查询或 URL 使用单元素数组。后端在全局配置中选择，不作为单次调用参数。
- **搜索与抓取分工**：web_search 不下载结果页面正文，不启动后台内容任务，也不发送相关完成通知。模型选择来源后另行调用 fetch_content。搜索响应包含查询、实际后端、有序来源结果、可选原生答案、内容引用和有限预览。批量输入逐项按原顺序返回成功或错误。
- **认证与模型选择**：只复用 Pi 中官方 OpenAI/Codex 模型的认证。显式搜索模型的 provider／ID 必须精确对应已存在的兼容 Pi 模型，并拥有优先级；否则复用兼容的当前模型，不按名称、价格等级或注册顺序猜测。使用其他聊天后端时，需要显式指定 OpenAI 搜索模型或使用 Exa。Exa 认证只从 EXA_API_KEY 读取，只调用搜索接口，不调用答案接口或无 Key MCP。
- **配置**：全局配置命名为 pi-stuff.json，位于宿主解析的 agent 目录。文件和字段均可省略：已知工具默认开启，默认搜索后端为 openai，另一个值为 exa。tools 映射保存各工具布尔开关，web.provider 选择默认后端，可选的 web.openaiModel 保存显式 OpenAI/Codex 模型 provider／ID。不迁移上游配置，不提供项目覆盖或临时会话开关命令。显式配置无效时明确失败，不改选其他模型。配置错误使 Pi Stuff 工具保持不可用，直至修正并重新加载；不改写配置，也不改变其他扩展。
- **工具开关**：修改通过 /reload 生效。开关控制模型对单个工具的直接调用，不禁止底层能力的一切内部使用。全局关闭不能被 Pi 工具选择重新打开，全局开启仍尊重 Pi 自身关闭。关闭一个工具不连带关闭其他工具。
- **普通搜索路由**：请求前选择已配置且兼容的后端；默认后端未配置时使用另一个可用后端，并记录选择。请求开始后，仅在传输错误、超时、HTTP 408、429 或 5xx 时，最多尝试另一个后端一次。不重复请求同一后端。认证、配置、请求错误，响应格式错误，能力不支持，取消及正常空结果均不触发回退。
- **域名筛选**：包含／排除条件任一非空时，无论默认后端为何都使用 Exa。必须配置 Exa Key，该查询不回退到 OpenAI/Codex。条件传给 Exa，并校验返回来源 URL 的主机名。域名匹配自身及子域，排除优先；必要时返回更少的有效结果，不承诺完整覆盖所有子域。域名必须是主机名，不接受 URL 或通配表达式。不把约束替换为查询提示。
- **原生答案与时间**：保留 OpenAI 原生答案及引用，不额外调用摘要；Exa 只返回搜索结果。结果数量是上限。不提供独立时间参数；查询中的日期只是意图，不保证按发布日期筛选。
- **提取与网络范围**：保留一套 HTML 主正文提取和 Markdown 转换流程。原始模式处理纯文本、Markdown、JSON、HTML 等文本响应，不转换二进制。HTTP 错误和提取失败按错误返回。仅访问 HTTP(S) 公网目标，每次重定向同样受限，最多重定向五次。拒绝 localhost／私网目标及调用方传入的凭据、cookie 和 headers。删除 GitHub 专用处理不封禁普通公开 GitHub URL。
- **内容存储**：已保留搜索内容和抓取文本只存当前会话内存。成功引用支持后续分页／查找，完整正文不得藏入工具结果 details 或会话自定义条目。正常可见工具输出仍遵循 Pi 的对话历史行为。重启、reload 或切换会话时清空。不写磁盘，不恢复，不设 TTL，不合并重复请求。达到任一缓存上限时先淘汰最早保存的内容；引用不可用时提示重新搜索或抓取。
- **分页与查找**：位置和长度按 JavaScript UTF-16 代码单元计数；在输出字节预算内返回实际继续位置和总长度。查找只接收一个非空、不区分大小写的字面词，返回匹配位置及附近上下文；不提供正则、模糊匹配和多词查找。说明是否还有更多匹配。
- **固定上限**：采用下列默认值，不为每个数字增加配置项。这些是已接受的边界，不是性能测量结果。

| 边界       | 契约                                                                                  |
| ---------- | ------------------------------------------------------------------------------------- |
| 批量／并发 | 每次最多 5 条查询或 URL，同一次调用最多并发 3 项，单条查询按顺序尝试后端。            |
| 结果       | 每条默认 5 条，最多 20 条，允许更少。                                                 |
| 输入       | 查询最多 2,000 个 UTF-16 代码单元，URL 最多 8,192 个，每个域名列表最多 20 项。        |
| 时间       | 每次后端尝试或页面抓取 30 秒；一次回退使普通查询最多尝试两次。                        |
| 响应／内容 | 每个网络响应体最多 5 MiB，每项保留文本按 UTF-8 计最多 1 MiB，超限使该项失败。         |
| 缓存       | 最多 64 项、32 MiB UTF-8 内容；这是内容预算，不是进程总堆内存上限。                   |
| 可见输出   | 每次工具结果中模型可见文本最多 32 KiB，附带截断及继续读取信息。                       |
| 分页       | 默认分页／预览 8,000 个 UTF-16 代码单元，单次请求最多 20,000 个，同时受字节预算限制。 |
| 查找       | 单词最多 200 个 UTF-16 代码单元，最多 10 处匹配，每处两侧各最多 200 个代码单元。      |

- **取消与展示**：取消会终止正在执行及排队的工作，不启动回退。使用 Pi 默认工具渲染，不增加活动面板、进度命令、浏览器服务或自定义 renderer。
- **工具链与依赖**：保留严格 TypeScript、Bun 1.4.0 和 Effect 4.0.0-rc.112。纯算法保持普通函数，Effect 负责应用边界、类型化错误及必要 I/O。已批准运行时依赖为 @mozilla/readability 0.6.0（Apache-2.0）、linkedom 0.18.13（ISC）、turndown 7.2.4（MIT）、typebox 1.3.7（MIT），开发类型依赖为 @types/turndown 5.0.6（MIT）。TypeBox 声明宿主要求的工具入参，配置和后端响应仍用 Effect 解码。Pi Coding Agent 及直接导入的 Pi AI 作为宿主 peer dependencies，以已检查的 0.85.1 为基线，实际 Bun 宿主兼容性仍须验证。默认渲染不需要直接依赖 Pi TUI。
- **后端适配**：复用 Pi 的模型和认证服务，但保留独立的官方 OpenAI Responses／Codex 搜索请求，因为已检查的普通 Pi 模型接口不暴露原生托管 web_search。直接调用 Exa 搜索。已批准依赖方案不包含 OpenAI／Exa SDK、p-limit、undici、defuddle、unpdf 或兼容性 polyfill。
- **维护与代码量**：以 pi-web-access 0.28.0、commit e55f78a6cf28e2ba5013e14c3dd7bb5eef2ac7c5 为重写来源，保留导入的源码／许可声明，在实现证据中记录来源。选择性移植上游修复，不承诺兼容其目录、配置或工具接口。对照已检查的 66 个文件、25,795 行有效代码，按相同 cloc 口径统计：排除空行、注释、测试、文档、声明、独立资源和依赖内部实现，计入嵌入 TypeScript 的界面代码。测试、文档和依赖另列。减量来自已约定的功能删除，不设硬上限或同功能压缩比例，不压缩格式，也不删除必要验证。

## 测试决策

- **主要测试入口**：通过注册的工具调用完整网页访问能力，保留真实路由、解析、筛选、存储和输出行为；只在宿主／环境及网络边界注入确定性适配器。不做模块 mock，不默认逐个测试私有辅助函数，不建立通用测试框架。这沿用访谈已确认的公开工具契约和验证范围。
- **有效测试的标准**：外部输入应产生约定输出、失败、状态变化或资源释放。检查来源与元数据、继续读取位置、工具可用性和外部请求行为，不依赖辅助函数名、内部调用结构或无关序列化细节。
- **搜索场景**：覆盖单条／批量顺序及部分失败、精确模型选择与认证复用、已配置后端选择、各类回退及不回退情况、最多一次回退、请求前／执行中／排队时取消、原生答案和引用、正常空结果、数量上限及错误响应数据。区分未配置后端与认证失败。
- **筛选场景**：验证默认 OpenAI 时仍为带筛选查询选择 Exa、缺 Key 报错、同时包含和排除、排除优先、自身／子域匹配、无效主机名、返回 URL 再校验、有效结果减少，以及禁止放宽条件的回退。后端请求 fixture 验证外部请求契约，不依赖适配器内部结构。
- **抓取场景**：代表性公开 HTML、纯文本、Markdown 和 JSON fixture 通过真实提取流程运行。覆盖空页面／不可提取页面、二进制、HTTP 错误、重定向上限、首次和重定向目标的公网检查、取消、超时及字节／文本限制。可控本地 fixture 不得削弱生产环境的公网目标规则。
- **存储／输出场景**：验证字节截断后的准确分页衔接、UTF-16 位置、有限预览、字面不区分大小写查找及上下文、混用参数报错、按条目数和字节预算淘汰、引用不可用提示，以及重启／reload／切换会话清缓存。验证完整保留内容不会通过隐藏 details 或自定义条目落入会话持久化。
- **开关／配置场景**：验证默认值、配置错误、独立开关、其他工具不变、/reload 生效，以及与 Pi 工具选择共同限制。覆盖抓取关闭后搜索和已有内容读取仍可独立使用的情况。
- **真实宿主验收**：在维护者支持的 Bun 编译 Pi 中，隔离设置、会话及其他自动加载资源，加载扩展并验证搜索到抓取、分页／查找、取消、reload 和工具开关。记录实际 Pi／Bun 版本及环境，缓存 SDK 类型声明不算验收。确定性／离线证据与明确选定账号／模型后的 OpenAI/Codex、Exa 在线检查分别记录，必要检查不可用时如实报告。
- **既有基础与运行方式**：仓库没有可复用的自有产品测试套件或 test 脚本。新增首个真实套件及 CI 入口时使用 Bun test 和既有 QA 规则，包括该规则要求的锁定版本 actionlint。已有 tuistory 0.11.0 及 #29 的 Pi 0.85.1／Bun 1.4.0 实验可作为终端驱动参考，不是网页功能的证据。仅在需要真实终端交互验证时使用 tuistory，其余宿主行为可由确定性 fixture 或 RPC 覆盖。
- **审查与证据**：运行仓库要求的静态检查和针对性行为测试。实质实现须完成严格代码质量技能要求的独立完整 diff 标准／需求审查；依赖、接口、网络／取消和状态边界须完成高风险审查。结构性问题须修复或以证据反驳并独立复查，测试通过本身不是反驳。没有覆盖率配额、占位套件、退休治理测试，也不在未观察到失败测试时声称 TDD。
