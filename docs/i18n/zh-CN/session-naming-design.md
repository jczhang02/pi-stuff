# 仅开场自动命名规格

[English](../../session-naming-design.md). 本规格汇总维护者的调研与设计访谈. 两位独立 GPT-6 Astra reviewer 已复核 `8c11554` 的四项修订, 报告无剩余规格阻塞项, 见[审查记录](https://github.com/jczhang02/pi-stuff/issues/108#issuecomment-5771952855). 这里定义后续实现, 不代表功能已存在.

## Problem Statement

未命名会话难以辨认和恢复. 反复自动改名可能把主任务换成最近的一次调试, 后台判断也可能消耗 token 却没有带来有效改名. 用户需要能辨认开场任务的名称、可预期的请求次数, 并明确控制后续替换.

## Solution

新建空白主会话在首轮成功交互后命名一次, 此后保留. 首版自动支持范围为已支持 Pi 宿主的前台 TUI 会话; 来源不明或非 TUI 模式跳过生成. 后续通过 `/autoname [目标说明]` 显式生成, Pi 的 `/name <名称>` 仍直接赋值. 命名模型和风格提示词可配置, 默认采用简短英文. 保护用户修改并丢弃过期结果. 自动命名默认开启, 可以单独关闭而保留命令.

## User Stories

1. 作为 Pi Stuff 用户, 我希望新主会话在开场交互后获得名称, 以便在会话列表中辨认它.
2. 作为短会话用户, 我希望命名不必等满三条消息, 以便只有一轮的会话也有标识.
3. 作为用户, 我希望名称描述请求的目标和对象, 以便进入实现和测试后仍然有用.
4. 作为用户, 我希望后续不自动改名, 以免临时障碍或最后的提交命令取代任务身份.
5. 作为关心费用的用户, 我希望最多自动尝试一次, 以免长会话不断累积命名请求.
6. 作为取消首轮交互的用户, 我希望跳过自动命名, 以免取消后又启动后台请求.
7. 作为首轮失败的用户, 我希望后续轮次不补命名, 以便开场限定的规则始终可预期.
8. 作为用户, 我希望命名失败或输出无效时保留现有显示且不重试, 以便主任务继续正常使用.
9. 作为已经命名的用户, 我希望保留该名称, 以免自动命名覆盖我的安排.
10. 作为恢复或重载会话的用户, 我希望不补生成, 以免打开旧会话就消耗 token.
11. 作为创建 fork 的用户, 我希望无论是否继承名称都不自动请求命名, 以免分叉带来隐形工作.
12. 作为运行后台子 agent 的用户, 我希望它们不参与自动命名, 以免每个子会话都多发请求.
13. 作为用户, 我希望关闭自动命名时仍能使用生成命令, 以便自行决定何时调用.
14. 作为用户, 我希望 `/name` 保留原生直接赋值行为, 以便不用模型就能指定准确名称.
15. 作为用户, 我希望 `/autoname` 只生成一次替代名称, 以便纠正含糊的开场名称.
16. 作为目标已经变化的用户, 我希望显式生成针对当前已明确的主任务, 以便名称反映现在的意图.
17. 作为用户, 我希望可以附带目标说明, 以便不发送完整历史也能指导命名.
18. 作为用户, 我希望手动生成保持显式操作, 以免重新开启自动管理后又改动名称.
19. 作为用户, 我希望单独配置的命名模型优先, 以便控制费用和速度.
20. 作为未配置命名模型的用户, 我希望使用当前会话模型, 以便无需额外设置就能使用.
21. 作为用户, 我希望复用宿主模型认证, 以免维护第二套凭据.
22. 作为用户, 我希望默认采用简短英文 `type: Action object`, 以便名称统一、便于浏览.
23. 作为用户, 我希望保留技术标识符并省略进度, 以便名称可辨认且稳定.
24. 作为用户, 我希望通过配置替换风格提示词和长度限制, 以便命名习惯变化时无需修改扩展代码.
25. 作为用户, 我希望配置变更只影响未来请求, 以免已有会话因此改名.
26. 作为用户, 我希望输入文本有上限且不含工具结果和 thinking, 以免命名重复发送不必要的上下文.
27. 作为用户, 我希望请求有截止时间且不额外调用摘要模型, 以便命名保持轻量.
28. 作为在请求期间改名、导航或再次生成的用户, 我希望过期结果被丢弃, 以便最终名称服从最近的操作.
29. 作为调用命令的用户, 我希望失败时保留名称并给出有用提示, 以便修正配置或主动重试.
30. 作为维护者, 我希望通过真实隔离 Pi 宿主验证生命周期和请求次数, 以便测试覆盖实际集成.

## Implementation Decisions

1. **职责和宿主集成.** 一个命名能力负责资格判断、输入准备、命令处理和结果写入. 由现有包入口注册, 现有配置 owner 解码设置. 复用 Pi 名称 API、模型注册表和认证. 保留严格 TypeScript、固定 Bun 版本和 Effect v4 边界解码、类型化错误及必要 I/O. 本规格不要求新增依赖或 provider client.
2. **自动资格.** 首版仅支持已支持宿主的前台 regular/fullscreen TUI 会话. 要求 TUI 模式、可持久化且无 parent link 的原生会话、没有对话条目或名称, 并有当前运行期间新建的证据: 原生 new-session 切换, 或 startup 指向尚未在磁盘存在的新会话文件. startup 时已有文件即视为历史会话, 即使对话为空. 恢复、导入、重载和 fork 不符合资格, 后续清除名称不恢复机会. RPC、JSON、print、非持久化会话及来源不明的会话均跳过自动命名, 包括这些模式下真正的主会话. 这是保守的支持范围, 不声称所有非 TUI 或带 parent link 的会话都是子 agent. 已核对的后台子 agent 启动方式被模式条件排除. 第三方若把子 agent 启动为与普通前台 TUI 无法区分的进程, 不在支持的集成内; 必须关闭自动命名或提供可验证子会话来源后才能宣称支持. 宿主支持扩展命令的地方仍可显式生成.
3. **开场交互.** 使用第一条已交付用户请求及其最终可见助手答复, 包括完成该请求所需的工具与内部续跑. `settled` 事件不等于成功, 还需检查最终助手完成状态并排除取消/报错. 排队的独立用户请求不得重置机会或混入开场快照. 无法安全识别开场时跳过自动命名, 不从最近答复猜测. 首轮失败或取消消耗机会, 包括可观察到的 preflight 失败, 不顺延到后续成功交互.
4. **一次性状态.** 等待模型 I/O 前先消耗自动机会. 重复事件、失败、无效输出、配置变化和导航均不恢复它. 重启、恢复和重载不重放. 优先使用宿主会话身份/历史和本地请求状态; 仅在真实宿主行为证明必要时增加持久化元数据. 元数据必须符合 Pi 名称的会话级语义. 不重写会话历史, 不增加独立会话数据库.
5. **命令.** 保留 `/name <名称>`. 注册 `/autoname [目标说明]`, 每次显式请求生成一次替代名称, 自动关闭时仍可使用. 接受命令后, 在校验或模型 I/O 前立即消耗剩余自动机会, 包括首轮仍在运行时; 命令失败也不恢复. 用户提供的说明优先于推断的目标; 无说明时从有界开头和近期对话推断当前主任务. 说明是命名输入, 不能要求执行工具或改变生命周期. 成功则替换名称, 失败则保留, 不恢复自动命名.
6. **配置.** 提供自动开关, 默认 true; 可选命名模型; 可选替换风格提示词; `maxLength`, 默认 80. 复用现有配置重载约定, 不新增设置 UI 或 watcher. 模型配置必须明确 provider 和 model. 未配置时使用当前模型; 已配置但无效、缺少认证或请求失败时, 不静默改用其他 provider/model. 请求开始时固定配置和模型选择. 无效配置按现有配置机制拒绝, 并给出可操作诊断.
7. **默认风格.** 英文 `type: Action object`, type 为 `research / feat / fix / refactor / docs / chore`, 描述宜为 4-8 词. 保留技术标识符大小写, 不加括号 scope、日期、进度或完成状态. type 描述整个请求任务, 不跟随其中的调研、测试或提交阶段. 助手误解时以用户请求为准, 助手文本只补充有依据的任务意图; 替换风格指导时保留该规则. 默认风格是提示词指导, 不保证语义总是正确.
8. **自定义风格与校验.** 替换提示词可改变语言、type 词表和格式, 不能改变触发资格、输入选择、重试、模型路由或写入保护. `maxLength` 独立存在, 必须是正数字符上限. 去除首尾空白后, 只接受非空、单行、无控制字符且不超长的输出. 不把超长结果截成可能误导的半截名称, 不调用修复模型, 不用默认英文/type 规则限制自定义提示词. 无效输出视为失败. 所有文本上限统一按 Unicode code point 计数, 文档说明这里的字符含义.
9. **输入上限.** 自动输入中首条请求和最终答复合计最多 2,000 字符. 显式生成中目标说明和所选对话合计最多 4,000 字符, 说明优先. 无说明时保留部分开场用户意图及有界近期用户/助手文本. 选择和截断必须确定性, 不调用第二个模型做摘要. 避免只取前缀而漏掉长日志后的实际请求, 保留有用边界并标识省略部分. 排除工具结果消息、thinking、过程日志、图像和加载的 system/skill 指令. 助手文本仍可能引用这些内容, 按消息角色过滤不等于保密保证. 自定义风格指令和请求封装在上述对话上限之外另耗 token.
10. **资源和路由.** 每次命名采用 15 秒端到端截止时间, 到期取消本次本地命名工作, 不取消主对话. 每次自动机会或显式命令最多发起一个扩展级生成请求. 支持时关闭 SDK/client 重试, 不做模型回退链、自主重试、周期定时器、额外分类或摘要. 支持时不请求额外 reasoning, 并按 `maxLength` 设置有限输出预算. 记录 provider 映射, 在兼容性证据中纳入隐藏 reasoning 和传输重试. 这些控制约束工作量, 不构成通用精确 token 或账单上限. 取消无法收回远端已耗 token.
11. **并发写入.** 应用结果前重新检查会话身份、分支/导航代次和名称修订. 手动改名、新的显式生成、切换会话、树导航、重载或退出都会使此前工作失效, 即使名称字符串后来又改回原值. 尽力取消请求, 最终有效性检查不可省略. 普通新用户消息本身不授权新一轮命名. 不排队执行多次显式生成; 新请求取代旧结果, 不自动重试旧请求. 名称仍属于整个会话, 不增加分支标题.
12. **失败和交付.** 自动命名不打扰主交互, 不让主对话等待标题请求. 显式命令通过宿主现有反馈报告模型/认证缺失、超时、无效输出或被新请求取代. 诊断不输出提示词、历史或凭据. 失败时保留已有名称和正常默认显示, 不影响原生响应、打断和会话恢复. 继承 Pi 原生延迟持久化: 全新会话在尚无助手消息时命名, 可能只更新内存. 适用时命令反馈必须说明会话未保存; Pi 落盘前退出可能丢失名称, 后续正常落盘的交互会保留它. 不强制写历史来改变该行为.

## Testing Decisions

- **维护者已确认的主测试边界:** 复用现有真实 Pi launcher 和本地可控模型 endpoint, 保留真实扩展注册、配置、事件、命令和持久化. 仅扩展外部模型 fixture 来记录命名输入、请求次数和完成顺序. 不 mock 模块, 不另造一套假生命周期自证正确.
- **现有先例:** Pi terminal 生命周期/配置测试已有隔离 regular/fullscreen 会话、`/new` 和 `/reload`、真实 provider 流量及会话文件检查. 配置 owner 测试已有真实临时文件和过期写入. 复用这些方式; 可见终端验收使用 Terminal Control 和维护者的 Bun 编译 Pi profile.
- **一次性行为:** 支持的前台 TUI 首轮成功产生一次请求和名称, 后续轮次及重复 settled 不再请求. 首轮 error/abort/preflight 失败、已有名称、关闭自动、恢复/重载/导入、两类 fork 和后台子会话均不请求. 覆盖 startup 打开已有空会话文件、parent link 或来源不明、非持久化会话和官方 JSON 后台子进程启动方式; RPC/JSON/print 均无自动请求. 通过真实宿主覆盖排队用户输入、内部重试/压缩和新建会话切换.
- **显式行为:** `/name` 不请求模型; 自动关闭时 `/autoname` 仍可替换手动名称; 目标说明优先; 命令不启用后续自动更新. 在首轮之前及运行期间调用, 覆盖成功、无效配置和生成失败; 无论返回顺序如何, 之后均不得启动自动请求. 命名模型/认证缺失时不请求备用模型. 同时统计逻辑调用和支持零重试 adapter 的真实 fixture HTTP 请求.
- **竞态和恢复:** 暂停模型响应, 在此期间手动改名, 包括改走再改回、导航、重载、切换会话或发出新命令. 仅仍有授权的结果可写入. Pi 已保存会话后, 检查进程重启及分支导航保留名称. 另在首轮前生成, 分别立即退出或完成一轮交互, 检查反馈和恢复符合原生延迟持久化. 失败/取消不能恢复自动机会.
- **边界:** 仅在必要处直接测试配置解码和确定性输入/输出边界, 覆盖 Unicode 长度、长日志后的请求、超长说明、自定义提示词/type/语言、换行/控制字符、2,000/4,000 字符输入预算和名称长度. 检查可观察输入及结果, 不绑定私有 helper 结构或完整提示词字面值.
- **失败上限:** 可控 endpoint 测试截止时间、无效输出、无响应和 provider 错误, 确保保留名称并释放本地工作. 记录所支持 provider adapter 的重试/reasoning 行为, 不从可见标题很短推断其成本低.
- **语义检查:** 用一小组记录下来的开场/目标说明样例检查主任务相关性和标识符保留. 包含用户要求调研 OAuth 兼容性且先不实现、助手却声称已添加 adapter 的冲突样例, 预期名称须保留调研意图. 与确定性生命周期测试分开; fixture 返回好标题不能证明真实模型会如此. 本次规格发布不要求在线质量 benchmark 或账户消费.
- 实现阶段运行仓库必需静态检查和适用离线产品测试, 记录真实 Pi/Bun/provider 版本、编译宿主验收及并发/持久化审查. 本次规格交付仅运行文档适用检查, 不宣称生产行为通过验收.

## Out of Scope

周期或目标跟随自动改名; 等待三条消息; 自适应澄清分类; 重试/模型回退链; 批量重命名历史会话; fork/子 agent 自动命名; 非 TUI、非持久化会话或未验证第三方 launcher 的自动命名; 进度标题; 新模型/认证 client; 设置 UI、模板语言或 watcher; 改变 Pi 会话/分支身份; fork 宿主源码; 未获授权的依赖; 在规格阶段实现或合并功能.

- 已接受的取舍: 含糊或失败的开场可能永久保留差名称或无名称, 直到用户手动生成; 无名 fork 不自动补名; 有界文本可能遗漏上下文. 不隐含周期修复.
- 成本限制: 自定义提示词大小、模型分词、provider 强制 reasoning 及无法关闭传输重试的 adapter, 都使通用 token 硬上限无法成立. 默认当前模型方便使用, 但不保证金额低. 用户文档必须保留这项限制.
- reviewer 可以挑战这些选择, 但需区分已接受的产品取舍与矛盾或无法实现的约定. 修正规格缺陷时, 不静默推翻维护者选择的仅开场策略.
