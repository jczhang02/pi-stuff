# Session 命名设计

[English](../../session-naming-design.md). 本文记录 [#104](https://github.com/jczhang02/pi-stuff/issues/104) 在[调研](session-naming-research.md)后的设计访谈结果. 已确认选择如下, 末尾默认参数及整体理解仍待确认. 本稿不构成实现授权.

## 目的与任务身份

用有界的命名工作生成可辨认的开场任务标签. 自动标题不追踪后续阶段或目标变化. 这明确接受开场名称可能不够准确, 用户可主动请求替代名称. 显式生成描述当前明确的主任务, 不取最近的临时操作, 也不罗列全部历史主题.

## 自动命名生命周期

| 场景                                      | 已约定行为                               |
| ----------------------------------------- | ---------------------------------------- |
| 新建空白主会话                            | 首轮成功交互完全结束后, 最多尝试生成一次 |
| 生成前已有名称                            | 保留名称, 跳过生成                       |
| 首轮取消或报错                            | 跳过生成, 不等后续成功交互               |
| 命名失败、超时或输出不合格                | 保留默认显示或已有名称, 不自动重试       |
| 后续输入、换题、压缩或 reload             | 不再次自动生成                           |
| 恢复、分叉 (有名称或无名称)、后台子 agent | 不自动生成                               |
| 用户显式请求生成                          | 只替换一次, 不恢复自动管理               |

开场输入为首条用户请求和有限的最终助手答复文本. 排除工具结果、过程日志和思考内容. 助手误解任务时以用户请求为准. 不额外调用模型判断澄清是否完成.

实现必须在 reload、恢复和导航后保持最多一次的边界. 未完成请求的结果不得覆盖之后的手动名称, 也不得改到另一个会话或分支. 这些是验收条件, 尚未选择持久化结构或并发抽象.

## 手动操作

保留 Pi 的 `/name <name>` 直接设名, 增加 `/autoname [目标说明]` 生成替代名称. 有目标说明时优先使用; 无说明时使用有界的开头及近期用户/助手对话, 不发送整场历史. 命令只替换一次名称, 不启动周期行为.

手动名称持续具有优先权, 直到用户修改或显式请求生成替代名称. 编辑命名配置不会追溯修改已有会话名称.

## 模型与命名规则

有命名模型配置时使用该模型, 否则使用当前会话模型, 复用 Pi 模型注册表和认证. 不新增模型服务客户端. 命名失败不触发自动重试或连续切换备用模型.

默认风格:

- 英文 `type: Action object`, 类型为 `research / feat / fix / refactor / docs / chore`.
- 描述优先 4-8 个词, 完整名称最多 80 个字符.
- 保留技术标识符大小写. 不含括号范围、日期、进度或完成状态.
- 类型描述整项任务, 不随调研、测试或提交阶段切换.

用户可在配置中替换命名风格提示词. `maxLength` 独立配置, 默认 80. 基本输出校验保留: 非空、单行、符合配置长度且无控制字符. 自定义风格后不强制默认类型列表或英文. 自定义提示词不改变输入选择、请求资格或重试行为.

## 宿主事实对实现的约束

Pi 0.85.1 的 `agent_settled` 没有成功状态字段. 需要核对先前已持久化的助手状态, 不能只看 settled; preflight 错误可能没有 settled 事件. `session_start` 可能表示 startup、reload、new、resume 或 fork, startup 也可能打开旧会话. 分叉只复制到选定 leaf 的路径, 因而只继承该路径上的名称. 名称本身跨会话所有条目读取, 只在当前分支记录归属不足以处理这一语义. 来源: [事件](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/src/core/extensions/types.ts), [生命周期](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/src/core/agent-session.ts), [会话管理](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/src/core/session-manager.ts).

## 最后待确认的默认值

以下是建议, 尚未确认:

- 默认开启开场自动命名, 配置开关只关闭自动行为, 保留 `/autoname`.
- 自动命名最多使用 2,000 字符对话文本, 手动生成最多 4,000 字符. 自定义风格指令和请求包装会额外占用输入. 用确定性选择控制长度, 不另发摘要请求.
- 请求期限 15 秒, 使用较小输出预算. 在宿主支持时关闭客户端重试, 在模型支持时不启用额外推理. 输出计费取决于服务商, 不能把 80 字符标题当成 80 token 账单.

这些数值是保守的设计起点, 未被实验确定为最优值. 配置字段名和持久化表示属于后续实现工作, 必须满足已约定行为和仓库审查要求.
