# Subagent 重新开发正式规格

[English](../../subagents-redevelopment-spec.md). 以英文版为准.

状态: 2026-09-21 正式实现合同, 发布于 [#97](https://github.com/jczhang02/pi-stuff/issues/97), 属于 [#64](https://github.com/jczhang02/pi-stuff/issues/64). RQ01-RQ10 和 UIR01-UIR09 全部接受. 本规格整合运行、UI 决策及 UI 审查, 取代先前 F01-F33、Q/R 和 UI01-UI15 实现合同. 这不表示重新开发已经完成, 也不授权合并或发布软件.

## 问题

先前独立实现超出了选定上游包的范围, 并且无法在安装依赖的真实项目中启动普通只读任务. 它在调用模型前扫描 ignored 文件, 耗尽自己设定的 Git 输出额度. 维护者希望采用 arhen 较小的执行模型, 按仓库规范改写, 并能留在 Pi 主对话中清楚查看工作、问题、结果和失败.

主要 UI 流程已经确定, 但逐张概念图形成的记录仍缺少完整的键盘归属、旧报告入口和长内容行为. 应先补齐这些契约, 避免实现再次自行发明产品要求.

## 方案

基于已检查的 `@arhen/pi-core-subagent` 1.3.55, commit `676b11eb415cd46fbede712b5bbb075ff3f043bf` 重新开发. 保留选定行为并修复可证实的问题. 将父代理操作整合为单一 `subagent` 工具, 加入已接受的完成后续聊、逐次任务记录和子代理扩展工具.

沿用 statusline 下方占满宽度的 FleetView. 子代理详情、依赖图及辅助阅读页接管底部交互区域, 上方保留主对话. 公共接口适用时复用 Pi 编辑器、消息/工具渲染、主题、按键匹配和通知; 只补充缺少的组合布局、FleetView、依赖图和有界阅读行为. Claude Code 用来参考随焦点变化的帮助和有用的信息顺序, 不据此要求宿主会话切换.

## 实现决策

### 1. 运行边界与职责

- 本规格未明确修改的行为以上游 arhen 为准. 内部按严格 TypeScript、固定 Bun 和 Effect v4 改写; Effect 用于边界解码、类型化错误及必要 I/O, 纯计算仍用普通函数. 保留上游许可及来源.
- 执行、通信、工作区和逐次记录由 subagent 能力拥有. 精简 Pi 适配层注册单一工具, 将状态投影为 UI. 阅读和导航不修改任务状态或调用模型.
- 子代理仍是同一进程中的独立 Pi AgentSession. Run 是一次提交的任务组, child 保留会话上下文, request 是该 child 的一次执行. Follow-up/resume 新增 request 记录. 显示名称不是稳定地址. 内部 run/task/request ID 可用于工具和记录, 不作为日常 UI 标签.
- 保留原生子会话记录及上游 run 恢复. 重载的未结束 run 标记为中断, 不静默重启. 当时的待答问题不成为持久化批准. 新元数据与旧实现格式分开, 不要求迁移或删除.

### 2. 单一父代理工具及上游覆盖

单一 `subagent` 操作字段覆盖 dispatch、status、result、wait、reply、steer、resume、follow-up、cancel. Dispatch 保留单任务、并行、串行链及显式 `needs`. Status 不阻塞; result 可读单个任务或整组; wait 支持超时及上游问题唤醒行为. Steer 面向指定 live child 或组内所有正在运行的 child; cancel 可面向一个任务或整组. 不再独立注册其他父代理工具. 准确参数名可以重设计, 不引入旧协议多余操作.

保留逐任务角色/system prompt、任务文字、write/tools、model、thinking、cwd 和运行时限; 保留整组 concurrency、auto-await 和逐任务通知选项. 沿用上游默认: 单次最多 16 个任务, 默认并发 3、上限 8, 后台派发, 默认通知每个任务完成, 显式时限或 auto-limit 设置对应的 1 小时/6 小时上限. 保留简单的上游 auto-limit 设置及命令, 不另建设置应用.

Agent 文件查找和匹配沿用固定上游的优先顺序, 包括项目/home 搜索和 description 匹配. 依据 Pi 实际 registry 验证模型及 thinking, 展示生效值和覆盖/回退说明. 内置工具读写选择沿用上游; RQ09 另外将继承的扩展工具限制在父代理当前启用扩展工具内, 再按角色收窄. 不静默弱化明确请求的必需工具.

### 3. 依赖与工作区

- 任何 child 启动前验证重复/未知 ID、自依赖及环. 串行链是依赖边并保留上一步输出替换. 依赖既携带顺序, 也携带带名称的前置报告.
- 保留 ready-wave 调度及并发上限. 当前波次尚未结束时, 不因某个前置已完成就启动后续波次. 失败或停止的前置使后续任务 skipped, 独立同级继续. Follow-up/resume 不自动重跑其他节点.
- 只读任务直接使用选定当前目录, 不创建 Git 快照或遍历全部 ignored 文件. 写任务必须有可用的任务 worktree; 初始化或必需分支恢复失败则停止启动, 无法提供该 worktree 同样失败. 不自动退回原目录写入.
- 保留上游基线规则: 独立写任务从 HEAD 开始; 串接写任务从选定的已完成依赖分支开始. 多个写依赖时, 上游选择最后一个符合条件的依赖分支, 不合并全部分支. 收到全部依赖文字不证明已经拥有全部代码, 须报告真实祖先关系.
- 不自动将父目录未提交修改带入写 worktree. `node_modules` 仍共享, 不构成沙箱. 保留禁止子代理在 worktree 安装/删除依赖的上游指令. 工具选择不等于进程隔离.
- 保留真实 commit、diff、变更文件证据、部分成果保存及保护分支/live work 的清理行为. 保存失败时保留可恢复目录并报告错误. 不仅凭分支字段声称代码已保存. 父代理审查和集成是后续独立动作.
- 完成报告与提交失败可以同时存在. 这一情况保留上游调度语义, 不新增调度终态, 不暗示代码成功交接. UI 和返回结果须明确这个限制.

### 4. 通信、继续工作与修错

保留子代理 `ask_parent`、`notify_parent`、同级发送及 mailbox polling, 包括上游有界问题等待. 不向子代理注入父代理委派工具, 本次不启用递归委派.

Steering 须指向 live child 并确认实际入队. 对应输入进入该会话前, 保留指令原文及待处理状态. Reply 必须回答打开 composer 时的那条问题; 父代理并发回答、超时或取消不能使其改投其他问题. 这些检查修正投递正确性, 不增加确认回执协议.

停止沿用既有取消生命周期. 执行或本次收尾仍在进行时显示 Stopping. 保留输出并展示真实文件保存结果. Resume 和完成后 follow-up 要求整组结束、该 child 没有活动执行、原会话及所需自身代码可用. 写代理沿用剩余 worktree 或重新挂接自己的分支; 只读代理读取选定目录当前内容. 接受继续交办后新增记录, 保留旧报告、状态、时间及用量, 同时提供累计用量.

复现并修复已查到的问题: 原目录回退、错误的 steering 成功、过早显示停止、将空文字误判为没有会话、部分提交错误未报告. 同时处理 assistant stop reason 和抛出的 provider 错误. 单个工具错误不直接使整个任务失败. 创建 run 前拒绝派发不能虚构 child 或 transcript.

子代理从父代理已加载的选定扩展来源, 在自身会话中加载和绑定工具. 必需加载/绑定失败则启动失败. 工具需要不支持的交互 UI 时明确报错; 不自动转接 UI, 不将 Pi 无界面空响应当成功. 保留选定扩展工具上限及上游通信工具.

### 5. 优先复用 Pi 的组合方式

| 界面部分             | 复用                                                    | 本功能负责                                    |
| -------------------- | ------------------------------------------------------- | --------------------------------------------- |
| 主输入               | `CustomEditor`, 宿主历史/补全及编辑                     | 编辑器边缘入口和焦点路由                      |
| 局部输入             | Pi `Editor` 及编辑/提交/换行绑定                        | 收件人、草稿目标和实际发送结果                |
| 回复/报告/transcript | 公共输入适用的原生消息/Markdown 和工具执行组件          | 选择 request、有界 viewport、事件到组件的投影 |
| 列表和帮助           | Pi 选择绑定、按键匹配、生成的提示; 适用时用原生列表组件 | 仅圆圈选中的 FleetView 行及图节点选择         |
| 主题和宽度           | 当前语义主题、原生换行/截断/可见字符宽度                | 统一列预算及窄屏优先级                        |
| 通知                 | `ctx.ui.notify` 及主对话正常工具结果                    | 准确描述操作和结果                            |
| 底部位置             | 公共 editor/footer 组合接口                             | 接管底部区域并恢复原状态                      |

Pi 的 `belowEditor` widget 位于 footer 之前, 不能单独实现 statusline 下方的 FleetView. 该位置使用公共 footer 接口. `FooterComponent` 虽已导出, 却要求完整的父 AgentSession, 标准扩展 footer factory 并不提供. 不将残缺 context 强转成 session, 不访问宿主私有字段. 用文档提供的 footer context/provider 数据实现最小 statusline 适配, 集中格式处理并保留其他扩展 status. 输入不可用时不承诺直接复用原生 footer.

以小型 `CustomEditor` 扩展和公共 footer 组合接管底部区域. 不重建 Pi 编辑器、会话切换器或终端框架. 通用 `ui.custom` 自身不保证移除主 footer 和 widgets. 原生组件是构件, 不是现成的子代理查看器. 宿主 slot 支持其布局契约时优先使用原生 `ScrollView`, 本功能只负责分页/锚点策略, 不再造通用滚动引擎. 使用公共 `keyText`/`keyHint`/`rawKeyHint`, 内部 helper 导出不作为扩展契约. 须在固定真实宿主中验证组合, 不通过访问宿主容器私有状态满足设计. 这里的主 statusline 指 cwd/model/usage footer, 不是 Pi 整个 status container. 查看期间通过 `setWorkingVisible(false)` 隐藏内置工作指示, 退出恢复. 其他宿主 pending/status 行及无关扩展 widget 不属于本功能可移除的范围; 应计算其占用空间, 不修改宿主容器. Reload/会话结束时释放本功能订阅与组件, 根据当前 context 重新同步. 原生工具 renderer 接收真实结果及子代理 cwd; renderer 数据不可用时使用 Pi 支持的 fallback, 不伪造工具输出.

后台通知属于代理编排消息. 向父模型交付必要报告和问题, 主对话默认只显示紧凑事件摘要, 通过 Pi 原生工具展开绑定查看详情. 结构化工具结果遵循同样的折叠/展开方式. 面向用户的结论由父代理给出, 避免逐条复述通知或重复 UI 中的问题. 继续交办的完成通知只包含本次新执行的报告, 不再重发未变化的同级报告. 保留错误、后台唤醒及非 TUI 问题处理.

### 6. 主界面、FleetView 与依赖图

主对话、编辑器、statusline 顺序不变. FleetView 位于 statusline 下方, 占满可用宽度. Icon 与其左边缘对齐, 无额外留白. main 无 description. 选中仅改变圆圈, 无整行背景或第二个指针. 实心表示 FleetView 当前键盘选择; 失焦时空心, 但保留内部选择. 它不表示切换了宿主会话.

执行原生工具时, 描述显示真实操作和目标; 其他时候显示任务文字, 不编造进度. FleetView 显示待处理 steering 数量, 详情保留原文. 耗时按秒、分秒、时分显示.

按整组可见行和终端字符宽度计算名称、描述、尾部列. 指标行统一耗时与 token 位置, 形式为 `34s · ↓ 8.2k tokens`. Waiting/状态与同一尾部区域的右边缘对齐. 正常工作不显示 Running. 长描述优先让出空间, 不挤掉关键状态, 不逐行各算对齐位置.

FleetView 获得焦点后在行上方、statusline 下方显示帮助; 编辑器获得焦点时隐藏这行操作帮助. Confirm main 返回编辑器, confirm child 打开详情. 列表滚动保持所选项可见, 有省略行时显示紧凑范围提示. 状态变化不重排行或抢占选择. 列表覆盖当前父会话所保留 run 的 child, 包括恢复的 run. 完成、失败或停止行不自动消失; `/subagents` 重新打开同一集合, 保持续聊可达. 重启后沿用上游 run 保留范围, 不新增跨项目归档. 没有 child 时隐藏 FleetView, 保留主 footer.

只有显式依赖提供关系图入口, 独立工作仍是列表. 箭头从前置指向消费者, 串行链同样如此. 同名角色附简短任务描述, 无需任务 ID 即可区分. 节点打开相同详情, 返回恢复图中选择. 大图使用有界 viewport, 保持选中节点可见, 标明延伸到区域外的连线; 不删边或改画成树. 等待原因来自真实调度器, 不仅根据画出的边推测.

### 7. 详情、Transcript、Info 与历史

详情接管底部交互区域, 主编辑器、主 statusline 和 FleetView 不显示, 上方主对话保留, 使用语义主题的整宽横线划分边界. 返回恢复入口列表/图的选择和主草稿. 关闭查看不停止显式后台工作.

使用紧凑的身份/任务标题, 附本次耗时及输出 token. 主体优先级: 可行动的执行/保存失败或 live 待答问题, 然后是运行中最新可见回复、完成后的最终报告. 不额外生成模型摘要. Prompt 折叠在主体上方, 展开后去掉重复的任务标题. Activity 是下方简短原生工具轨迹, 完成或输入时折叠. 显式打开 Activity 时将其放在长报告前, 使操作立即可见. 回复时问题只在 composer 中出现一次, 仍保持准确的问题目标和草稿. 不恢复被否定的分类目录详情.

- **Transcript:** 只读、按时间排列的已保留子代理消息与工具调用/结果. 用任务文字和时间划分 request, 不显示任务编号. 仅阅读位置已在实时末尾时跟随最新内容. 翻离末尾后保持位置并提示有新输出. 完整记录保持可读, 区分显示折叠、上游原生截断及记录缺失. 不承诺提供未记录内容或 provider 隐藏的推理.
- **Info:** 一页紧凑文档, 按生效配置、工作区/Git 结果和用量分组. 包含角色来源及覆盖说明、model/provider/thinking、实际工具/cwd、session 位置、分支/祖先、文件/diffstat、完整错误、本次和累计用量. 不适用项省略, 不可用值明确说明. 被缩短的路径可通过换行/分页完整读取. Info 只读, 不是设置面板或合并 UI.
- **History:** 从 Info 的单一入口打开原生风格 request 列表, 包含时间、任务摘要和结果. 选择后只读查看对应报告及证据. 旧 request 不显示会作用于当前 request 的 message/resume 操作. Esc 依次恢复列表选择、Info、当前详情. 无任务编号、tabs 或固定侧栏.

### 8. 键盘与焦点契约

| 焦点      | 行为                                                                                                                                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主编辑器  | Pi 光标、历史及补全优先. 只有编辑器上下绑定没有改变文字、光标、历史选择, 且无补全菜单或其他已处理操作时, 才进入 FleetView. 保留草稿并隐藏光标. 边缘入口不方便时, `/subagents` 提供命令入口.                                   |
| FleetView | Pi 配置中的前/后项和确认键; 固定 Esc 返回编辑器. Confirm main 返回编辑器, confirm child 打开详情. 仅有真实依赖时 `g` 打开关系图.                                                                                              |
| 详情      | `p` 展开/折叠 Prompt; `a` 展开/折叠 Activity; `t` 打开可用 Transcript; `i` 打开 Info; `g` 打开已有依赖图. `m` 执行当前符合条件的 Message/Resume/Follow-up; `x` 发起符合条件的停止确认. 仅 live 待答问题时 confirm 打开 Reply. |
| 阅读      | `[`/`]` 前后翻页, 显示位置. 原生选择绑定操作可选择行, 不抢文字输入. Esc 返回一层. Transcript 显示 `f` follow 以回到实时末尾.                                                                                                  |
| Info/历史 | Info 中 `h` 打开历史; 历史使用 Pi 选择/确认键. Esc 返回记录的来源.                                                                                                                                                            |
| 依赖图    | Pi 选择绑定按稳定依赖顺序遍历节点, confirm 打开详情. Viewport 跟随选择, Esc 返回来源.                                                                                                                                         |
| Composer  | 原生提交、换行和编辑拥有输入, 字母是文字. Esc 不发送, 保留绑定准确目标的草稿并返回详情. 空间允许时保留原报告、问题或回复.                                                                                                     |
| 停止确认  | 配置中的 confirm 停止明确目标, Esc 取消确认. 保留当前输出及真实依赖后果.                                                                                                                                                      |

提示与执行使用同一绑定匹配器, 保留固定 Esc 返回. 功能字母只在非输入界面生效; 不要求 Alt+A、功能键、Home/End 或 PageUp/PageDown. 未拥有焦点时保留 Pi 全局行为, 不另注册竞争性的全局导航系统. 帮助将主要介入、阅读和返回分组, 必要时换行次要提示, 不为减少动作数量另加菜单.

### 9. 可观测状态与有界布局

| 观察条件                             | 紧凑展示/详情规则                                             |
| ------------------------------------ | ------------------------------------------------------------- |
| 排队, 依赖未完成                     | 尾部 Waiting; 详情/图指出真实前置                             |
| 排队, 波次或并发限制                 | 尾部 Queued; 详情说明已知调度原因                             |
| 启动/正常工作                        | 尚未执行时显示 Starting; 工作时显示时间/输出用量, 无 Running  |
| Live 父代理问题                      | Waiting for main, 问题优先                                    |
| 已接受的 steering 尚待处理           | FleetView 显示待处理数量, 详情保留原文, 不替换执行状态        |
| 已请求取消, 执行或该请求的收尾未结束 | 真正结束前为 Stopping, 不提供冲突的修改操作                   |
| 完成                                 | Done 及原报告, 报告内容不是 UI 发出的验证结论                 |
| 失败/停止/跳过                       | 各自标签及真实原因, 必要时标明保留输出未完成                  |
| 代码保存失败                         | 执行结果旁持续显示 Commit failed, 包括 Done; 窄尾部先让出指标 |

正常完成后也可能还在收尾 Git 结果. 没有取消请求时不显示 Stopping, 未确认前不声称代码已保存; 可在报告旁显示准确的 Finalizing 提示, 不新增调度终态.

FleetView、图和详情紧凑指标均表示当前/选中的 request: 耗时与输出 token, request 结束后时间冻结. Info 提供已记录的 input/output/cache/cost/turns 和 child 累计用量. 缺值是不可用, 不能编造零. 普通 UI 不要求内部 ID 或原始调试轨迹.

普通尺寸下, 打开的底部区域最多约占四分之三屏; 原生输入需要时可以增高, 但至少留下六行给主对话和分隔. 保持身份及局部帮助可见, 正文分页. 内容增长不能使面板无限增高. 所有分页正文, 包括运行中的详情, 离开实时末尾后都保留所读内容及锚点; 用户显式跟随后才用新回复替换内容. 显示新输出提示及局部 `f` follow 操作. 新事件不挪动 composer 或抢焦点. 当前宿主会话内的 Esc、发送失败及 resize 保留草稿; 不承诺重启后草稿持久化.

验证 150x50、120x36、80x24 可用布局. 尺寸不足时显示带 Esc 的提示, 不裁掉操作. 先压缩可选上下文, 再考虑原生输入、状态或退出帮助. 长问题/报告可以在填写前阅读及重新打开输入时访问完整内容. 产品界面文字保持英文; 中文内容、宽字符及 ANSI 使用原生字符宽度处理. 遵循实际明暗/自定义主题, 不将概念图配色写死到产品.
