# TUI 设计

[English](../../../design.md) · 以英文版为准。

Pi Stuff 融入 Pi 的界面、主题和操作习惯，在具体功能需要时扩展。这些是未来功能共用的设计规则，不代表 Pi Stuff 已经实现了相应界面。[代理指令](AGENTS.md#详细操作流程)规定何时创建 TUI 原型以及使用哪个技能。

## TUI 原型保真标准

TUI 原型直接呈现拟交付的产品界面。在被评审的使用场景中，布局、间距、文案、状态和交互必须与预期的真实界面一致。这项标准在探索设计时就适用，无须先完成具体产品规格。

使用真实 Pi TUI 组件，并放在其预期的宿主环境中展示，包括周围的编辑器和 statusline。数据与执行可以在隔离环境中模拟。显示的消息、路径、模型信息、计数和耗时应与场景相符，避免实现上的简化影响界面判断。

被评审的终端只包含产品内容和操作。不得加入 demo/prototype 标识、模拟说明、导览面板、调试状态或原型专用快捷键。正常产品的帮助、状态和错误反馈仍应显示。删除演示标识时，也要删除为它预留的空间。

在文件和交付文档中标明原型身份，并在那里说明模拟执行、未实现行为和验证限制。方案选择、重播、场景注入和调试检查通过启动参数或被评审终端之外的开发控制界面操作，不得占用该终端的空间、焦点或快捷键。

交付前检查实际终端，并操作本次评审涉及的交互。用户应能直接判断画面和体验操作，无须在脑中删去演示元素或补全缺失的 UI 行为。尚存的一致性差距在界面之外说明；未经验证不得声称完全一致。

## 截图证据

使用 Terminal Control 导出代表维护者 Ghostty 环境的图像时, 必须明确指定以下字体栈:

```sh
--font-family "JetBrainsMono Nerd Font Mono, Symbols Nerd Font Mono, LXGW WenKai Mono"
```

不得依赖导出工具的默认字体列表. 字体缺失时, 工具可能静默选用另一种已安装字体, 导致截图与被评审的终端不同. 字体栈或调色板会影响判断时, 须随证据一并记录. 该选项只控制导出的 SVG 或 PNG; 实际 TUI 仍使用所属终端配置的字体.

## 禁用的浮层结构

Pi Stuff 不得使用以下两类多分区控制浮层: 在浮层顶部使用横向标签导航, 或在浮层内部设置常驻侧栏导航. 本规则适用于整个仓库, 即使 Pi 能在技术上渲染这些结构也不例外.

需要类似的多分区导航时, 必须改用其他结构, 并按适用流程用真实组件制作原型后再决定是否接受. 否决上述两种浮层不代表自动接受 drilldown 原型或其他替代方案.

## 信息与状态

让用户容易看清当前操作、关键结果和可用的下一步。具体布局与辅助信息随功能确定。

按功能需要区分加载中、没有数据、没有匹配结果和失败。耗时操作提供可见的状态反馈；只有能计算真实进度时才显示百分比。这些状态优先复用 Pi 的现有组件和展示习惯。

## 主题与反馈颜色

使用 Pi 当前主题及其文本、选中项、边框、成功、警告和错误等语义颜色。自定义组件使用 Pi 传入的主题。状态同时用文字表达，让用户无需辨认颜色也能理解失败信息。

同时验证内置 light 和 dark 主题. 对已证实对比度不足的内置颜色, 可在功能内部做局部修正, 不修改 Pi 全局主题或替换自定义配色值. 记录已测试的配色和背景, 保留语义色相与状态文字.

## 键盘与焦点

优先复用 Pi 的现有组件和交互方式, 在适用处保留可配置的选择和提交键. Pi Stuff 面板固定使用 Esc 返回或退出, 包括尺寸提示和嵌套编辑器, 不替换为 Ctrl+G 等重映射取消键. 面板关闭后, 将焦点还给输入框或发起操作的控件.

功能快捷键必须能在 60% 键盘上直接使用. 不将 PageUp、PageDown、Home、End 或功能键区按键分配给功能操作. 翻页使用 `[` 和 `]` 等普通键, 页内提示须与实际支持的按键一致. 复用 Pi 原生选择导航, 不修改宿主全局键绑定.

同一页面加载、刷新、保存和翻页时, 保持尺寸和控制区位置稳定. 不同类型页面可以采用不同高度: 短菜单和设置页按内容收紧, 不填充到报表高度. 只为该页临时反馈和说明换行预留必要空间. 长报告使用固定预算的内容区、分页及可见页码, 不随记录增加撑大面板. 调整终端尺寸时可以改变内容预算. 换行和分页须保留查看已保留文本的途径, 并明确区分上游截断和显式报告大小限制.

分页表格每页保留标题和列名. 报告有多个分区时, 当前页所属分区及各列含义始终可见. 外部报告先解析为界面所需字段, 不以原始 CLI 文本堆叠代替结构化视图.

## 窄终端

根据终端可用宽度，采用适当的换行、紧凑布局和截断。如果路径或其他必要信息被缩短，应提供查看完整内容的方式。关键状态与退出操作须清楚可辨。

终端过小、无法提供有用布局时，显示明确的尺寸提示，并保留退出方式。最低尺寸随实际功能确定，目前不设统一的固定阈值。

## 取消与后台工作

使用临时面板的返回或取消操作时，关闭面板，并请求取消由它发起的临时操作，例如搜索。关闭面板不能让该操作悄悄变成后台任务。

明确作为后台任务启动的工作，可以在面板关闭后继续运行，但须提供查看状态和停止的入口。取消意味着停止后续工作，不代表已经完成的修改被撤销。具体回退或恢复行为随对应功能确定。

## 操作反馈

失败通过 Pi 聊天区域的错误通知显示，文字不定时消失。说明失败的操作和实际结果，包括修改是否已经保存；已知时提供原因和有用的下一步操作。

普通成功消息同样沿用 Pi 现有通知行为。在当前聊天画面保留提示，不承诺它在重新加载、重建会话或重启后仍然存在。现阶段不将持久错误历史设为共用要求。

## 随具体功能确定

具体布局、信息密度、最低终端尺寸和功能专属操作，随对应功能设计时确定；不可逆影响、取消的限制和恢复方式也在那时说明。上述共用规则不要求每次 UI 修改都创建原型或新增测试套件；适用工作与证据遵循[代理工作流](AGENTS.md)和[质量保证](quality-assurance.md)。
