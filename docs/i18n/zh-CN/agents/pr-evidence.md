# PR 证据

[English](../../../agents/pr-evidence.md) · 以英文为执行依据, 本文仅供人阅读.

PR 应让维护者在阅读完整差异前判断影响、决策和证据. 这适用于代码、文档及配置. 小改动保持简短, 不为填模板而编造场景或文档. 使用 Sepia, 遵循[语言与呈现](../CONTRIBUTING.md#语言与呈现).

## 准备审查

将完整 base-to-head 差异与任务验收条件比较. 说明变化和不变的部分、相关取舍、实际验证、风险和未解决问题. 链接持久决策, 不重复抄写. 证据中移除敏感信息, 实质变更后刷新受影响的声明.

遵循 [PR 范围、依赖与回退规则](workflow.md#pr-范围依赖与回退)：关联工作注明前置 PR 和合并顺序, 风险部分说明适用的代码撤回或数据恢复路径. 链接任务的当前主责 session 记录, 在审查证据中标明审查会话.

## 必需章节

使用 `.github/pull_request_template.md` 的五个章节作为人工审查提纲, 而非机器解析契约:

| 章节                          | 内容                                           |
| ----------------------------- | ---------------------------------------------- |
| Behavior and impact           | 前后行为或流程、影响对象和不变范围             |
| Approach and decisions        | 方案、相关取舍和有用的决策链接                 |
| Verification and reproduction | 实际命令、前提、观察结果和验证局限             |
| Risk and review               | 风险、独立审查状态、发现及处理                 |
| Related work                  | Issue 与 Beads 链接, 或有依据的小修/初始化例外 |

每节先英文后中文, 使用易于阅读证据的普通 Markdown. 不再限定标记语法子集, 也没有占位符解析器. 空模板不是证据. 缺少验证时直接解释, 不把它包装成成功声明.

说明低/高风险, 以及独立审查已完成、不需要、待完成或明确豁免. 提供审查者/工具身份、base/head 范围、发现和处理, 或适用的无需审查理由. 豁免须链接维护者的明确授权. 不抄用其他 PR 的已完成审查声明.

高风险 PR 就绪前需要完成独立审查或获得明确豁免. 审查待完成时保持草稿, 缺少审查者作为阻塞报告.

## 按变更类型提供证据

- Bug: 报告复现、版本/输入、观察到的失败和相关验证. 可行时增加有用回归覆盖, 说明局限.
- 可见 UI 或终端变更: 提供真实截图或录屏. Mockup 是设计证据, 不是执行证明.
- 后果重大的架构、状态、依赖或并发变更: 链接决策, 有助解释时使用图示.
- 难以浏览的跨模块变更: 提供简短审查地图或可视化材料, 链接实际代码.
- 安全、权限、持久化/恢复、并发/取消、公共 API、依赖、CI/合并政策及大范围重构属于高风险, 需要独立审查.
- 简单文档或格式修改通常只需简述影响和实际检查.

无法提供证据时说明仍未验证的部分, 对后果重大的不确定性请维护者决定. 链接稳定 CI 或产物, 长日志折叠呈现；本地 `/tmp/` 路径不是公开证据.

## TDD 声明

只有观察到相关测试在实现前失败、实现后通过时才能声称 TDD, 并报告同一命令及 base/fix 上下文. 测试框架或 import 失败本身不算行为复现. 实现后写的测试不是 TDD. 不为满足文字要求添加占位测试或伪造失败日志.

## 独立审查

使用分离只读上下文, 提供固定的比较范围及原始 Issue/规格. 对完整差异同时审查仓库规范和需求覆盖. 一个合适上下文即可, 不必动用所有模型. 执行负责人实施修复.

实质性代码变更的审查者必须加载 `.agents/skills/thermo-nuclear-code-quality-review/SKILL.md`, 应用完整强制上游标准. 文档或机械变更不自动触发该特定深度审查, 高风险要求仍适用. 必需技能或审查者不可用时报告阻塞, 保持待审查状态.

具体结构问题阻塞, 直到修复或用证据反驳并独立复查. 记录处理结果, 测试通过本身不是反驳. 未解决分歧交维护者决定. 修复实质改变已审查行为时进行聚焦复查, 不为重复未变验证而复查.

发布审查者/工具身份、base/head 引用、发现、修复及未解决问题. 代理审查不等于 GitHub approval, 也不授权合并.

## 发布与执行

GitHub 保存需求和选定证据, Beads 保存执行上下文和链接, ADR 保存长期决策. 遵循[跟踪流程](issue-tracker.md), 发布有意义的里程碑, 不逐条镜像内部记录.

PR 正文结构、风险分类、审查真实性及授权由作者和审查者负责, 不通过程序验证. 独立标题 CI 使用 commitlint, 元数据编辑不重跑代码检查. 工作流存在不意味着它是合并必需检查, 修改远端规则集需要明确授权. 更换基线后, 合并前同步分支并重跑代码 CI.

所有进入 main 的变更都通过 PR, 任务分支仍可推送. 不为落地修改而削弱 main 规则集. 合并和 release 分别需要用户明确授权. 本地 Beads 和远端设置不属于 Git 提交, 但修改仍受授权边界约束.
