# Subagent 验证记录

[English](../../subagent-verification.md) · [使用指南](subagents.md)

本文记录 [#55](https://github.com/jczhang02/pi-stuff/issues/55) 的正式实现验证。测试使用正常 Pi 进程加载 `src/pi/index.ts`、独立子代理 SDK 会话和真实工具执行。截图没有使用原型宿主或模拟对话。

## 环境与复现

验收环境为 Linux、Bun 编译版 Pi `0.85.1`、Bun `1.4.0` 和 tuistory `0.11.0`。终端使用 `TERM=xterm-256color`、`COLORTERM=truecolor`、Pi 浅色／深色主题和 Nerd Font。截图由 tuistory 的终端渲染器生成，前景与背景设置匹配对应终端；这些是截图设置，没有修改截图中的界面图像。

离线测试隔离项目、Git 仓库、代理设置、会话、模型服务和 worker：

```bash
bun run check
bun run test
PI_TEST_HOST=/absolute/path/to/compiled/pi bun test tests/system
```

默认 system 测试使用 Bun 运行已安装的 Pi CLI，`PI_TEST_HOST` 选择编译后的可执行文件。确定性 provider 只替代远端模型 HTTP 边界；注册、运行时、会话文件、工作树、工具和 TUI 均使用正式实现。清理只停止该测试拥有的进程与临时目录。

真实模型测试使用已配置的 `openai-codex/gpt-5.6-luna`、`low` 推理、隔离 agent 目录，以及一个已提交的小型 TypeScript 项目。不公开凭证和完整会话记录。提取的计数与检查结果见 [live-results.json](../../evidence/subagents/live-results.json)。

## 真实开发过程

1. 主代理并行启动三个子代理：Explore 检查错误的 `clamp`，Implement 在独立工作树修改并运行 `bun test`，Clarify 用 `ask_parent` 询问非法上下界约定。子代理执行时主代理读取 README。本轮由主代理自动回答 Clarify；用户在子代理界面直接回复另由离线 TUI 测试验证。
2. 进入 Clarify 并发送第二条提示后，继续的是原会话。返回 main 时保留主代理对话和后台结果通知。
3. `/reload` 后进入 Implement，恢复此前的工具调用和修改 diff。第二轮要求补充 `RangeError` 校验和相等边界测试；执行中追加负数边界用例。该引导消息保存在同一个子代理会话中。
4. 真实 Bash 命令打印 `CANCEL_SECOND_READY` 后等待。Esc 在约 0.2 秒内中断命令。保存的工具结果包含 `Command aborted`，没有延迟输出 `UNEXPECTED_END`；其他子代理仍保持完成状态。
5. 取消后续聊使用同一个 Implement 会话和工作树，四个测试再次通过。在其工作树独立执行 `bun test` 也得到四个测试、六个断言通过。主工作树保持干净，两侧 HEAD 提交相同，子代理的修改没有自动提交。
6. 普通保留设置下手动 `/compact` 首先提示会话过小。将隔离测试设置中的 `keepRecentTokens` 设为 1000 后，实际压缩了 4,759 tokens。仍可向上翻阅旧工具调用，摘要使用 Pi 原生可展开组件；压缩后的新提示正确概括了原先修改。计数包含此次压缩用量。
7. Pi 正常退出后，新进程以深色主题重新打开原主会话，恢复 Fleet、子代理历史和压缩记录。未知子代理命令保留草稿，返回 main 再进入也不丢失。80 列界面仍对齐名称、活动、时间及输入输出 token。

Implement 在同一个子代理会话内累计七条用户消息和一次压缩。主代理保存了十二条 subagent 通知，全部为 `display: false`。保留的子代理费用是 SDK 报告值，不作为账户实际账单。

将手动压缩交由运行时管理后，又用真实模型压缩了 Explore 的 2,891 tokens，隔离设置为
`keepRecentTokens=100`。Fleet 显示 `Compacting context` 和运行图标；完成后
恢复此前结果，并累计压缩用量与耗时。原先的对话与工具条目仍保留在新压缩记录上方。

增加恢复检查后，`/reload` 仍能打开原来的只读 Explore 与可写 Implement 对话。再用真实
模型继续 Implement，它根据原上下文正确回答：非法上下界抛出 `RangeError`，四个测试
通过。第八条用户消息保存在原会话 id 和原工作树中。此时主代理共有十三条子代理通知，
全部隐藏。补充验证的计数单独保存在证据 JSON 中，保留原测试过程的记录。

恢复回归只修改测试自己的文件，然后重新启动真实 Pi。它们拒绝缺少工作树信息、未知
工具、丢失的会话文件或路径、空文件和不同的会话头 id，检查没有第二次子模型请求、
没有写入主目录，已有文件的字节内容也不变。放回原文件后，同一进程中的查看器可以
重新打开它。压缩回归会挂起真实摘要 HTTP 请求，在没有键盘输入或模型事件时检查 Fleet
的秒数持续增长，然后通过主代理工具取消压缩。

## 原生 editor 与滚动修复

维护者澄清：只有 editor 右上角的 agent 标识允许与 Pi 原生界面不同。已删除空输入
占位文字和额外提示符；子代理编辑器沿用 Pi 的思考级别边框颜色和 editor 设置。
与安装的 `CustomEditor` 做聚焦对比，确认标签装饰器保留原生输入行、隐藏行提示，
以及已接入编辑器的 working indicator。这项检查针对装饰器；子代理查看器本身尚未
接入 Pi 的 working indicator。

在 fullscreen 编译版 Pi 中打开保留的真实模型 Explore 会话，修复前无论向上滚动
一步还是八步，记录均不移动；PageUp 正常。Pi 将标准化鼠标事件与键盘输入分别分发，
而 viewer 缺少鼠标处理器。修复后沿用 Pi 的滚轮步长，并把 editor 鼠标事件交回原生
编辑器。向上八步、再向下八步，准确回到初始画面；点击草稿后输入，也会在点击位置
插入文字。这轮检查复用了已有真实模型历史，没有发起新的模型调用。

编译宿主 UI 回归展开真实 `read` 工具返回的 80 行内容，双向滚动到首尾、检查
Home/End，并断言草稿保留、主代理 worker 仍存活。新增滚轮断言已在加入处理器前
观察到失败。独立审查还发现旧的 `Ctrl+End` 查看器快捷键覆盖了原生编辑行为：
修复前依次按 Ctrl+A、Ctrl+End 并输入 `!`，字符被加到草稿开头，记录跳到底部。
移除该拦截后，回归检查字符加到草稿末尾，记录仍停留在顶部。测试发送真实终端序列
`CSI 1;5F`，因为 tuistory 0.11.0 的 `press()` 会把 Ctrl+End 编码为普通 End；
分页断言也检查 Pi 原生的四行重叠。下方截图已在恢复原生 editor 后重新采集。

## 与原生 Pi 0.85.1 对照

子代理页面是在自定义全屏浮层中复用原生组件，没有启动另一个完整 Pi InteractiveMode。
对照进程使用编译版 Pi、同一份 Implement 历史的副本，不加载扩展或凭证；两个终端均为
140 × 38、深色主题，没有发起模型请求。无凭证的对照进程没有可用模型，因此不比较其
模型／上下文 footer 数值与已认证子代理的差异。

| 区域              | 结果与证据                                                                                                                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| editor 外观       | 复用原生输入行、光标与内边距，只有子代理额外添加边框标签。此前装饰器检查覆盖空输入、多行输入和隐藏行提示。                                                                                           |
| 编辑与基本导航    | 真实宿主测试覆盖草稿保留、原生 Ctrl+End、滚轮、Home/End 和分页四行重叠。进入／离开子代理保留主代理 worker 的运行。                                                                                   |
| 斜杠命令与补全    | 普通 Pi 输入 `/mo` 出现 `model`、`scoped-models`、`import` 候选，子页面没有候选。子页面只实现 `/help`、`/stats`、`/compact`。                                                                        |
| 按用户消息跳转    | 发送真实 `CSI 1;5A`（Ctrl+Up）后，普通 Pi 跳到此前用户消息，子页面不动。子页面仅实现分页／半页／逐行／首尾滚动。                                                                                     |
| 对话搜索          | **未修复缺陷：** `CSI 102;6u` 在子页面上弹出宿主搜索框，但搜索的是底下的主会话。独立打开子历史搜索 `clamp` 有 14 处，主会话有 5 处。这不是子代理搜索。                                               |
| Working indicator | 装饰器能保留已接入的原生运行指示器，但子代理查看器尚未接入它。目前通过 Fleet 显示进展，没有原生 editor 的运行指示器。这是源码核查结果，未声称通过运行中指示器一致性测试。                            |
| 追踪实时输出      | 源码对照：原生 ScrollView 在向上浏览后保持绝对位置，当前查看器保存距底部的距离，新输出可能移动正在阅读的内容；也没有原生滚动条和回到底部提示。这轮没有另用流式 provider 实测这一点。                 |
| 渲染设置          | 源码对照：思考隐藏、输出内边距、Markdown 变换和图片显示设置没有完整传递；工具使用 SDK 定义，没有完整接入宿主的内置 renderer 合并。因此不能据复用组件声称每种工具显示都相同。                         |
| Footer 设置       | 源码对照：子代理没有同步 FooterComponent 的自动压缩开关，而组件默认是 true；关闭自动压缩的子代理仍可能显示 `(auto)`。没有独立分支时还会回退到父分支，包括 cwd 不同的情况。这些仍是待修正的显示问题。 |
| 压缩后历史        | 子页面有意显示完整保存分支，包括压缩前记录；普通 Pi 则按压缩后的上下文条目重建可见对话。                                                                                                             |
| 退出／取消键      | 子页面 Ctrl+C 返回 main，原生通常先清空输入；子页面 Esc 取消活动任务或关闭已结束任务的页面。这是明确的 Fleet 操作约定，不是完整原生 app 快捷键行为。                                                 |
| 恢复编辑状态      | 源码对照：重新进入子页面会恢复草稿文字、记录滚动和展开状态；编辑器是新建的，没有恢复此前的光标／选择区域和撤销栈。                                                                                   |
| 宿主级操作        | 子页面没有接入 Pi 的完整命令、补全、模型选择、剪贴板图片和扩展快捷键。复用组件不会自动获得这些操作。                                                                                                 |

搜索错位来自宿主输入分发顺序：安装版本的 `pi-tui/dist/tui-alt-screen.js` 构造时先
注册 viewport 输入监听器，`handleViewportInput()` 在
`shouldDeferViewportInputToOverlay()` 之前处理搜索；扩展的 `onTerminalInput()`
监听器随后才追加，因此不能简单在当前查看器里提前拦截该键。这轮没有修改 Pi 私有方法、
全局键位或依赖。完整原生交互验收仍未通过，搜索缺陷未解决前 PR 保持草稿。

## 切换的实际机制

主代理和子代理各自的 **AgentSession（代理会话）** 持有对话与执行状态。
**AgentView（会话视图）** 持有显示状态：草稿、滚动偏移、工具展开状态。Fleet 选择
决定哪个视图获得焦点，不会另开一次子代理执行，也不会替换主会话。

`Subagents.open()` 保存主草稿，通过 `ctx.ui.custom()` 的 `overlay: true` 打开
`openViewer()` 全屏浮层。浮层绑定选中子代理的既有会话，用原生编辑器／消息／工具
组件显示内容。`Transcript` 订阅 SDK 事件，文本或工具结果到来时请求重绘。
`Fleet.send()` 按选中子代理的状态，将输入路由为问题回复、运行中引导或原会话续聊。
关闭浮层时保存子草稿、释放显示资源并恢复主编辑器；关闭视图不等于取消任务，取消有
独立操作。

这属于视图切换、会话与视图状态分离，以及输入路由。各会话共享一个 Pi 进程，
会话不是独立操作系统进程。Git worktree 用于隔离可写任务的文件，与当前屏幕显示
哪个会话无关。实现没有调用 `switchSession()`：Pi 宿主替换会话时会先中断并释放
原运行时。

## 证据边界

这些结果适用于上述 Linux／Bun／Pi 环境及已配置的 Codex 模型，不能据此声称支持 Windows／macOS、Node 宿主、任意 provider 或任意自定义 footer。Pi 的公开 footer API 只允许一个拥有者，使用指南中的组合限制仍然存在。子代理查看器支持指南列出的命令，没有嵌入 Pi 的整套命令分发器。

PR 记录最终检查计数、比较提交、独立标准／需求审查、修正与验收边界。截图或模型回答成功本身不能证明取消和恢复机制正确。
