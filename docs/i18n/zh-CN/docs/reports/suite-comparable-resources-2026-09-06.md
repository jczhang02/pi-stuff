# 可比 Package 资源与保留的输入失败

与可比的优化前 Package `40101bb2` 相比，`e7b1170e` 的七种 Suite 工作负载均减少了 scope 内 CPU 用量。
各两个样本的 CPU 中位数下降 11.2–28.8%；每个候选值都低于对应的两个基线值。一个候选后台 Agent 样本
违反锁定输入门槛：命令补全在 48.868 ms 后出现，超过 40.465 ms 上限。后续通过样本不抵消这次失败。
整个 Suite 的验收仍未完成。

[数值记录](../../../../../docs/reports/suite-comparable-resources-2026-09-06.json)保留全部 32 个样本、单次门槛
违规、Source 身份及私有证据哈希。基线与候选使用相同的依赖锁文件和 Package 依赖声明。`40101bb2` 已包含
认证 Host 适配、Work Continuity 和 Goal 终态回复语义。[较早的生命周期对照](suite-lifecycle-comparison-2026-09-06.md)
使用更旧的基线，不能单独归因于此次优化。

## 内核跟踪 CI 的时限失败

[运行 34051108002](https://github.com/jczhang02/pi-stuff/actions/runs/34051108002)保留的 Provider 和 Session
记录解释了基线前台观测为何不完整：两个子进程均成功结束，父进程在 2026-09-06 18:18:56.993 UTC 请求最终
回复，夹具安排四秒后发送。最后采集时间为 18:18:58.831 UTC，比计时器最早触发时间提前 2,161.883 ms。
记录中没有 Provider 错误。60 秒观测预算在被跟踪负载结束前用完；Tool 完成不能证明 Provider 死锁。
此前未保留这些记录的失败仍未归因。

调度诊断现使用独立的 75 秒观测预算，不能应用验收门槛，结果记录诊断用途和时限。普通 30/60 秒观测、
采集器外层 90 秒限制、隔离、完成检查及锁定响应性门槛不变。后续采集成功只能建立调度证据，不能抵消保留的输入失败。

## 后台输入的定点诊断

在 `e51caab5` 上分四次诊断输入失败，未改变生产行为。第一次 CPU profile 观测到 49.579 ms 反馈，
该区间 47 个样本中有 44 个位于原生布局渲染。采样也延长了其他普通反馈，因此这些栈不能解释两次未采样失败。

下一次直接计时记录 430 次绘制，累计 360.564 ms，最大 4.700 ms。另一轮对首次 FFI `flock` 加载的标记
测得 1.836 ms；两次均未复现反馈延迟。最后的文件系统调用跟踪记录父进程主线程 18,039 次已完成调用，
累计 198.967 ms，最大 8.947 ms，发生于启动时创建 Jiti 缓存文件。其最慢输入/补全准备为 14.240 ms。
这些只是对应运行的观测值，不能作为偶发渲染或 I/O 延迟的上界。

四个工作负载均完成并回收两个子 Agent、记录两个后台结果并保留自动 Naming/Usage。临时渲染包装、FFI
标记和 strace 命令均已撤除，数值记录绑定探针、profile 和观测的哈希。未依据这些未复现的探针重写渲染、
提前加载或修改文件系统操作；48.868/72.710 ms 失败与此前后段停顿仍未解决。
