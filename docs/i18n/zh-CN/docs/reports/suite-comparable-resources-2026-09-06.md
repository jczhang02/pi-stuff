# 可比 Package 资源与保留的输入失败

与可比的优化前 Package `40101bb2` 相比，`e7b1170e` 的七种 Suite 工作负载均减少了 scope 内 CPU 用量。
各两个样本的 CPU 中位数下降 11.2–28.8%；每个候选值都低于对应的两个基线值。一个候选后台 Agent 样本
违反锁定输入门槛：命令补全在 48.868 ms 后出现，超过 40.465 ms 上限。后续通过样本不抵消这次失败。
整个 Suite 的验收仍未完成。

[数值记录](../../../../../docs/reports/suite-comparable-resources-2026-09-06.json)保留全部 32 个样本、单次门槛
违规、Source 身份及私有证据哈希。基线与候选使用相同的依赖锁文件和 Package 依赖声明。`40101bb2` 已包含
认证 Host 适配、Work Continuity 和 Goal 终态回复语义。[较早的生命周期对照](suite-lifecycle-comparison-2026-09-06.md)
使用更旧的基线，不能单独归因于此次优化。

## 成本与可见反馈

全部运行使用同一个 Pi 0.85.0 可执行文件
`0cfd1bf3e9468f1052d172502fa388e8e8e53dcdeb9fa97f1ef828fdd7757072`、内嵌 Bun 1.3.14 和 120×40 终端。
observer 使用 Bun 1.4.0。测量于 2026-09-06 17:42:14 至 17:57:55 UTC 串行执行，机器为 i9-13900H，
20 个在线逻辑 CPU，Linux `6.19.10-jc-xanmod1`。

批次按基线/候选/候选/基线顺序运行。每批依次执行 Goal、原生 Tool、Suite Tool、前台 Agent、后台 Agent、
Context、冷 Ledger Tool 和冷 Ledger 前台 Agent。每个样本新建私有配置及用户、网络、PID 命名空间。

CPU 和记账内存覆盖 Host cgroup，包括其中的 Worker 和已回收子进程，统计至退出前的最终观测。
observer、tmux、合成 HTTP 服务和 Ledger 种子创建不在该范围内；冷恢复包含在内。前台执行移至 Worker
并未把其 CPU 用量移出这些计数器。

并非所有内存指标都改善。直接前台 Agent 的最终存活进程 RSS 中位数从 645.4 增至 663.9 MB，冷 Ledger
前台场景从 684.8 增至 713.2 MB；其他 Suite 场景的最终 RSS 中位数下降。最终 RSS 是快照，不是进程树
合计峰值；记账内存峰值还包含其他费用，也不是累计分配量。最终进程 I/O 遗漏已退出子进程，不能证明总 I/O 节省。

每次 Suite 运行均自动请求并持久化一次 Naming，自动执行一次 Usage HTTP 刷新。Agent 场景完成两个子 Tool，
并按进程身份确认两个子进程均已回收；后台场景还在父 Agent 独立结束的情况下持久化两个不同的完成结果。
Context 发起三次原生请求并检索到写入证据；Goal 自动续行后持久化完成状态和唯一最终回复。
冷 Ledger 包含 24 次合成执行，每个结果为 800,000 字符；种子创建没有禁用校验。

## 为什么不能算通过

所有样本的观测连续：活跃 Spinner 无缺失，活跃覆盖至少 12.145 秒，最大采集间隙不超过 24.608 ms。
候选唯一超标是 `1-candidate-background`，证据 SHA-256 为
`d48fce849b085ef422a2360ccd5950faa97ae003f90121f202948d7f424141a7`。
命令补全准备始于 observer 时钟原点后 10,639.420 ms，之后三次采集仍无补全列表；列表与排队 Agent roster
于 10,688.288 ms 同时出现。这证明首次 Agent 启动附近的反馈延迟，不能定位负责函数。
没有将它作为观测缺口丢弃，也没有在缺少对应 Suite-off 复现的情况下归因于原生 Host。

两个基线前台、后台样本均违反 Spinner/输入门槛；两个冷 Ledger Tool 样本违反 Spinner 门槛，两个冷 Ledger
前台样本违反 Spinner/输入门槛。全部失败保留在记录中。[锁定门槛](../../../../../docs/reports/suite-responsiveness-gates-2026-09-05.json)
没有改变。候选 Spinner 最大值通过不能抵消独立输入失败，也不能解释此前保留的后段停顿。

较早的本地矩阵使用 `6d0507c1`，在运行候选之前就停于 Goal：该 Package 的终态 Tool 语义未产生当前夹具
要求的最终回复。其部分样本不计入本报告。两个独立的 `e7b1170e` CI 跟踪尝试也在基线工作负载阶段停止，
未比较候选（[第一次](https://github.com/jczhang02/pi-stuff/actions/runs/34048786759)、
[第二次](https://github.com/jczhang02/pi-stuff/actions/runs/34049432866)）。最后画面显示 Tool 已完成，Pi 仍处于
恢复状态；这些日志尚未定位原因。跟踪运行用于诊断，不是活性门槛验收。

分配/GC、精确调度唤醒、进程树合计峰值 RSS、最长主线程工作区间及其余 owner/恢复场景仍需独立证据。
本轮保留了表中工作负载的自动功能，但没有执行所有配置的外部服务，也没有完成[资源清单](suite-resource-inventory-2026-09-05.md)。
