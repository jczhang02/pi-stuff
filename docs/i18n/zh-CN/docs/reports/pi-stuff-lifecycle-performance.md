# Pi Stuff 生命周期性能

> **当前处置（2026-08-29）：** 本报告保留 Pi 0.84.1 与 0.84.2 的生命周期测量证据。已验证宿主现在是 Pi 0.84.3；其身份以 [`docs/compatibility.md`](../compatibility.md) 为准。Schema 6 基准和文末回归预算仍是可执行仓库检查，但下方历史测量不会重新标为 0.84.3 结果。

## 范围

本报告记录 Bead `ps-5bw` 的验收证据。测量在真实全屏 PTY 中使用已验证 Pi 0.84.1 宿主和 Bun 1.3.14。每次运行都有隔离设置、Home、缓存和会话目录。模型是确定性本地 Provider，因此凭据或网络请求不会影响结果。

基准比较两个变体：

- **Host** 只加载确定性用例软件包。
- **Suite** 加载 Pi Stuff 软件包和同一个用例软件包。

启动有两个独立缓存维度。每个样本都是新 Pi 进程，因此其进程局部套件模块图是冷态。每个矩阵单元内，一次保留的预处理运行会预热可执行文件和文件系统缓存；后续三个预算样本是系统缓存热启动。基准有意不清除机器全局页缓存。

它覆盖 100×32 与 64×28 终端；全新、六轮、240 轮和依赖降级会话；普通退出、Ctrl-C、重载、首次输入、改变源码后重载，以及活跃后台 Shell 或 Agent 下关闭。每个普通生命周期矩阵单元先一次预热，再三个测量样本。活跃资源关闭在两种终端尺寸下的全新和 240 轮会话中演练；昂贵的源码变化重载只在 100×32 演练一次。每个进程离线运行。降级场景增加异常 Magic Context 配置。每个适用进程退出后都会检查终端尺寸、规范输入、Echo 恢复、跟踪子进程稳定、有效会话 JSONL、已完成提示词标记和后台/Agent 工具调用结果回执。接受未触碰新会话不产生文件的 Pi 有意行为，因为没有历史需要保留。

运行完整基准：

```bash
bun run benchmark:lifecycle --output .artifacts/lifecycle-benchmark/final.json
```

该验收命令要求两个变体、所有场景与操作、两种终端尺寸、至少三个测量样本、一次预热和生命周期追踪。它会把覆盖或 p95 预算违规写入 JSON 报告，并以失败退出。直接脚本调用仍可用于明确不构成认证的实验。

最初超预算的单元会收到一次独立确认批次，样本数和预热数相同。每个单元摘要记录两个计数，因此验收不能依赖未预处理确认批次。只有同一绝对或配对宿主开销预算再次超出时，验收才失败。基准不会提高预算或丢弃任何批次：初始与确认样本都留在 JSON 报告。这样可区分可重复 Pi Stuff 回归与一次调度器离群值，同时保留原始墙钟证据。

原 `ps-5bw` 强制运行本地记录在 `.artifacts/lifecycle-benchmark/acceptance-post-rebase-final.json`。它启动 292 个隔离 Pi 进程，最终 `acceptance.passed: true` 且无发现。最差 Suite p95 为：普通启动 1,488.08 ms、240 轮启动 1,660.97 ms、首次输入确认 25.60 ms、首次响应 811.88 ms、普通重载 154.25 ms、240 轮重载 501.30 ms、普通退出/Ctrl-C 97.29 ms、240 轮退出/Ctrl-C 281.30 ms、全新活跃资源关闭 141.14 ms、240 轮活跃资源关闭 333.28 ms、源码变化重载 4,284.66 ms。

## 消息提交后续

Bead `ps-nxm` 后来发现，延迟 Context 适配器为每次交互提示词加入了两次合成 17 ms UI 帧等待，并把官方 Magic Context 模块、工厂、数据库和会话初始化留在第一次 Provider 轮次路径。上游扩展提交消息时两者都不做。对可识别且无需迁移的配置，Pi Stuff 现在会在 `session_start` 完成这些工作，并删除两次帧等待。缺失或旧版配置仍休眠到直接使用授权创建或迁移；启动可以初始化可重建派生状态，但不修改用户配置。

生命周期基准 Schema 5 会在同一个真实 Pi 进程中发送两条提示词。它分别记录首轮确认/响应和稳态确认/响应，要求两条提示词都进入持久会话，并强制专用稳态预算。在五样本 100×32 全新会话差分中，未修复套件的稳态确认 p95 为 24.00 ms，稳态响应为 68.90 ms。最终矩阵覆盖两种终端尺寸下已配置全新、六轮和 240 轮会话，以及异常配置降级开放回退对照。初始矩阵中，Suite 稳态确认 p95 为 2.28–4.05 ms，稳态响应为 21.01–50.36 ms。唯一超预算单元 100×32 240 轮响应（50.36 ms）在独立五样本确认中以 38.84 ms p95 通过；确认确认时间为 2.92 ms p95。首次输入确认为 3.00–4.58 ms，首次确定性响应为 53.29–114.85 ms。已配置启动增至 2,022.24–2,388.15 ms；降级原生开放回退启动为 2,068.33–2,088.97 ms。同一矩阵中 Host 稳态响应为 19.55–21.16 ms。

最新保留 Schema 6 运行本地记录在 `.artifacts/lifecycle-benchmark/ps-9t2-1-4-final.json`。它运行 292 个隔离 Pi 0.84.2 进程，带 6,500 个保留 8 KiB 工具结果，最终 `acceptance.passed: true`、无发现、无确认单元。两种终端尺寸下，6,500 工具 Suite p95 为：重载 1,997.18–2,053.80 ms、第一次确定性响应 465.75–488.09 ms、同进程第二次响应 54.53–68.28 ms、活跃后台 Shell 关闭 198.84–201.99 ms。

## 历史 ps-5bw 诊断与变更

原套件有两项实质延迟：

1. Magic Context 在启动时急切导入。该导入约耗时半秒，而且调度不当时会把工作移到 Enter 后。
2. Pi 会在 `/reload` 时正确创建新 Jiti 加载器，但重新求值未变化 Pi Stuff TypeScript 模块图又增加约半秒。

Pi Stuff 现在会在延迟激活 Magic Context 前绘制并确认首次输入，而第一次 Provider 轮次和压缩门槛仍会等待有效 Context 所有者。生成的软件包入口现在是一个小包装器。它跨重载缓存未变化套件运行时模块命名空间，但针对新宿主 API 重新运行每个能力安装器。完整 `src/` 指纹会使缓存失效。变化的嵌套源码使用新的无修改 Jiti 加载；被拒绝加载会被驱逐并可恢复。

没有增加编译 `dist/` 通道、启动网络请求、软件包安装、子进程或启动文件写入。

### 历史结果

下列值为毫秒 p95 墙钟测量。范围合并两种已验证终端尺寸。

| 路径 | 之前 | 之后 | 解释 |
| --- | ---: | ---: | --- |
| 延迟 Context 激活前的冷套件启动 | 2,042–2,229 | 1,157–1,405 | 急切 Magic 导入离开启动路径。 |
| 未变化重载，全新会话 | 624–672 | 131–135 | 套件开销现在比 Host 约高 20 ms。 |
| 未变化重载，短恢复会话 | 669–689 | 137–139 | 会话重载保持响应。 |
| 未变化重载，240 轮会话 | 965–1,033 | 470–471 | 剩余时间大多由 Host 水合/持久化占用；Host 测得最高 438 ms。 |
| 首次输入确认 | 22–29 | 22–26 | Magic 激活前已绘制并确认 Enter。 |
| 首次确定性响应 | 764–899 | 643–817 | 包含第一次延迟 Magic 激活和用例响应。 |
| 普通 Suite 退出，全新/短/降级 | 85–106 | 84–95 | 没有引入新的关闭排空。 |
| 普通 Suite 退出，240 轮会话 | 267–274 | 241–270 | 长会话持久化由 Host 主导。 |

其他生命周期证据：

- 活跃后台 Shell 父级关闭：130–140 ms；跟踪 Shell 在两秒内稳定；
- 活跃 Agent 父级关闭：87–89 ms；子 Pi 与其 Shell 都在八秒内稳定；
- 异常 Magic Context 配置仍到达编辑器，22–24 ms 内确认输入，完成确定性响应并以恢复后的终端退出；
- 未变化重载发送一次 `suite.module-imported` 事件加缓存命中事件，同时仍重新运行每个能力安装器并恢复必需工具界面；
- 复制的冷软件包中编辑嵌套 Todo 模块，重载后发送编辑标记，证明深层源码失效。该正确性路径约耗时 4.1 秒，因为新 Jiti 加载器有意禁用文件系统缓存且不写入。

### 已取代 ps-5bw 回归预算

下列 p95 预算适用于原 `ps-5bw` 验收运行。回归调查应先比较 Host 与 Suite 单元，再修改能力。

| 测量 | 预算 |
| --- | ---: |
| 全新、短或降级 Suite 启动 | ≤ 1,600 ms |
| 240 轮 Suite 启动 | ≤ 1,800 ms |
| 首次输入确认 | ≤ 50 ms |
| 包含延迟 Context 激活的首次确定性响应 | ≤ 1,100 ms |
| 全新、短或降级普通退出 / Ctrl-C | ≤ 150 ms |
| 240 轮普通退出 / Ctrl-C | ≤ 350 ms |
| 全新、短或降级未变化重载 | ≤ 200 ms |
| 240 轮未变化重载 | ≤ 550 ms |
| 活跃后台 Shell 或 Agent 父级关闭，全新会话 | ≤ 250 ms |
| 活跃后台 Shell 或 Agent 父级关闭，240 轮会话 | ≤ 375 ms |
| 带嵌套代码证明的冷源码变化重载 | ≤ 6,000 ms |

源码变化重载预算是开发正确性防护，不是普通用户路径。绝不能通过接受过期代码、交付编译产物或在软件包首次导入期间写入来改善。显式源码刷新所使用、经过内容校验且可丢弃的 XDG 转译缓存是允许的。已验证基准会强制表中每项预算，而不是把它当作叙事指引。

240 轮活跃资源关闭上限包含套件生命周期加固合并后增加的 25 ms 调度器余量。十样本确认测得中位数 342.63 ms、最大值 359.45 ms，同时保留持久后台工具回执和已证明子进程清理；该运行中所有其他上限不变。

## 当前回归预算

Schema 6 使用至少 8,192 字节的 6,500 个保留历史工具结果验证 Pi 0.84.2。更大的真实形态会话和 Pi 0.84.2 宿主基线取代上方较早的 240 轮 Pi 0.84.1 上限。基准为已验证本地配置强制以下 p95 上限：

| 测量 | 预算 |
| --- | ---: |
| 全新或短已配置 Suite 启动，或降级原生开放回退启动 | ≤ 2,700 ms |
| 带已配置 Context 初始化的 6,500 工具 Suite 启动 | ≤ 12,000 ms 且 ≤ Host + 2,250 ms |
| 其他 Suite 启动相对配对 Host 单元开销 | ≤ 2,250 ms |
| 首次输入确认 | ≤ 50 ms |
| 第一次 Provider 边界，普通 / 6,500 工具会话 | ≤ 800 ms / ≤ 2,300 ms |
| 第一次确定性响应，普通 / 6,500 工具会话 | ≤ 1,100 ms / ≤ 2,600 ms |
| 同进程稳态输入确认 | ≤ 15 ms |
| 同进程稳态 Provider 边界，普通 / 6,500 工具会话 | ≤ 100 ms / ≤ 350 ms |
| 同进程稳态确定性响应，普通 / 6,500 工具会话 | ≤ 150 ms / ≤ 550 ms |
| 全新、短或降级普通退出 | ≤ 150 ms |
| 全新、短或降级 Ctrl-C | ≤ 250 ms |
| 6,500 工具普通退出 / Ctrl-C | ≤ 550 ms |
| 全新、短或降级未变化重载 | ≤ 200 ms |
| 6,500 工具未变化重载，包括导入会话超过其模型窗口 2 倍时的有界原生预检 | ≤ 2,500 ms |
| 活跃后台 Shell 或 Agent 父级关闭，全新会话 | ≤ 250 ms |
| 活跃后台 Shell 或 Agent 父级关闭，6,500 工具会话 | ≤ 375 ms |
| 带嵌套代码证明的冷源码变化重载 | ≤ 8,000 ms |

更高启动上限明确表达取舍：已配置模块、工厂、数据库和会话初始化发生在编辑器被接受为就绪前，而不是 Enter 后。它不授权配置创建或迁移。最初超预算单元仍需独立确认批次后才能判定验收失败。
