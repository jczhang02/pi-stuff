# 设计依据

## 模板选择

采用 Kami `long-doc`，目标为 9 页 A4。V1.1 在原有 Pi Stuff 源码、Claude Code 官方二进制黑盒实验、规则矩阵和产品建议之间，新增一页非官方公开源码快照分析。篇幅因此由 8 页扩为 9 页，避免把来源限制、实现链路和产品结论挤在同一页。

## 排版与颜色

正文使用 TsangerJinKai02，英文技术词保留等宽字体。暖纸色作为底色，墨蓝只用于章节锚点、关键数字与三张流程图中的焦点节点；没有加入第二强调色、渐变或阴影。表格承担证据分层与直接比较，流程图只解释状态门槛和显示流水线，避免把比较内容硬画成装饰性图形。

## 构图

封面采用左上标题与右下版本信息的不对称结构。正文每章一页，阅读顺序固定为论点、证据、结论。第 2 页目录直接标出三类证据；第 3 页解释为什么官方二进制行为与非官方源码快照不能混用；第 5 页保留 Claude 2.1.220 的可重复黑盒行为；第 6 页单独呈现 Tool 分类、连续段归并和双态渲染的源码链路；最后两页完成风险矩阵与演进路线。

## 证据表达

公开镜像固定引用提交 `6f6f12b37f529488b10e53928dd5508bb93535c7`，不引用可变的 `main`；核心折叠文件与初始源码提交 `9f51e716` 相同。报告显式标注该仓库并非 Anthropic 官方来源、没有可验证产品版本、原始快照不完整。只有与 2.1.220 黑盒实验一致的规则才写作“相互印证”；MCP、Memory 和全屏条件路径只写作“静态发现”。

## 材料缺口与处理

项目未提供正式 Logo 或成套品牌图形，因此封面保持纯文字，不制造替代标识。报告不依赖产品截图，因为关键事实来自源码、PTY transcript 和状态转换；引用截图反而会弱化规则层比较。无意外偏离 Kami 设计系统。
