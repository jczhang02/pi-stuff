# 通过套件负责的 UI 呈现诊断信息

## 背景

Pi Stuff 在 Pi 的终端渲染器中运行。把维护警告直接写入 stdout 或 stderr 会绕过该渲染器，可能把文本插入编辑区，并让内部维护信息获得与用户工作相同的视觉权重。

## 决策

能力模块应向 `conversation-ui` 报告结构化诊断记录，而不是使用宿主侧控制台输出。

呈现方式服从所有权。能力的正常状态留在其现有界面上，例如 Fleetview、后台工作、Todo 或工具结果。无需用户操作的清理和重试信息在主 UI 中保持静默，但可在有界、仅限当前进程的 `/diagnostics` 历史中查看。需要用户处理的失败可在编辑器上方显示一条去重提示。该提示不抢占焦点，在确认后或下一条提示词开始时清除，并指向 `/diagnostics`。详情视图复用现有全宽、非浮动命令对话框。

诊断记录只属于显示状态。它们不会追加到会话历史、发送给模型、复制到状态栏，也不会持久化到独立数据库或日志。详情有界，终端控制字符会被移除，常见凭据形式会被遮盖。具有相同能力、键和严重程度的重复报告会合并，同时保留次数和最新详情。

浏览器负责的控制台和脱离宿主的子进程日志是明确例外，因为它们不会写入 Pi 宿主 TUI。仓库安全检查会拒绝狭窄许可列表之外的任何新增宿主侧控制台调用。

### `/diagnostics` 可读性

2026-08-17 接受的可读性更新只改变现有的当前进程命令对话框。记录所有权、提示确认、去重、边界、遮盖、非持久化，以及与会话、模型上下文、对话记录和状态栏的隔离都保持不变。`/diagnostics` 采用顺序的列表/详情流程，并在所有终端宽度下保持单列；该故障排查路径绝不引入分栏。

列表的首要信息是发生了什么。能力是来源，不是标题。紧凑行依次为 `›` 焦点标记、严重程度图标、能力、摘要、重复次数和最近时间：

```text
诊断 · 3 条记录

› × Agents          读取 Agent 对话记录失败           ×3 · 2 分钟
  ! 后台工作        无法确认进程所有权                     5 分钟
  i 上下文          已重试过期的派生状态刷新                  刚刚
```

信息、警告和错误分别使用 `i`、`!` 和 `×`。信息记录不得使用对话框生命周期中的 `●` 运行图标。`›` 始终只表示选择。窄宽度下，应先保留图标、能力和摘要的有效部分，再保留时间；如果记录经过了去重，应在时间之前保留重复次数。

记录按最近一次报告或更新时间倒序排列。更新会把去重记录移到最前，但不会改变当前焦点记录。列表超出可见窗口时，显示 `… N 条较新记录` 和 `… N 条较旧记录`。Pi 配置的上、下操作每次移动一条记录；Ctrl+P/Ctrl+N 是只读别名。PageUp/PageDown 与 `b`/Space 每次移动一页，Home/End 跳到第一条或最后一条。页面提示只在溢出时出现；`?` 打开上下文按键帮助。`c clear` 保持立即生效、只作用于当前进程的既有行为；该历史是有界、短暂的显示状态，而不是持久用户数据。

详情以能力作为面包屑，以摘要作为视觉锚点，并在标题元数据中使用完整严重程度文字：

```text
诊断 / Agents
× 错误 · 发生 3 次 · 最近一次在 2 分钟前

读取 Agent 对话记录失败

◆ 操作
会话文件恢复可读后，再次运行 /agents。

◆ 详情
……最新且经过边界限制与遮盖的诊断详情……
```

没有记录用户操作时省略“操作”。“详情”显示最新的有界记录内容；若不存在，则显示“未记录其他详情。”，不得编造解释。紧凑的 `◆` 只出现在小节标题。PageUp/PageDown 与 `b`/Space 按页滚动；Up/Down 与 Ctrl+P/Ctrl+N 每次滚动一行；Home/End 跳到顶部或底部。选中去重记录发生实时更新时，应刷新次数、时间、操作和最新详情，不得把用户移到其他记录，也不得重置仍然有效的阅读位置。

在高度很小时，应优先保留标题、严重程度与摘要、选中行或第一行详情，以及 Escape 退出路径；时间、次数、可选操作和周边记录优先级更低。为了视觉简洁，也绝不能削弱清理、凭据遮盖、记录与详情边界和观察者隔离。

实现现在使用 `i` 表示信息严重程度，优先显示问题摘要，提供列表溢出提示和分页导航，删除通用的“严重程度/发生时间/摘要”详情行，并渲染 `◆` 小节。聚焦测试覆盖单列约定、状态图标、更新时选择稳定、详情边界、分页别名和低高度适配；真实 PTY 验证器覆盖宿主渲染。

## 后果

- 内部恢复警告不再以原始文本出现在编辑器中。
- 除非问题需要用户操作，主对话保持安静。
- `/diagnostics` 提供一个可预期的位置，用于查看近期套件失败，而不改变模型上下文。
- 宿主重启会有意清除诊断历史；持久运行状态仍由各能力负责。
- 能力和诊断观察者的呈现失败不能升级为宿主失败。
