# 负责上下文命令界面

## 背景

Magic Context 提供若干命令和呈现钩子，但直接安装它们会在套件内部产生相互竞争的命令、对话框、组件、状态栏和对话记录权威。

## 决策

Pi Stuff 只暴露一个宿主命令 `/ctx`，用于检查和维护 Magic Context。它的 `status`、`flush`、`wrapup`、`recomp` 和 `upgrade` 子命令，与 Pi Stuff 全宽上下文命令对话框中的操作共用一个分派器。上游命令处理器仍负责校验、确认、存储、Historian 工作和结果，但它们的五个扁平命令注册只作为私有适配器输入，而不是宿主命令。

呈现属于 Pi Stuff。状态使用共享命令对话框。维护工作使用持久化但对模型不可见的上下文活动条目，以一行项目符号和有界展开详情渲染。Magic Context 的标题、页脚、组件、状态栏、自定义对话框、快捷键、标志和条目渲染器注册全部保持禁用。上下文维护不占用状态栏位置。

### `/ctx` 可读性

2026-08-17 接受的可读性更新只改变套件负责的上下文命令对话框呈现。分派器、上游校验、存储、确认权威、Historian 工作、上下文活动、带类型子命令，以及对上游 UI 的禁用均保持不变。`/ctx` 在所有终端宽度下都保持单列。

概览必须依次回答三个问题：当前模型上下文有多满、哪些上下文状态需要注意，以及现在有哪些维护操作有用。上下文使用量仍是标题的首要值。正文使用紧凑的 `◆` 小节标记，而不是三行无标签的密集状态：

```text
上下文
72.4% · 145K / 200K tokens

◆ 概览
8 个区间 · 已压缩历史约 54K tokens
3 条记忆 · 2 条笔记
Historian 空闲 · 缓存剩余 12 分钟
12 个活跃标签 · 4 个已丢弃标签

◆ 注意
! 2 项待处理丢弃 · 删除正在等待应用

◆ 操作
› 收尾历史
  完整保留近期消息，并压缩较早历史
  应用 2 项待处理丢弃
  重建区间
```

区间（Compartment）是压缩后的派生对话历史。Historian 是创建或重建该派生历史的上下文 Worker。待处理丢弃是已经排队但尚未应用的删除。保留这些规范术语，但要在可见文案中解释，不能假设用户了解上游词汇。

没有待处理工作或错误时，省略“注意”。活跃的 Historian 工作、待处理工作或警告、上下文错误分别使用 `●`、`!` 和 `×`；状态文字必须保留，使图标和颜色绝不是唯一证据。错误显示在待处理工作之前。在高度很小时，应优先保留标题使用量、第一项错误或警告、选中操作和 Escape 退出路径；次要计数、标签、缓存详情和描述优先级更低。

“收尾历史”始终存在。只有正数的待处理数量使它有用时，才显示“应用待处理丢弃”。需要升级，或状态无法安全判断时，显示“升级旧版数据”；已知会话已是当前版本时，省略无操作行。“重建区间”继续作为显式修复操作。即使对话框省略了无操作行，带类型的 `flush` 和 `upgrade` 子命令仍然可用。

选择使用 Pi 原生的 `›` 语法和上、下行为。窄宽度下，操作标签优先于描述保持可见。有空间时，一行描述可以换行；在选中标签或页脚之前，描述应先消失。实时状态刷新保留选中操作，绝不因为可选操作出现或消失而移动焦点。

收尾界面用直白文字说明：近期消息会完整保留，较早消息会变为紧凑区间。推荐选项保留最近 20 条消息；自定义输入接受一个正整数。重建范围可选整个符合条件的会话，或一个包含两端的消息范围。输入错误显示在输入旁边，并保留用户输入的文字。

重建确认是该流程唯一的警告界面：

```text
上下文 / 确认重建

! 重建整个符合条件的会话？
区间和事实数据将重新生成，并可能消耗模型 token。
原始 Pi 对话会被保留。

› 取消
  立即重建
```

初始选择仍是取消。Escape 恰好返回上一层界面。清理、收尾、重建和升级仍会先关闭对话框，再由共享分派器开始工作；进度和完成状态继续通过一个持久化、对模型不可见的上下文活动呈现，而不是第二个模态框或状态栏项。

实现现在会为概览加标签，使用图标加文字显示状态，解释上下文术语，隐藏已知无操作的清理与升级操作，标示警告确认，并在窄宽度下让描述为主要标签让位。聚焦测试覆盖操作可见性、选择保留、校验、安全的重建默认值、分页别名和低高度适配；真实 PTY 验证器覆盖宿主渲染。

## 后果

- 用户可以从一个命令发现上下文，并在不了解上游语法的情况下完成参数输入和破坏性操作确认。
- 带类型子命令和对话框操作不会漂移成不同执行路径。
- 上下文活动可跨会话恢复，同时不会进入模型上下文，也不会伪装成工具调用。
- 升级上游 Magic Context 时，必须保持适配器的命令和状态条目约定，或显式更新该边界；不能悄悄添加第二套全局 UI。
