# 结束 v1 Agent 调度器的实时共存

## 背景

当前 Pi Stuff 版本不会在整个 Pi 会话生命周期内持有 v2 之前 Agent 调度器的 `mkdir` 目录锁。它们可以读取一次未锁定的 v1 账本，并把经过证明的历史记录导入 v2 账本。如果读取时存在 v1 锁，Agent 启动会安全关闭，并提示用户关闭较旧的 Pi 进程。

旧协议无法同时提供新旧进程的实时互斥，以及新进程被终止后的自动恢复：旧写入方不参与 v2 内核锁，而为它们创建的目录会在进程退出后继续存在。基于 PID 的删除会增加“检查后删除再被替换”的竞态。因此保留生命周期屏障会让普通崩溃永久禁用该会话的委派功能。

## 决策

不支持 v2 之前与当前 Agent 调度器在同一个 Pi 会话中并发运行。当前版本可以导入一次未锁定的 v1 账本。如果存在 v1 锁，Agent 启动会安全关闭并提示用户停止较旧的 Pi 进程；当前代码不会创建新的 v1 生命周期屏障。

## 后果

- v2 调度器仍是唯一的当前执行权威，并保留其进程退出安全、稳定 inode 的内核声明。
- 已锁定的 v1 账本保持安全关闭，绝不会被自动回收。只有当进程代际元数据明确证明所有者已经消失时，才会回收由紧邻的前一版当前版本兼容代码写入的陈旧屏障；当前恢复竞争者通过 v2 内核声明串行化。
- 不支持针对同一 Pi 会话同时运行 v2 之前和当前 Pi Stuff 进程；使用当前版本启动 Agent 前，应先结束旧进程。
- 没有 v1 账本时，兼容启动不会创建目录或锁，因此终止当前 Pi 进程不会留下新的升级前屏障。
