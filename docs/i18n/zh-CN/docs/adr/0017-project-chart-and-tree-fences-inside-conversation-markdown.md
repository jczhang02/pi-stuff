# 在对话 Markdown 中投影 chart 和 tree 围栏

## 背景

图表和树形输出在终端对话中很有用，但显示投影不能重写规范消息、改变 Provider 上下文，也不能引入第二套 Markdown 权威和运行时。

## 决策

Pi Stuff 会在现有对话 Markdown 投影接缝识别完整的 `chart` 和 `tree` 围栏代码块。有效代码块会被替换为受宽度限制的终端文字用于显示，而规范的用户或 Assistant 消息、会话记录、复制/导出源码和 Provider 上下文保持不变。Thinking 继续由实时思考负责，绝不进入该可视化路径。

分派器是对话 UI 内部的静态实现。它在该模块唯一注册的宿主 Markdown 转换器中运行；不存在第二个转换器、插件注册表、设置、能力、软件包或运行时依赖。Assistant 候选识别被融合进现有保留分块的清理遍历；用户 Markdown 使用精确的开围栏预过滤。只有检测到目标围栏候选后，才同步延迟加载固定且由仓库负责的投影器模块；所属转换器注入 Pi TUI 的列宽测量，使这些模块不含宿主导入。因此，普通启动和普通消息绝不会加载或进入可视化解析。只有闭合围栏、语法、安全检查、限制和可用终端宽度全部满足时，匹配代码块才会投影。每条 Markdown 消息最多投影 16 个有效代码块。否则逐字节返回原围栏。

`chart` 接受 `bar`/`histogram`、`line`、`scatter`、`sparkline` 和 `heatmap`。其经过改编的 MIT 实现已固定版本，并在源码旁记录。输入最多 12,000 个字符和 64 个普通数据点；热力图最多 32 行、64 列。图表至少需要 24 个内容单元，最多使用 80 个；宿主代码缩进还需要两个额外可用单元。`tree` 恰好接受一个根节点和每层两个空格，拒绝制表符、奇数缩进、层级跳跃、空行和多个根节点；上限为 12,000 个字符、256 个节点和 32 层。树标签绝不截断：任一输出行无法容纳时，保留源码围栏可见。

投影为每个可视化输出一个内部 Markdown 代码块，而不是每行输出一个行内节点。现有 Markdown 主题上的作用域适配器只把该合成代码块的上边框替换为第一行内容，并抑制下边框，之后立即恢复普通代码块渲染。这样可保持输出无边框且惰性，同时避免投影内容含 ANSI 或终端控制序列。Pi TUI 的终端列宽测量和字素边界覆盖中文、日文、韩文与 emoji。渲染会为宿主代码块保留两个单元的内容缩进；Assistant 投影还会保留现有外层 `• ` 标记宽度。

## 被拒绝的替代方案

- 第二个 Markdown 转换器会拆分对话显示权威，并增加另一次完整消息遍历。
- 独立安装的图表软件包或运行时依赖会违反单软件包架构，并为一个小型有界渲染器增加启动和导入工作。
- 通用围栏块注册表、设置或动态插件会增加两个已接受语言无法支撑的产品和生命周期表面。
- 每行输出一个 Markdown 代码 span 或硬换行节点可保留无边框外观，但会让最大规模树渲染在宿主中扩展不佳。普通代码块效率高，却显示可见边框。作用域合成边框适配器保留高效块 token，同时去掉边框。
- 用 Provider 指令鼓励图表/树形输出，会为每个请求增加 token 与延迟，包括从不使用该功能的请求。
- 在持久化或分派前重写消息，会为显示问题破坏规范会话与 Provider 内容。

## 后果

- 模型和用户只有编写显式且完整的围栏时才选择加入；不增加提示词注入。
- 无效、不安全、不受支持、不完整、超限或过窄的输入仍作为普通围栏代码显示。
- 普通路径与功能路径分别进行基准测试。基线/候选门槛使用交错样本、配对 Bootstrap 置信区间；当配对中位数比值的 95% 区间在较慢一侧排除 1 时，再运行一次独立确认。可重复的普通路径回归会阻止交付。
- 修改格式、限制、受支持图表类型、投影所有权或性能验收时，必须同时更新本 ADR 与对话 UI 文档。
