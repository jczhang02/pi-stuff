# Pi 版本支持

[English](../../pi-version-support.md) · 英文为准.

维护范围为 Linux 上的 Bun 编译版 Pi `0.85.1` 至 `0.87.1`. 新稳定版默认允许尝试, 不设置版本上限阻断; 验收前仍属于适配目标. [#113](https://github.com/jczhang02/pi-stuff/issues/113) 保存已确认政策及实施要求.

## 当前证据

产品修订 `8c474dc` 于 2026-09-23 使用下列官方 Linux x64 二进制进行验证. 每个样本均通过完整离线套件, 覆盖网页访问、RTK 和主题, 使用不含开发依赖和已安装宿主 peer 的隔离生产副本. Pi 和内嵌 Bun 版本由宿主自身报告. 测试及开发工具由 Bun `1.4.0` 运行, 它不会替换编译版 Pi 内嵌的运行时.

| 直接验收 Pi | 内嵌 Bun | 指定 API 类型检查 | 完整离线套件 |
| ----------- | -------- | ----------------- | ------------ |
| `0.85.1`    | `1.3.14` | 通过              | 通过         |
| `0.86.1`    | `1.3.14` | 通过              | 通过         |
| `0.87.1`    | `1.3.14` | 通过              | 通过         |

维护者使用 Bun `1.4.0` 编译的 Pi `0.87.1` 另通过宿主身份和最终结果测试; 这是定向检查, 不是另一轮完整套件. 较早的 `bb03c4e` 记录针对维护者的 Pi `0.85.1`/Bun `1.4.0` 环境. 两组记录都不认证 Node 宿主、macOS、Windows 或其他架构.

首轮完整运行发现运行时差异: 官方二进制的 `node:util` ANSI 清理会吞掉孤立 ESC 后的普通文本. 最终工具结果现使用 `src/rtk/register.ts` 中固定的 Node 兼容 ANSI 规则, 保留上游 MIT 声明. 相同回归断言随后通过, 正文、图片块、错误、元数据和 usage 保持完整. 无需增加 Pi API 兼容分支或提高最低版本.

另在三个指定宿主中验证了原生 RTK `0.45.0`. 使用临时仓库、显式可执行路径和私有 RTK 数据库, 执行 `git status`, 观察送往模型的压缩输出, 打开全部六个 Usage 视图, 再调整到 56x26 和 45x20, 均通过. 这些检查不重验 mise 发现, 也不认证其他 RTK 版本; 确定性 fixture 单独覆盖发现及失败路径.

## 维护决定

声明范围内的所有中间版本仍属于维护对象. 抽样测试不意味着只支持样本. 中间版本的故障需要修复或明确记录例外; 仅要求报告者升级不能解除维护承诺. 当前验收区间没有已知的版本专属例外.

最低版本允许提高. 提高前说明具体 API 或功能需求、保留兼容的成本及受影响版本, 再由维护者确认. 不要求证明兼容绝对做不到. 版本较老本身不足以成为停止支持的理由.

[术语表](CONTEXT.md#术语)区分适配目标、维护范围和直接验收版本. 新稳定版进入适配目标, 在声明环境中验收后再扩大正式支持范围.

## 包声明

遵循 [Pi 官方包规范](https://pi.dev/docs/latest/packages#declare-dependencies), 导入的宿主包使用通配 peer: `pi-ai`、`pi-coding-agent`、`pi-tui` 和 `typebox`. 开发 Pi 包固定为 `0.87.1`, TypeBox 为 `1.3.27`, 提交 Bun lockfile. `pi-agent-core` 是测试 fixture 的开发依赖. 运行时库仍为普通依赖.

通配 peer 允许尝试新版宿主, 不等于验收证据. 常规开发安装仍为 `bun install --frozen-lockfile --ignore-scripts`. 干净包验收将未修改的入口、源码、主题、manifest 和 lockfile 复制到临时目录, 再使用 `--frozen-lockfile --production --omit peer --ignore-scripts` 安装.

## 验收样本与 CI

选取精确最低版本, 加上拟议区间内每个覆盖 minor 的最新 patch, 去掉重复样本. 当前为 `0.85.1`、`0.86.1` 和 `0.87.1`. 历史 patch 仍被维护, 不声称逐一运行过所有版本.

[CI](../../../.github/workflows/ci.yml) 明确列出样本, 固定官方发行归档的 SHA-256 摘要. 每个作业安装指定 Pi API 包及匹配的 TypeBox 进行类型检查, 再用指定编译宿主和干净包运行完整套件. `quality` 作业检查冻结的开发依赖图. 原有必需 `checks` 作业仅在 quality 和全部兼容样本成功时通过; 失败、缺少宿主、取消或跳过依赖作业都不能产生通过的门禁. 没有引入定时升级或新增权限.

本地指定宿主运行使用与 CI 一致的 Bun 和依赖:

```bash
PI_TEST_HOST=/absolute/path/to/pi \
PI_TEST_VERSION=0.86.1 \
PI_TEST_PACKAGE=/absolute/path/to/production-copy \
bun run test
```

`PI_TEST_VERSION` 核对实际执行的宿主, 不只检查已安装的开发包. 版本不匹配或可执行文件缺失会失败. 不设置覆盖时, 测试通过测试运行器启动固定版本 Pi CLI 并加载检出目录. 隔离与覆盖范围见[质量保证](quality-assurance.md#终端-e2e).

扩大区间前, 更新样本、检查相关 API 变化、运行必需检查、记录产品修订及实际运行时, 并完成审查. 样本失败时保留旧声明. 离线验收不包含真实账号 provider 认证. [#106](https://github.com/jczhang02/pi-stuff/issues/106) 等独立功能证据, 复用前须匹配修订、环境和行为范围.
