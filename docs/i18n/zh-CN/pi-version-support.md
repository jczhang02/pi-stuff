# Pi 版本支持

[English](../../pi-version-support.md) · 英文为准.

状态: [#113](https://github.com/jczhang02/pi-stuff/issues/113) 中的决定已逐项确认, 完整政策仍待最终确认. 本文不扩大当前已验证的运行环境声明.

## 当前证据

主分支修订 `bb03c4e` 声明并记录的环境是 Linux 上的 Bun 编译版 Pi `0.85.1`, Bun 为 `1.4.0`. 开发测试也会通过 Bun 启动已安装的 Pi CLI. 对该修订而言, 其他宿主版本和运行环境仍未验证. 见 [README](README.md#项目状态) 和[质量保证记录](quality-assurance.md#终端-e2e).

## 已确认决定

以 `0.85.1` 为最低适配目标, 持续跟进后续稳定版 Pi. 新版默认允许尝试使用并进入适配目标, 宿主验收通过后才成为正式支持版本. 宽泛的 peer dependency 声明不等于验收证据. [术语表](CONTEXT.md#术语)区分适配目标、支持范围和已验收版本.

声明的支持范围内, 所有中间版本仍属于维护对象. 仅测试两端不意味着只支持两个端点. 中间版本的故障需要修复或明确记录例外; 仅要求报告者升级不能解除这项维护承诺.

最低版本允许提高. 提高前说明具体 API 或功能需求、保留兼容的成本以及受影响版本, 再由维护者确认. 不要求证明兼容绝对做不到. 版本较老本身不足以成为停止支持的理由. 这意味着不永久承诺维护旧版, 而是在维护成本或宿主能力变化时明确作出决定.

## 包声明方向

拟议实施遵循 [Pi 官方包规范](https://pi.dev/docs/latest/packages#declare-dependencies): 导入的宿主提供 Pi 包使用通配 peer, 开发依赖仍固定精确版本以保证可复现. 支持政策和宿主证据单独界定维护范围. 依赖和 CI 改动等待完整方案确认.

## 验收样本

固定最低版本, 再选取每个覆盖的 minor 分支在拟议区间内的最新 patch, 重复样本只测一次. 若目标上限为 `0.87.1`, 初始样本为 `0.85.1`、`0.86.1` 和 `0.87.1`. 该抽样政策已确认, 本文档任务尚未执行这些新增宿主验收. 历史 patch 仍属于维护承诺, 但不要求逐个版本重跑.

扩大支持上限前, 在声明的运行环境中完成扩大后区间所选样本的验收. 单独记录直接验收版本和支持区间, 不把抽样描述成逐一测试过所有历史 patch.

## 证据边界

Pi [0.86.0](https://github.com/earendil-works/pi/releases/tag/v0.86.0) 和 [0.87.0](https://github.com/earendil-works/pi/releases/tag/v0.87.0) 均记录了破坏性 API 变更. 这说明需要检查 Pi Stuff 使用的接口, 不代表已经证明 Pi Stuff 在这些版本上故障. [#106](https://github.com/jczhang02/pi-stuff/issues/106) 等其他功能任务的证据, 复用前须核对修订、环境和行为范围.
