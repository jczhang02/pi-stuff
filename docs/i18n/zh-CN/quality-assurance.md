# 质量保证

[English](../../quality-assurance.md) · 英文版本为规范依据.

本文为 Pi Stuff 的变更定义证据要求. 这是按风险选择证据的指南, 不是配额: 变更不必为了填满分类而覆盖每个级别或新增 CI 任务. 简要写明行为和验收承诺, 复用对同一修订仍有效的证据, 只为重要的未覆盖行为或回归添加测试. 不添加占位测试、覆盖率目标、镜像实现的测试、为流程凑数的工具或已退役的治理套件.

## 四类 QA 活动

根据变更提出的问题选择活动:

| 活动     | 提供的证据                                                                             | 默认用法                                                                                                                            |
| -------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 静态检查 | 不运行产品行为, 检查源码与配置是否符合适用的语法、类型、lint 和格式规则.               | 每个 PR 运行 `bun run check`. 实现产品测试套件及其 CI 时, 在现有 `checks` 任务内增加固定版本的 `actionlint` 步骤; 本次基线暂不接入. |
| 测试     | 在明确边界上验证行为得到所需结果, 并在相关时覆盖失败、取消、恢复、清理及输入/数据处理. | PR 运行适用的离线套件; 共享基础设施、Pi 升级或影响不明确时运行完整的适用离线套件.                                                   |
| 基准测试 | 在给定环境和工作负载下测量任务效果、耗时或资源使用的差异.                              | 独立按需运行, 不作为例行合并门槛. 明确的产品性能要求属于测试, 可以阻塞验收.                                                         |
| 审查     | 同行检查需求、风险、设计、证据和可维护性.                                              | 审查是横跨所有测试级别的同行活动, 不是额外的测试级别.                                                                               |

当前仓库没有自有产品测试, 也没有 `test` 脚本. 等可执行行为出现后再确定分类和命令; 本文现在不新增测试入口.

## 测试级别

按验证的边界和目的分类, 不按进程数量、mock 或工具名称分类. 实际引入测试时, 按这些级别及所验证的能力组织测试; 不要求占位目录结构.

- **单元测试**：隔离验证一个纯函数或小模块. 例如, 解析器在不访问 Pi、文件系统或进程的情况下, 将合法和非法配置映射为规定结果.
- **组件集成测试**：通过真实模块接口验证一个 feature 拥有者及其直接协作者. 例如, feature 使用本地确定性适配器组装命令, 并保留适配器的类型化失败.
- **系统测试**：通过公开行为或宿主界面验证整个包或能力集合. 例如, Pi 加载扩展, 命令解析输入并应用 feature, 在隔离设置下呈现预期输出.
- **系统集成测试**：验证包与外部系统、服务、运行时或工具的交互. 例如, 扩展启动真实本地工具或调用受控 HTTP 服务, 处理响应并在失败时释放资源.
- **验收测试**：在实际支持的宿主和环境验证用户或维护者承诺. 例如, 扩展由维护者的 Bun 编译版 Pi 宿主加载并完成约定工作流, 记录测试所用的 Pi 和 Bun 版本.

默认使用离线、隔离的临时设置、目录和会话. 问题需要时使用确定性 provider 和本地外部 fixture. 真实在线账号或模型须单独选择并明确记录. 缺少必需环境时结果为未验证或失败, 不能因省略而通过. 使用 fixture provider 的真实 Pi 离线运行, 可以通过 RPC 或 PTY 提供端到端或验收证据; 工具不决定测试级别, 真实在线模型也不是普遍要求.

## 终端 E2E

终端 E2E 使用 `tuistory` 驱动终端, 使用 Bun test 运行测试. 开发依赖版本固定在 `package.json`. 编程测试使用其 `launchTerminal` API; 交互式检查通过 `bun run tui` 使用 CLI. 使用前阅读 [tuistory skill](../../../.agents/skills/tuistory/SKILL.md). 运行 `bun run tui --help` 查看 CLI 参考, API 细节以已安装包的文档和类型声明为准. 只有本地资料无法回答当前问题时才查阅匹配的上游文档, 并复用已经有效的上下文而不是重复查询. 使用仓库依赖, 不调用全局安装或临时拉取的版本.

测试聚焦自有的用户可见行为:

- 为每个测试隔离工作目录、设置目录和会话目录. 对 Pi 设置 `PI_CODING_AGENT_DIR`, 关闭无关扩展、skill 及其他自动加载资源. 同时控制测试运行器的环境: 子进程选项可能继承或合并父进程变量.
- 在明确超时内等待特征状态. tuistory 0.11.0 的 `text()` 和 `waitForText()` 包含滚动历史, 匹配可能来自旧输出. 断言可见画面时, 使用 `text({waitFor, timeout})` 的条件回调读取 `getTerminalData()`, 取 `lines` 的最后 `rows` 行, 拼接每行各 span 的文本. 检查完整的相关文本, 包括出现的中文和 emoji, 并为每个操作检查不同的结果. 布局属于要求时, 在对应界面打开期间调整终端尺寸.
- 在 teardown 中停止测试自己启动的进程, 限时等待退出, 并始终关闭终端; 断言或等待退出失败时也要清理. 失败时保留有用的屏幕输出, 让非预期失败传递给测试运行器. 不关闭其他 session 共享的 CLI 终端.
- 只添加实际用例需要的初始化与生命周期辅助函数. 复用框架的输入、画面读取和等待 API, 不另建终端测试封装层.

首个可执行 feature 应按下方执行策略引入适用测试和 CI 入口. 当前没有产品套件或可包装的开发服务器; 等真实的长驻开发命令出现后, 再应用 skill 的开发服务器设置.

[选型试验](https://github.com/jczhang02/pi-stuff/issues/29) 在 Linux、Bun 1.4.0 和真实 Pi 0.85.1 中使用临时对话框扩展. Tuistory 0.11.0 通过了完整中文/emoji 文本、选择、Escape 取消、对话框打开时调整尺寸, 以及预期的缺失文本超时检查. 对照的 `@microsoft/tui-test@0.1.0-beta.3` locator 对屏幕转储中可见的文本等待超时, 原因未诊断. 这些结果支持工具选型. 产品验收、托管 CI、其他操作系统和真实模型流程仍未验证.

## 执行策略

让 PR 证据保持小而相关. 小型套件可以完整运行. 只有测得成本或范围证据支持时才选择性执行或分片, 不要臆测引入. 套件存在后提供由真实套件支持的手动完整入口. 只有实际成本或选择性 PR 运行足以说明需要时才增加定时或 nightly 运行; 本基线不引入自动调度器.

变更触及恢复、取消、资源清理或输入/数据边界时, 保留相应检查. 在 PR 证据中记录适用的活动、级别、环境、命令或手动步骤、结果及未验证要求. 必需验证失败或未完成会阻塞验收. 修订、环境或行为变化后, 重新判断旧证据是否适用; 仅在这些变化、失败或未解决疑点需要时重跑检查.
