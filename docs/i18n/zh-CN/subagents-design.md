## 已确认决策

- 基于 @arhen/pi-core-subagent fork 和重写. UI 独立设计, 不采用上游 UI 方案.
- 按核心行为, UI 场景与原型, 实现接口与结构的顺序推进. UI 探索发现问题时可以重新讨论核心行为.
- 能力逐项确认. 工具名, 参数和配置可以重设计, 本次设计不以兼容上游接口为约束.
- 最终支持的每项功能均须在真实使用场景中验收. 并行, 串行及其他支持的执行方式各自需要验收覆盖, 一个主要场景不能替代全部功能验收.

## 任务与上下文规则

- **Q14, 身份与任务历史:** 多次交办保留子代理逻辑身份和可恢复对话历史, 活跃 SDK 运行对象可以卸载后重建, 临时工具缓存不因此自动持久化. 每项任务独立保存记录, 交办结果声明和固定成果引用. 被委派任务记录创建它的父任务. 已保留代理接到新交办, 不会重新打开早已结束的父任务. 续聊不覆盖旧结果或自动重跑其使用者.
- **Q15, 递归限制:** 根任务树共享执行并发, 累计接受任务数和最大委派深度. 三者分别计数: 等待可以释放执行名额, 但不删除任务历史, 重置深度或返还累计额度. 上下文驻留内存不等于正在执行. 派发边界见 Q24, 初始试用数值见 Q26.
- **Q16, 完成:** 本次任务委派的下级仍在执行或等待执行时, 父任务不能完成. 生命周期沿任务归属计算, 不包含保留下来的下级代理日后收到的所有交办. 后端负责人等待自己派出的数据库工作; 主代理以后再交办数据库代理时, 旧负责人任务不会重新变成未完成. 失败与最终交付见 Q23, Q55.
- **Q17, 取消:** 取消一个任务时取消其全部下级分支, 阻止新的下级启动, 保留已有记录和代码成果供检查. 取消后端负责人也会停止数据库和 API 下级.
- **Q18, 工具与权限范围:** 下级工具范围和实际执行权限不能超过适用的父级上限, 角色与调用只能收窄. 工具名白名单控制暴露入口, 不等于文件, 网络或进程沙箱. 只读研究员应请有权限的上级安排写任务; 复制历史不授予工具权限.
- **Q19, 历史快照:** 在合法会话分叉边界复制父代理可见历史, 保留已完成消息, 工具结果和已有压缩摘要. 处理尚未配对的工具调用, 保证子会话收到合法的调用与结果组合; 如生成分叉控制记录, 必须标明用途, 不能假称工具已执行. 后续父消息显式传递. 历史复制不复制活跃工具句柄, 权限授予或工作区状态.

## 调度, 失败与恢复规则

- **Q20, 忙碌时续聊:** 向忙碌子代理交办的新任务进入队列, 同一子代理一次执行一个任务. 审查员完成登录审查后才开始排队的支付审查; 修正当前审查则使用 steering.
- **Q21, 等待与并发:** 显式等待下级或答复时, 仅在本任务没有模型请求或其他工具仍在执行后释放名额. 恢复时通过队列重新取得名额. 身份, 收件箱, 归属和累计计数继续保留. 等待下级的负责人不能阻塞下级启动; 同时仍在运行的测试工具会阻止过早释放名额.
- **Q22, 依赖失败:** 依赖已收尾却未产生可放行的完成结果时, 阻止其使用者启动, 无关分支继续. 包括执行失败, 取消, 声明无法完成或缺少完成声明. 尚未启动的使用者按 Q32 跳过, 已被直接取消者仍算取消. 明确报告原因, 不让它们无限等待.
- **Q23, 下级失败:** 将下级失败报告给直接父代理, 允许父代理重新委派或自行完成工作, 保留下级失败记录. 一个下级失败不立即取消整棵树, 也不自动判定父任务失败; 父代理可以补救后完成交办.
- **Q24, 跨派发额度:** 同一主会话全部派发共享执行并发, 每次顶层派发及其下级各有累计任务额度. 给该派发保留代理的续聊继续计入原派发, 换一次工具调用不会重置额度. 另建顶层派发有独立累计额度, 仍不能绕过主会话并发限制. 主会话拥有顶层后台派发, 结束一轮回复无需汇合它们. 下级的后台标志只改变是否等待, 不改变父任务归属或下级汇合与取消规则.
- **Q25, 重启恢复:** 重新打开父会话时恢复子代理上下文和任务记录. 重开不授予重复执行权, 也不能把仍在执行的工作覆盖为中断. 多个本地实例仍须保持同代理串行, 主会话共享并发和原派发累计数. 接管前按 Q57 核实已有执行权限归属和未知活动, 不预选某种锁或协调器. 核实后将未完成任务标为中断, 由主代理或用户显式继续. 已完成子代理可以续聊, 已执行过的写操作不自动重放.

## 限制, 依赖调度与代码交接

- **Q26, 可配置试用默认值:** 主会话八个执行名额, 每次顶层派发累计六十四项已接受任务, 委派深度三层且主代理为零层, 作为可配置的初始试用值. 初始交办, 递归和续聊均计数, Pi 提供方请求重试不另建任务. 这些数值未经性能验证. 场景验收须用更小配置检查边界并记录资源消耗, 才能评估默认值是否合适.
- **Q27, 执行计时:** 任务执行时限累计模型和工具执行阶段的时间, 排除排队及显式等待下级或答复的时间. 等待答复另设超时. 研究员等候答复半小时, 不消耗半小时的执行时间.
- **Q28, 就绪任务调度:** 任务自身依赖满足且有执行名额即可启动, 不等待同批无关任务. API 调查三十秒后结束即可开始 API 实现, 五分钟的数据库调查可以同时继续.
- **Q29, 依赖补救:** 修复失败任务后保留原图及失败记录, 主代理显式派发后续工作并引用新结果. 替代调查成功时, 不自动重启旧图中已跳过的任务.
- **Q30, 写入隔离:** Git 中每个可写子代理默认拥有自己的 worktree, 多次交办在其中串行执行, 不同代理不共享可写副本. 创建 worktree 失败即启动失败, 不能退回原目录. 续聊与基线变更见 Q34.
- **Q31, 汇合代码:** 代码依赖引用保存的提交或其他固定成果, 不引用会移动的分支头. 单份上游成果可以直接继承; 多份写入成果须显式安排整合任务合并并解决冲突, 后续读取其固定成果. 上游续聊推进分支不能改变已接受的下游输入.

## 任务结果, 工作区与消息范围

- **Q32, 跳过的任务:** 依赖已经收尾但没有可放行的完成结果, 导致任务无法启动时, 该任务以跳过结束, 保留依赖与原因. 直接取消仍算取消, 不混作跳过. A 在 B 启动前声明无法完成时, B 有明确终态, 父任务不会无限等待.
- **Q33, 初始基线:** 隔离初始基线纳入已跟踪的未提交修改, 未跟踪文件仅显式选入. 原工作目录及暂存区保持原样. 捕获过程中源代码变化时, 检测并重试或报告失败, 不能默默拼接不同版本. 子代理因此能使用父代理刚改好的接口, 无须父代理先提交.
- **Q34, 续聊工作区:** 写任务续聊默认复用子代理保留的 worktree, 记录实际起始基线. 分支继续推进时, 旧结果的提交和差异引用仍保持固定. 改用其他基线由调用方明确选择, 执行前准备工作区并重新绑定会话资源. 不得默默重置部分成果或继续使用绑定旧目录的工具.
- **Q35, 代码交付:** 将任务范围内应交付的代码保存到自己的分支, 返回固定提交和差异引用及检查证据. 保存代码与声明完成交办分别记录. 保存失败时保留并报告未保存成果. 主代理明确决定是否应用; 工作代理不能提交无关文件, 也不能把分支名当作固定交付.
- **Q36, 清理:** 保留子代理工作区供续聊使用. 工作区被明确释放后, 仅在执行已停止且不可重建内容已经保存或明确处理时自动回收. 检查已跟踪, 未跟踪及忽略内容, 只有干净提交还不够. 结果引用和会话记录保留到显式清理. 内容未保存或情况不明时拒绝移除并报告.
- **Q37, 非 Git 写入:** 允许调用方显式选择直接写入指定的非 Git 目录, 例如普通文档文件夹. 无隔离写入不是默认行为.
- **Q38, 消息范围:** 同次顶层派发中的代理可通过已知 ID 互通消息, 包括不同委派层级. 向上提问默认找直接父代理, 不同派发之间由主代理转交. 数据库代理可直接把字段约定发给同次派发的 API 代理.

## 消息投递, 配置与扩展状态

- **Q39, 普通消息:** 保存消息及目标代理和任务关联, 在下一次模型处理前投递, 不打断正在执行的工具. 已接收不代表模型已经处理. 发给已结束任务的消息, 以及运行中接收但收尾时仍未消费的消息, 均保留并以未消费状态通知主代理. 不自动开始新交办, 转入另一任务或改写旧结果.
- **Q40, 未答复的问题:** 等待答复默认十分钟, 可配置. 到期明确返回未收到答复, 子代理可以继续不依赖答案的工作, 或说明无法完成交办; 不猜测答案, 也不自动判定整个任务失败. 迟到的回复仍关联原问题, 不自动启动新任务.
- **Q41, 角色选择:** 派发者明确选择已发现的 Markdown 角色文件, 或临时定义角色; 未指定时使用通用角色. 保留角色文件和发现列表, 核心不根据文字相似度自动选择或切换角色. 审查任务提到数据库, 不会因此自动选择数据库实现角色.
- **Q42, 配置优先级:** 新建子代理时, 普通值依次采用调用, 角色, 项目, 用户和父级配置, 保存解析结果. 续聊默认使用该代理已保存配置, 仅显式覆盖受支持的值, 修改角色文件本身不改变它. 排队工作, 启动及每次新工具调用均受当前工具和权限上限约束, 保存配置不能绕过它. 有权限者显式收紧限制时, 请求取消仍在使用被撤销权限的在途工作; 停妥前遵循 Q47, 不能提前声称限制已停止该活动. 已产生的外部副作用不会因此撤销. 配置与权限变化记录见 Q51.
- **Q43, 依赖结果传递:** 默认传递上游最终报告及文件, 分支, 提交等成果引用, 不附带整个执行日志. 超过可配置长度时提供明确标注的截断预览和完整内容读取引用, 保留完整结果. 下游实现代理需要时可以读完研究员的长报告.
- **Q44, 记录恢复:** 持久化任务创建, 重要状态变化和结果, 关联会话及固定代码成果. 启动前保存任务创建与接纳记录, 包括归属, 配置和额度关联. 创建记录保存失败按 Q50 明确报告接纳或启动错误, 不能留下无记录的执行, 恢复时身份和计数必须一致. 宣布结果已可靠保存前, 先保证对应终态记录可读取. 恢复可用部分并报告缺失或损坏. 持久化失败是核心错误, 不能按可选监听器错误忽略; 不预选存储事务, 不承诺写操作恰好一次重放.
- **Q45, 扩展状态:** 显式选择扩展入口, 在子会话中独立初始化上下文与生命周期状态, 再仅暴露允许的工具. 加载一个入口可能初始化该扩展的其他工具或钩子, 工具白名单不能阻止这些副作用. 不复用父工具闭包或可变扩展 runtime. 支持某扩展须验证会话行为安全, 不可用或不安全入口明确失败. 独立调用 factory 不代表任意模块全局状态, 外部服务和子进程均已隔离.

## 执行控制与恢复边界

- **Q46, 执行超时:** 保留按 Q27 计时的可配置累计执行期限, 未显式配置时关闭该期限, 撤销未经验证的统一三十分钟截断. 配置期限到达后请求取消任务及下级, 保留成果并记录超时原因, 实际停止遵循 Q47, 不自动重跑. 各工具或提供方自身时限独立存在.
- **Q47, 正在取消:** 发出取消请求不代表已经停止执行. 工具仍在运行时保留正在取消状态, 活跃执行继续占用名额. 确认停止前不启动同一子代理的下一任务, 也不清理其工作区. 报告尚未停止的活动, 例如取消后仍在运行的测试进程. 将取消接纳与可靠终态提交排序: 取消先被接纳, 后来的完成声明不能放行使用者; 完成先可靠成立, 晚取消不能改写该结果. 查询, 通知与恢复必须呈现同一个权威终态.
- **Q48, 限时等待结果:** 主代理单次等待结果以六十秒为可配置试用值, 相关完成, 提问或失败事件提前唤醒. 到期只结束本次等待并返回当前信息, 不停止下级. 使用事件唤醒; 六十秒不是轮询周期, 也不要求状态未变化时反复唤醒模型.
- **Q49, 运行中补充指令:** 修改当前任务的 steering 在当前轮工具执行结束后, 下一次模型调用前优先处理. 不强制停止这些工具, 仍属于同一个任务. 将指令接纳与任务完成排序. steering 先被接纳, 就须在同一任务处理后再完成, 即使在途模型请求原本会直接结束而没有下一次调用. 任何已结束任务都拒绝 steering, 不区分结束原因; 任意终态先于指令接纳成立时, 明确拒绝并提示续聊. 取消或执行失败可能阻止消费, 此时保留指令与原任务关联并报告未处理. 不能静默丢弃或带入之后的交办.
- **Q50, 无效派发与接纳:** 检查已知图, 角色或工具, 深度与累计额度错误, 无效派发整体拒绝, 不创建任务或消耗额度. 已接受任务启动前一致地预留额度, 并发不足时有效工作排队. 接受后发生的 worktree 创建等错误记为已接受任务的启动失败, 不回滚已运行的无关工作. 整体校验不等于任意运行副作用都具有事务性.
- **Q51, 配置快照:** 每项已接受任务记录接纳时的完整实际配置. 新代理按 Q42 解析, 续聊以代理保存配置为基础, 加上显式受支持覆盖与适用上限. 把 reviewer 角色文件从模型 A 改为 B, 不能默默改变已保留 reviewer; 新建代理可以使用新定义. 排队或运行任务的变更需要显式受支持操作, 不靠热加载. 在接纳快照之外关联记录显式权限限制及其实际生效变化; 快照不能恢复已撤销授权, 也不能表明在途活动已经停止.
- **Q52, 只读代码视图:** Git 只读任务默认读取指定代码基线的独立快照, 读取实时工作区需要显式选择. 主代理并发修改时, 审查报告不能默默混入修改前后的不同代码状态.
- **Q53, 工作区缺失恢复:** 工作区缺失而保存的代码提交仍可用时, 重建该代码状态并重新绑定恢复的会话, 执行仍须显式继续. 提交无法恢复从未保存的未提交或忽略内容, 缺口须报告. 必需上下文或代码缺失时阻止恢复, 不能默默退回父目录或替换基线.
- **Q54, 事件监听失败:** 可选生命周期观察者失败时记录扩展错误, 不改变任务结果或阻塞调度. 必需的状态持久化和成果保存不属于可选观察者, 失败仍按 Q35, Q44 报告核心错误. 进度日志失败不能推翻已完成工作, 结果记录没存下来也不能宣称已保存.

## 最终交付, 会话生命周期与管理权限

- **Q55, 父代理最终报告:** 父任务汇合自己委派的下级. 报告时尚未处理下级结果, 则不占执行名额地等待, 再恢复同一任务纳入新结果后最终交付. 下级提问也须唤醒这种隐式等待: 父代理按 Q21 重新取得名额, 在同一任务内回答后继续汇合, 不把问题拖到下级等待答复超时. 已经显式等待并处理结果时, 不为重复总结强制增加模型轮次. 模型一轮正常结束不能绕过任务级汇合.
- **Q56, 异常后的排队任务:** 保留异常后暂停同一代理未被取消队列的保守规则, 其他代理不受影响. 这是明确的队列策略, 不代表所有先后交办都存在依赖. 有权限调用方可先明确安排补救任务, 再决定继续或取消被暂停工作. 收到普通消息不自动释放队列. 补救只能释放独立且未被取消的排队项, 被取消分支拥有的任务仍保持取消.
- **Q57, 主会话生命周期:** 真正切换 Pi 会话或正常退出成功之前, 先停止其子任务, 将未完成工作保存为中断以便显式恢复. 尚未停妥或保存完成时, 明确报告离开尚未成功, 受影响工作区不能用于冲突执行或清理. 慢停工具遵循 Q47, 保存失败遵循 Q44, 不规定固定强杀期限. 回复结束或 UI 焦点变化不算会话结束. 崩溃不能证明外部工作已停止, 在受影响工作区恢复前须报告并核实未知活动. 不隐含脱离主会话的跨会话执行.
- **Q58, 管理权限:** 主代理管理整棵任务树. 分开判断复用保留代理的资格与控制具体任务的权限. 子代理跨多次交办可给自己的保留下级代理分配新工作, 仍受既有派发, 额度和权限规则限制; 新任务归当前交办它的父任务. 取消和 steering 权限沿当前任务的下级分支计算, 不沿历史代理关系计算. 例如 L 在 L1 中创建 C, 之后主代理给 C 派 M2, 给 L 派 L2. L2 可以在 C 上排入归属自己的 C3, 但不能取消或纠正主代理拥有的 M2. 汇合与分支取消按任务归属, 旧父任务维持终态. 同级消息既不授予复用资格, 也不授予任务控制权.
- **Q59, 默认只读工具:** 默认只读角色开放读取, 搜索和确认属于只读能力的扩展工具, 不开放任意 shell 或写入型扩展. 需要运行测试等命令时, 由有权限的上级明确安排相应工具配置和隔离工作区.
- **Q60, 交办结果:** 分别记录执行是否结束, 子代理对交办结果的声明和主代理验收. 模型正常结束一轮或进程成功退出不能证明交办完成. 依赖仅在任务已收尾, 明确声明完成且必需结果与成果已保存可读时放行, 没有声明, 无法完成或运行失败均不放行. 声明不证明结果正确, 测试和审查证据及主代理验收仍单独保留. 后续接口须明确携带该结果, 不因此要求任意业务输出 schema.

[决策审查](subagents-decision-review.md)覆盖 Q1-Q60 全部决定, 区分源码事实与本项目取舍. [验收场景表](subagents-acceptance.md)已按当前合并方案修订. 产品场景尚未执行. 先整体 review 这些修订, 再进入 UI; 接口, 源码结构和隔离机制仍属后续工作.

## 上游边界与重写决策

- F10 存在初始化期间取消的已知缺口: 后续状态更新可能覆盖取消状态, 使任务继续执行. 上游也没有专门的暂停操作, 取消后用 F11 继续只能部分替代.
- F11 只接受失败或中止任务, 不支持已完成任务的后续对话. 显式指定的替换模型也可能再次被匹配到的角色文件覆盖.
- F21 的子代理加载器关闭了 extensions. 加载项目规则和 skills 不代表继承扩展工具.
- F26 创建 worktree 失败时可能退回原目录写入, Q30 将其改为启动失败. node_modules 通过符号链接共享, 没有隔离依赖. 提交保存后交由主代理审查, 自动合并不是上游运行时功能.
- F27 选择一个已完成的上游分支, 不合并全部上游分支. Q31 要求需要汇合多个分支时显式安排整合任务.
- F28 在整批结束时写 sidecar, 不属于持续且可靠的崩溃检查点; 恢复记录也不会自动重放工作流.

上游缺少的已完成会话续聊, 父会话历史复制, 子代理继续派生和扩展工具加载, 已通过 F30-F33 及上述规则纳入范围, 实现和场景验收仍待完成.

上游还缺少运行时修改任务图, 保存工作流模板, 条件循环, 自动验收关卡, 人工审批节点, 模型输出 schema, 硬性用量预算, 跨运行角色记忆, 外部 agent 后端和周期调度. 这些尚未纳入重写范围.
