# Subagent 重写设计

[English](../../subagents-design.md) · 英文为准.

状态: [#64](https://github.com/jczhang02/pi-stuff/issues/64) 中的设计讨论. 本文分别记录已确认决策和上游能力目录. 能力选择明确必需功能, 目录描述不代表重写采用的详细运行规则或实现状态.

## 已确认决策

- 基于 @arhen/pi-core-subagent fork 和重写. UI 独立设计, 不采用上游 UI 方案.
- 按核心行为, UI 场景与原型, 实现接口与结构的顺序推进. UI 探索发现问题时可以重新讨论核心行为.
- 能力逐项确认. 工具名, 参数和配置可以重设计, 本次设计不以兼容上游接口为约束.
- 最终支持的每项功能均须在真实使用场景中验收. 并行, 串行及其他支持的执行方式各自需要验收覆盖, 一个主要场景不能替代全部功能验收.

维护者要求先列出直白的功能表, 再选择能力. 此后 Q14 明确子代理与子代理任务的区别, Q32-Q33 明确跳过的任务和任务基线, Q47 区分正在取消与已经停止, 均已记入[术语表](CONTEXT.md). 下文规则来自明确回答, 功能目录本身不决定运行语义.

## 能力选择

Q3-Q9 已确认上游 F01-F29 全部必需, 包括执行方式与结果传递, 任务控制, 通信, 角色与资源配置, 限制与统计, worktree 管理, 持久化和生命周期事件. 每项能力均须覆盖真实场景验收.

保留能力不代表接受上游参数名, 默认值或已知缺陷. 下文已确认规则明确了部分行为, 尚未讨论的规则仍待决定.

## 已确认新增能力

| ---- | ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| F30  | 已完成子代理续聊   | 审查员已交付首次报告后, 继续带着先前上下文复查修改后的代码. Q25 还要求父会话重启后恢复上下文并支持续聊.                  |

## 已确认任务与上下文规则

- **Q14, 身份与任务历史:** 多次交办保留子代理的身份和上下文, 每次任务各自保留执行记录和结果. 首次审查与后续复查可以分别查看. 续聊不覆盖早先结果, 也不自动重跑已经使用该结果的下游任务.
- **Q15, 递归限制:** 整个根任务树共享并发上限和累计创建数量上限, 另设最大深度. 三个负责人各派四名下级时, 不会每层各自获得一份额度. Q24 明确跨派发的额度边界, Q26 明确初始数值与计数单位.
- **Q16, 完成:** 即使子代理自身已经返回报告, 也要等它的全部下级任务结束后, 才能将本次任务标为完成. 数据库下级还在修改文件时, 后端负责人的任务仍未结束. 下级失败的处理见 Q23.
- **Q17, 取消:** 取消一个任务时取消其全部下级分支, 阻止新的下级启动, 保留已有记录和代码成果供检查. 取消后端负责人也会停止数据库和 API 下级.
- **Q18, 工具范围:** 下级可用工具不能超过父级范围, 角色定义和单次调用只能继续收窄. 只读研究员不能给下级配置写工具, 应向具备所需工具的上级请求另行安排.
- **Q19, 历史快照:** 可选历史复制包含派发时父代理可见的完整对话, 包括工具调用和结果; 已压缩历史沿用已有摘要. 后续父代理消息需要显式通信, 不自动同步. 因此审查员获得派发时可见的代码与测试日志, 不会自动看到之后的父代理活动.

## 已确认调度, 失败与恢复规则

- **Q20, 忙碌时续聊:** 向忙碌子代理交办的新任务进入队列, 同一子代理一次执行一个任务. 审查员完成登录审查后才开始排队的支付审查; 修正当前审查则使用 steering.
- **Q21, 等待与并发:** 显式等待下级或答复时释放执行名额, 恢复工作时重新进入执行队列. 四个等待下级的负责人不能占满四个名额, 导致下级无法运行.
- **Q22, 依赖失败:** 依赖任务失败时, 阻止依赖它的任务启动, 无关分支继续, 并返回阻塞原因. 数据库调查失败后, 需要其结果的任务按 Q32 跳过, 独立的 API 调查继续.
- **Q23, 下级失败:** 将下级失败报告给直接父代理, 允许父代理重新委派或自行完成工作, 保留下级失败记录. 一个下级失败不立即取消整棵树, 也不自动判定父任务失败; 父代理可以补救后完成交办.
- **Q24, 跨派发额度:** 同一主会话的全部派发共享总并发上限. 每次顶层派发及其全部后代各自计算累计创建额度. 先派五名研究员再派五名审查员, 不能绕过主会话的并发限制.
- **Q25, 重启恢复:** 重新打开父会话时恢复子代理上下文和任务记录. 已完成子代理可以续聊, 未完成任务标为中断, 由主代理或用户显式继续. 已执行过的写操作不自动重放.

## 已确认限制, 依赖调度与代码交接

- **Q26, 可配置默认值:** 同一主会话初始最多八个子代理任务并发, 每次顶层派发及其后代累计最多六十四个任务, 委派深度最多三层, 主代理为第零层. 初始任务, 递归委派和续聊计入任务额度; Pi 内部的提供方请求重试不创建额外任务. 三项限制均可配置.
- **Q27, 执行计时:** 任务执行时限累计模型和工具执行阶段的时间, 排除排队及显式等待下级或答复的时间. 等待答复另设超时. 研究员等候答复半小时, 不消耗半小时的执行时间.
- **Q28, 就绪任务调度:** 任务自身依赖满足且有执行名额即可启动, 不等待同批无关任务. API 调查三十秒后结束即可开始 API 实现, 五分钟的数据库调查可以同时继续.
- **Q29, 依赖补救:** 修复失败任务后保留原图及失败记录, 主代理显式派发后续工作并引用新结果. 替代调查成功时, 不自动重启旧图中已跳过的任务.
- **Q30, 写入隔离:** Git 仓库中的可写子代理任务默认各用独立 worktree. 创建失败时报告启动失败, 不退回原目录写入. 两个实现代理并发修改时, 各自保留独立代码成果.
- **Q31, 汇合代码:** 多个写任务产生不同分支时, 显式安排整合任务合并分支并处理冲突, 后续任务继承整合分支. 只有一个上游代码分支时直接继承.

## 已确认任务结果, 工作区与消息范围

- **Q32, 跳过的任务:** 因依赖失败而无法启动的任务以跳过状态结束, 保留失败依赖及原因. A 失败而 B 尚未启动时, B 有明确终态, 父任务不再无限等待 B.
- **Q33, 初始基线:** 首次派发到隔离工作区时, 将已跟踪文件的未提交修改纳入任务基线, 未跟踪文件仅在显式选中时纳入, 原工作区保持原样. 因此实现子代理能看到父代理刚修改但尚未提交的接口定义.
- **Q34, 续聊工作区:** 写任务续聊从上次任务的代码成果创建新的任务分支和 worktree, 保留同一子代理上下文与早先成果. 若改从主工作区最新代码开始, 需要显式选择基线.
- **Q35, 代码交付:** 将任务修改保存到自己的分支, 返回提交, 差异与检查情况, 由主代理明确决定是否应用到其工作区. 实现任务成功后不会自动把修改写回主代理目录.
- **Q36, 清理:** 自动回收成果已保存且没有活跃任务使用的 worktree, 分支和会话记录保留到显式清理. 未保存修改会阻止自动移除 worktree, 并须报告, 包括取消后留下的部分成果.
- **Q37, 非 Git 写入:** 允许调用方显式选择直接写入指定的非 Git 目录, 例如普通文档文件夹. 无隔离写入不是默认行为.
- **Q38, 消息范围:** 同次顶层派发中的代理可通过已知 ID 互通消息, 包括不同委派层级. 向上提问默认找直接父代理, 不同派发之间由主代理转交. 数据库代理可直接把字段约定发给同次派发的 API 代理.

## 已确认消息投递, 配置与扩展状态

- **Q39, 普通消息:** 消息进入目标任务的收件箱, 在下一次模型处理前送入上下文, 不打断正在运行的工具. API 代理跑测试时收到数据库消息, 在下一次处理机会读到它. 已结束任务保留消息并通知主代理, 不自动开启新任务.
- **Q40, 未答复的问题:** 等待答复默认十分钟, 可配置. 到期明确返回未收到答复, 子代理可以继续不依赖答案的工作, 或说明无法完成交办; 不猜测答案, 也不自动判定整个任务失败. 迟到的回复仍关联原问题, 不自动启动新任务.
- **Q41, 角色选择:** 派发者明确选择已发现的 Markdown 角色文件, 或临时定义角色; 未指定时使用通用角色. 保留角色文件和发现列表, 核心不根据文字相似度自动选择或切换角色. 审查任务提到数据库, 不会因此自动选择数据库实现角色.
- **Q42, 配置优先级:** 模型和思考强度等普通配置依次采用本次调用参数, 角色文件, 项目默认值, 用户默认值, 父代理当前配置. 本次指定模型 B 时覆盖角色文件中的模型 A. 工具范围和数量额度仍受已确认上限约束, 配置优先级不能扩大范围或额度.
- **Q43, 依赖结果传递:** 默认传递上游最终报告及文件, 分支, 提交等成果引用, 不附带整个执行日志. 超过可配置长度时提供明确标注的截断预览和完整内容读取引用, 保留完整结果. 下游实现代理需要时可以读完研究员的长报告.
- **Q44, 记录恢复:** 在任务创建, 重要状态变化和结果交付时保存记录. 十个任务尚在执行而 Pi 退出时, 恢复可用记录, 明确报告损坏或缺失的部分. 不能把新建会话或不同代码基线当作恢复成功.
- **Q45, 扩展状态:** 同名扩展工具在各子会话中独立初始化, 临时内容, 缓存和取消状态归各自会话管理. 清空父代理网页缓存不能清除子代理保存的内容. 只初始化本次任务需要的扩展, 再按已确认的父级和角色范围开放工具. 第三方扩展的全局状态如何隔离仍须在实现时验证.

## 已确认执行控制与恢复边界

- **Q46, 执行超时:** 单个任务默认累计执行时限为三十分钟, 可配置, 按 Q27 排除排队和显式等待. 到期停止该任务及下级, 保留已有成果并记录超时原因, 不自动重跑. 实现任务修改和测试代码耗尽时限后, 即使还有计划中的工作也须停止.
- **Q47, 正在取消:** 发出取消请求不代表已经停止执行. 工具仍在运行时保留正在取消状态, 活跃执行继续占用名额. 确认停止前不启动同一子代理的下一任务, 也不清理其工作区. 报告尚未停止的活动, 例如取消后仍在运行的测试进程.
- **Q48, 限时等待结果:** 主代理单次等待结果默认六十秒, 可配置. 所等待目标结束, 子代理提问或发生失败时提前返回. 到期返回当前情况, 只结束等待, 子任务继续执行. 主代理因此可以查看三名研究员的情况, 无须无限等待.
- **Q49, 运行中补充指令:** 修改当前任务的 steering 在当前轮工具执行结束后, 下一次模型调用前优先处理. 不强制停止这些工具, 仍属于同一个任务. 任务已经结束时明确拒绝 steering, 提示调用方使用续聊. 优先修登录而暂缓支付的指令在该边界生效.
- **Q50, 无效派发:** 启动前检查已知错误. 依赖图无效, 角色或工具配置无效, 深度或累计任务数量越界时, 拒绝整次派发, 不创建任务或消耗累计额度. 仅并发执行名额不足时, 有效任务排队等待. 三项交办中指定了不存在的角色, 三项一起拒绝.
- **Q51, 配置快照:** 接受任务时保存解析后的配置, 后续修改角色文件或默认值只影响新任务, 不影响排队或执行中的任务. 续聊按新任务解析. 排队的审查任务采用模型 A, 即使角色文件已改为模型 B, 仍沿用 A.
- **Q52, 只读代码视图:** Git 只读任务默认读取指定代码基线的独立快照, 读取实时工作区需要显式选择. 主代理并发修改时, 审查报告不能默默混入修改前后的不同代码状态.
- **Q53, 工作区缺失恢复:** worktree 不存在而保存的原提交仍可用时重建 worktree, 任务执行仍须显式继续. 原提交或必要上下文缺失时, 明确报告无法恢复执行, 保留其他可查看记录. 改从不同基线开始需要显式选择.
- **Q54, 事件监听失败:** 生命周期监听器失败时记录扩展错误, 任务结果和调度照常处理. 某扩展记录任务完成事件时报错, 不能因此把已完成任务改为失败.

这些规则是后续场景验收需要验证的行为. 剩余讨论涉及最终报告交接, 异常结束后的排队任务和会话生命周期, 随后补齐逐项功能验收规格. UI 与实现设计仍在后续阶段.

## 上游能力目录

来源: @arhen/pi-core-subagent 1.3.54, 提交 [de1c878](https://github.com/arhen/pi-extensions/tree/de1c8783c2a39b1cbb0f86b412307193de9774c1/packages/core/pi-core-subagent). 下述内容来自静态源码检查, 描述已有行为, 不代表上游已通过场景验收. 后续决策使用 F01-F29 引用对应条目.

| 编号 | 功能                    | 现有行为或使用例子                                                                           |
| ---- | ----------------------- | -------------------------------------------------------------------------------------------- |
| F01  | 单任务委派与独立上下文  | 交给子代理一个调查任务, 中间消息留在它自己的 Pi 会话, 主代理取得结果.                        |
| F02  | 并行执行                | 同一批次内同时调查 API 和数据库.                                                             |
| F03  | 串行执行                | 按调查, 实现, 审查的顺序运行.                                                                |
| F04  | 依赖图调度              | 用 `needs` 声明依赖, 按批次运行就绪任务, 拒绝无效图, 跳过依赖失败或中止任务的后续节点.       |
| F05  | 自动传递上游结果        | 将依赖任务的输出加入后续任务提示, 用首个上游结果替换 `{previous}`.                           |
| F06  | 后台执行与前台等待      | 立即返回 run ID, 或通过 `autoAwait` 等待结果. 子代理提问时可以结束等待, 让主代理回答.        |
| F07  | 状态与结果查询          | 查询整批快照, 子会话路径或单个任务结果.                                                      |
| F08  | 限时等待                | 等待超时后返回, 子任务继续执行; 子代理消息也能唤醒等待.                                      |
| F09  | 完成与失败通知          | 子任务或整批结束后通知主代理, 失败通知及时送达.                                              |
| F10  | 取消任务                | 公开工具可取消整批任务. manager 也实现单任务取消, 当前由上游 UI 调用.                        |
| F11  | 失败或中止后继续        | 重新打开已保存的子会话, 有条件时重新挂接原分支. 要求整批已结束, 且任务创建过会话.            |
| F12  | 运行中补充指令          | 给一个运行中的子代理或该批全部运行中的子代理追加要求.                                        |
| F13  | 向主代理提问            | 子代理在 `ask_parent` 中等待, 主代理用 `reply_subagent` 回答. 无人回答时最多等十分钟.        |
| F14  | 向主代理报告发现        | 子代理发送发现后继续工作, 不等待答复.                                                        |
| F15  | 兄弟代理邮箱            | 同批子代理相互发送短消息, 通过轮询取出邮箱内容.                                              |
| F16  | 临时定义角色            | 本次调用直接指定名称和系统提示, 无须先建角色文件.                                            |
| F17  | 角色文件                | 从项目或用户目录发现 Markdown 角色文件, 按描述与任务目标的词语重合度匹配.                    |
| F18  | 模型与思考强度          | 配置子代理的模型和思考强度, 角色文件默认值参与解析.                                          |
| F19  | 工具选择                | 使用只读或可写工具集, 也可指定内置工具白名单; 另装载子代理通信工具.                          |
| F20  | 工作目录选择            | 为任务指定仓库或子目录.                                                                      |

## 上游边界与重写决策

- F10 存在初始化期间取消的已知缺口: 后续状态更新可能覆盖取消状态, 使任务继续执行. 上游也没有专门的暂停操作, 取消后用 F11 继续只能部分替代.
- F11 只接受失败或中止任务, 不支持已完成任务的后续对话. 显式指定的替换模型也可能再次被匹配到的角色文件覆盖.
- F21 的子代理加载器关闭了 extensions. 加载项目规则和 skills 不代表继承扩展工具.
- F26 创建 worktree 失败时可能退回原目录写入, Q30 将其改为启动失败. node_modules 通过符号链接共享, 没有隔离依赖. 提交保存后交由主代理审查, 自动合并不是上游运行时功能.
- F27 选择一个已完成的上游分支, 不合并全部上游分支. Q31 要求需要汇合多个分支时显式安排整合任务.
- F28 在整批结束时写 sidecar, 不属于持续且可靠的崩溃检查点; 恢复记录也不会自动重放工作流.

上游缺少的已完成会话续聊, 父会话历史复制, 子代理继续派生和扩展工具加载, 已通过 F30-F33 纳入范围, 详细语义尚待确定.

上游还缺少运行时修改任务图, 保存工作流模板, 条件循环, 自动验收关卡, 人工审批节点, 模型输出 schema, 硬性用量预算, 跨运行角色记忆, 外部 agent 后端和周期调度. 这些尚未纳入重写范围.
