# 子代理

[English](../../subagents.md). 以英文版为准.

开发版扩展通过单一 `subagent` 工具委派工作. 独立调查可以并行, 串行链和显式依赖会把前序报告交给后续子代理. 运行时遵循 arhen `pi-core-subagent` 1.3.55, 按[重写规格](subagents-redevelopment-spec.md)增加已完成子代理续聊、逐次执行历史和选定扩展工具.

## 试用源码

按[贡献指南](CONTRIBUTING.md#验证变更)安装固定版本的依赖. 在希望子代理调查的项目目录中启动 Pi, 传入本检出的绝对路径:

```bash
pi --no-extensions -e /absolute/path/to/pi-stuff
```

使用已配置的模型和凭据. 可以从这个提示开始:

```text
使用 subagent 并行启动两个只读调查: 一个检查取消流程, 一个检查保存会话的处理.
然后用显式依赖让审查员比较两份报告. 在后台执行.
```

只读子代理直接调查选定目录及当前文件, 不枚举被忽略的依赖, 不创建 Git 快照. 有写入工具的子代理需要 Git 仓库, 在自己的 worktree 中运行. 父目录中的未提交修改不会复制进去.

## 查看和干预

FleetView 位于主状态栏下方. 编辑器边缘的 Up/Down 在 Pi 编辑、补全和历史没有消费该按键时进入列表. `/subagents` 也能打开列表. 选中时只有圆圈变化, 局部操作提示随焦点显示, main 行没有描述.

| 界面               | 操作                                                                    |
| ------------------ | ----------------------------------------------------------------------- |
| Fleet              | Pi 选择键移动, 确认键打开子代理, `g` 在存在依赖时打开其依赖图.          |
| 子代理详情         | `p` 展开 Prompt, `a` 展开 Activity, `t` 打开 Transcript, `i` 打开 Info. |
| 工作中的子代理     | `m` 打开定向消息编辑器, 原文保持排队状态直到原生输入消费它.             |
| 待答问题           | 确认键打开该问题的 Reply. 其他来源先答复也不会让草稿改投新问题.         |
| 已完成子代理       | 整批工作结束后, `m` 打开 Follow-up.                                     |
| 失败或已停止子代理 | 保存的会话和必要代码状态可用时, `m` 打开 Resume.                        |
| 停止               | `x` 打开内联确认, 确认键请求取消, Esc 撤回确认.                         |
| Info               | `h` 打开执行历史, 选择旧执行查看其报告和用量.                           |
| 阅读区域           | `[` / `]` 翻页. 新输出保留当前阅读页, `f` 跟随最新输出.                 |
| 局部编辑器         | 使用原生编辑、提交、换行绑定. 字母作为文本输入, Esc 保留草稿而不发送.   |
| 返回               | Esc 返回前一界面, 然后 Fleet, 最后恢复带有原草稿的主编辑器.             |

显示的选择、确认和编辑快捷键遵循 Pi 配置. 功能字母仅在检查界面生效, 不要求 Alt+A、功能键或专用翻页键. 详情替换底部编辑器和状态栏区域, 主对话仍在上方, 并不切换宿主会话.

## 结果和配置

父代理工具命令包括 `dispatch`, `status`, `result`, `wait`, `reply`, `steer`, `resume`, `follow-up`, `cancel`. `status` 返回简要状态, `result` 返回记录的证据. 后台完成会通知父代理. 正在等待时直接返回结果, 不额外触发重复的完成回合; 等待超时不会抑制之后的通知.

派发可以指定单个 agent、`tasks` 或 `chain`, 任务的 `needs` 指向依赖 ID. 批量输入的 `tools`, `write`, `prompt`, `model`, `thinking` 放在各任务中. 默认只读、后台执行、并发 3、逐任务通知. 最多 16 个任务, 并发上限 8. `/subagents auto-limit on|off` 将上游默认时限设为 1 或 6 小时, 任务也可显式指定时限.

代理文件按上游发现规则提供角色提示和工具、模型设置. Pi 项目的 `APPEND_SYSTEM.md` 或全局回退文件仍属于子代理指令. 选定的父代理扩展来源会在子代理加载, 可调用工具受父代理当前工具集合和角色限制. 必需工具加载失败、子代理不支持的交互 UI 请求都会报告错误. 子代理具有 `ask_parent`, `notify_parent`, `send_agent_message`, `poll_agent_messages`, 消息工具说明中包含同伴地址. 不支持递归委派.

Fleet 和详情展示本次执行的时间和输出 tokens. Info 提供记录的输入、输出、缓存、费用、回合及子代理累计用量. 缺失用量显示为不可用. 每次接受恢复或续聊都会保留前次执行, 继续相同的已保存上下文, 不自动重跑下游.

## 代码和保留证据

模型报告完成不代表 Git 已保存修改. 详情和 Info 区分已提交、无修改、正在收尾和保存失败. 执行与收尾都结束后才退出 Stopping. 保存失败保留工作目录和错误; 保存成功保留分支并允许清理 worktree 目录. 审查和集成仍需单独处理.

存在多个写入依赖时, 后续写入任务以最后一个符合条件的依赖分支为起点. 它收到所有前序报告, 但不会合并所有前序分支. 共享 `node_modules` 不构成沙箱, 子代理指令禁止修改依赖.

原生子代理会话保留对话证据. 新的运行元数据位于父会话旁的 `.pi-stuff-subagents.json` 文件, 不迁移或删除旧实现记录. Reload 将中断工作恢复为已停止, 不自动执行. 局部草稿在同一宿主会话内经过导航和缩放仍保留, 不承诺跨进程重启.

测试宿主、真实终端截图和验证限制见[验收记录](subagents-redevelopment-acceptance.md).
