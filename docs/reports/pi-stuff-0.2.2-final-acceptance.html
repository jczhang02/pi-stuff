CHAPTER 02

真正打开以后：信息完整，但不抢对话

欢迎区只回答“当前是谁、在哪里、加载了什么”；底部状态栏只保留模型、思考等级、目录、Git、上下文、缓存命中率与 Codex weekly limit，Fast 仅在开启时出现。Goal、Agents、MCP 等能力不在这里重复报状态。

统一设置入口是 /ui。它使用 Pi 原生可搜索列表，所有选项在一个层级；窄屏时保留完整词义，不把提示或值截成半个词。

CHAPTER 03

日常输出：Thoughts、Todo、工具和 Agent 使用同一节奏

实时思考显示为一行 ✻ thoughts:，同一次模型响应在原位更新，不再把多个片段拼成一条越来越长的句子。Todo 首行与 Agent 输出首格对齐，工具成功、运行、失败和取消共用稳定的一列状态图标。

BTW 采用一次提问、一次回答的 Claude Code 式总体形态，但由 Pi Stuff 统一 UI 渲染。它打开时主 Agent 继续工作；关闭后恢复原编辑器内容，不把旁问写进主会话。

Agents 保留后台执行能力，但移除了浮动 FleetView。普通屏幕只显示紧凑 roster；查看详情时才进入同一类全宽界面。短任务合同明确要求 Agent 直接完成，真实复测没有无意义的嵌套分裂。

CHAPTER 04

长上下文不是装饰：压缩、召回和隔离都跑过

在 45,655 tokens 的真实 Spark 会话中执行 /compact，Magic Context 生成一个且仅一个成功边界；界面不再误报“cancelled”。退出 Pi 后冷恢复，同一边界仍只出现一次，压缩前的唯一标记可以继续通过 ctx_search 找回。

CHAPTER 06

失败路径同样要好用：看得懂，也回得来

工具运行中使用 Pi 的 Escape 中断，Bash 行从运行状态转为红色 cancelled，不会残留假成功。缺失文件和 Web 安全拒绝保留短原因，完整路径和错误可以在 /tools 详情中查看；冷恢复后仍使用相同渲染，而不是退回 raw JSON。

没有掩盖的限制：模型仍可能第一次给 Goal 工具传错 schema；运行时会显示可执行的校验错误并允许重试。最终干净复测已一次通过。派生 Context 状态损坏时，Magic 工具会退出，而不是伪造召回；Pi 原生 session 保持可用。

APPENDIX A

边界：哪些是可替换选择，哪些不是缺陷

Magic Context 当前是明确的试用方向，不是不可逆的数据迁移。若日用表现不满意，可以替换 Context owner；Pi session JSONL、原生 resume 和项目文件不会因此丢失。

  • Memory 方案暂时让位于 Magic Context，不在 0.2.2 中偷偷加入 Mem0。
  • LSP、交互式浏览器和默认 Skills 明确不属于本轮范围；Web 与 MCP 已覆盖当前需要的外部读取和连接。
  • Permission 插件已移除；普通工作不会出现任何权限提醒。Pi Stuff 仍不是操作系统安全沙箱。
  • 真实模型输出存在随机性，UI 和运行时保证的是清晰状态、可恢复路径与诚实失败，不承诺模型永远第一次选对工具参数。
最终结论：Pi Stuff 0.2.2 已经满足“现在启动就能用、长时间用不容易乱、出错时看得懂”的交付标准。它的 UI 已先于更多功能完成统一，正式包已经装入当前 Pi；下一阶段可以在真实日用反馈上迭代，而不需要继续把基础体验当作未完成原型。
