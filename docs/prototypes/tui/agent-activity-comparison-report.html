01 / What the references actually do

先把两套喜欢的 UI 说成具体使用体验

以下 Claude 结论现在直接来自 2.1.197 发布二进制的黑盒交互；文档和源码研究只用于解释边界，不再代替画面证据。没有复制、翻译或移植任何参考代码。

Claude 2.1.197：对话组 + Agent 列表

  • 同一 assistant response 发出的两个前台 Agent 被合成一棵 Running 2 agents… 树；主 Agent 此时被阻塞。
  • 运行时还会在编辑器下方显示 main / explorer / reviewer 列表。它不是 statusline，也不是浮动窗口；空编辑器按 ↓ 进入管理，再用 ↑/↓ 选择、Enter 查看。
  • Ctrl+B 可把这批前台 Agent 转到后台。原记录立即收缩成 2 background agents launched，主 Agent 继续，底部列表保留。
  • 前台完成会把同一棵树改成 2 agents finished；后台完成则逐个插入绿色通知，并在底部列表保留耗时与 token 统计。
  • Ctrl+O 确实是全局 detailed transcript：完成树展开为每个 Agent 的 Prompt、Response 和统计，不是只展开当前选中项。

采集对象：Claude Code 2.1.197，Linux x64 发布二进制 SHA-256 f54e69cb…7f83。隔离 HOME、配置目录与 localhost Anthropic Messages fixture；两个 child request 同时发出并延迟 12 秒。完整方法见 capture script 与 local fixture。

三个入口仍不是一回事： 这里观察的是普通对话中的 Agent 活动；旧版 /agents library/wizard 和独立 claude agents Agent View 都不是下面五张图的对象。

tintinweb：工作区拥有实时态

  • 后台 Agent 运行时，编辑器上方常驻 Agents 树；每个运行项占两行并显示当前动作。
  • 队列不逐项展开，只显示“2 queued”；空间不足时优先保留运行项，并用“+N more”收口。
  • 编辑器下方还有可导航 FleetView：从 main 切进某个 Agent，查看并管理正在进行的会话。
  • 完成后，实时区消失；主对话收到带任务名、统计和结果预览的完成通知。
  • 原实现会同时出现 Widget、FleetView 和 Agent statusline 三份状态；会话查看还使用居中 overlay。Pi Stuff 已决定删除 statusline 重复并拒绝 overlay。

依据：tintinweb/pi-subagents、固定 clone 8976c63… 与 npm @tintinweb/pi-subagents@0.14.3。npm release 的 top-level renderer 与固定 clone 对应逻辑一致；在隔离 Pi 0.83 PTY 中复现，相关 70 个 UI tests 全部通过。

02 / The actual product choice

差别不在“好不好看”，而在谁占用主对话

使用时刻 A · Claude 前台组 B · tintinweb C · 融合
刚启动 对话生成 Agent 组，编辑器下方出现 Agent 列表；主 Agent 被阻塞。 对话只记“已后台启动”。 对话只记一行启动事实与总数。
运行中 组记录原位更新；列表持续可见；可按 Ctrl+B 转后台。 编辑器上下两处持续可见，信息最全。 编辑器上方只保留 2 项和 +N。
完成后 前台原组变为完成态；后台则逐条通知并保留列表统计。 每个 Agent 各自回写一条通知。 实时区消失，对话只留一组结果摘要。
完整详情 Ctrl+O 全局展开；空编辑器按 ↓ 管理，再选择 Agent。 FleetView 进入会话；原版会打开 overlay。 ↓ / Pi Stuff 拟议的 /agents 打开非浮动 Command Dialog。
主要代价 运行时同时占用 transcript 和编辑器下方两处，但职责不同。 编辑器附近重复显示，窄终端尤其拥挤。 需要维护“运行态 → 完成摘要”的明确迁移。
03 / Released Claude Code evidence

这五张才是 Claude Code 2.1.197 真实快照

真实的是发布二进制、TUI renderer、按键处理和前台→后台→通知的状态变化；合成的是模型返回的两个无工具任务。这样既能稳定停在所需状态，也不会使用用户账号、历史会话或外部 API。

04 / Native Pi previews

再把三种产品方向放进真实 Pi Host

以下六张是静态 Pi 布局，不冒充 Claude 原图。A 只翻译 Claude 的前台 transcript group；B、C 比较后台工作区。切换时重点看输入区附近：后台运行中是否一直找得到 Agent、是否重复，以及完成后主对话留下多少东西。

A

Claude 式 Pi 翻译：这里只画前台组

这里早于真实采集完成，只翻译了同一轮并行前台 Agent 的 transcript group，没有复现 2.1.197 同时出现的编辑器下方 Agent 列表。因此它是一个局部产品方案，不再称为“Claude 快照”。

实际优点

parallel sibling calls 天然属于一组；完成后主对话的历史记录自洽。

实际限制

它省略了真实 2.1.197 的底部 Agent 列表，也不回答“主 Agent 已继续时，后台 Agent 放在哪里”。Ctrl+O 仍会全局展开。

B

tintinweb 派生：实时工作区一直贴着编辑器

这是最接近“我始终知道后台在干什么”的方案。运行帧保留已在 npm 0.14.3 / Pi 0.83 实测的上方 Widget 与下方 FleetView；为了遵守既定规则，原版居中 overlay 和第三份 statusline 计数没有复现，因此它是 retained-surfaces translation，不是完整原版复刻。

实际优点

Agent 数量、当前动作、排队状态始终就在输入框旁；这一信息层级与 npm 0.14.3 的真实 Pi 运行帧一致。

实际问题

同一批 Agent 在 launch 行、上方树、下方列表和完成通知中多次出现。100×32 已明显压缩对话空间。

C

融合式：运行时靠近我，完成后回到历史

从 tintinweb 借“后台活动态应贴着编辑器”，从 Claude 2.1.197 的真实行为借“同一批 sibling work 应当成组”。Agent 只增加 owner、层级与状态；其内部 Read / Search / Bash 仍使用已经确定的统一 tool renderer。运行区只显示两个代表项和 +N；结束后只在对话中留下一个结果组。

实际优点

运行时不失联，完成后不制造三条通知；100×32 布局通过，64×28 只验证了 running frame 的截断与输入区可用性。

尚未验证

完整名单、selected row、局部 transcript、steer、resume、stop、权限请求和失败态都不在这六帧内。Pi Stuff 拟议的 /agents 必须随时可达，错误/等待授权也不能收进 +N。

05 / Superseded recommendation

这条生命周期分工仍成立；上方活动区不再采用

C

实时状态属于工作区；永久结果属于对话

这条规则能解释所有细节，而不只是拼两套样式：Agent 正在跑时，用户最关心“还有几个、现在在做什么、能不能管理”；结束后，用户只需要“这一批得到了什么、哪里能看完整过程”。

  1. 启动时，主对话只留一行批次事实。
  2. 运行时，编辑器上方最多展示 2 个 Agent；剩余用 +N more。 后续决策改为一个 Claude 风格的 below-editor roster。
  3. 完成时，活动区消失；同批 Agent 合成一条完成记录。
  4. 失败、等待用户输入、权限请求永远单独露出，不允许藏进 +N。
  5. ↓ 或 Pi Stuff 拟议的 /agents 打开已经确定的非浮动 Command Dialog；不采用 FleetView 打开的 centered ConversationViewer overlay。
已被 后续 roster 决策 部分取代：继续采用“launch/settled record + 一个 live roster + 显式 detail”的生命周期，但 roster 固定在编辑器下方；above-editor widget 被取消。single、failed、stopped、waiting-permission、通知合并和 linger 仍需后续状态帧。
