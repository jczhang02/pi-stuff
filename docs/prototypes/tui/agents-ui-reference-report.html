State comparison

Running · 先回答“现在谁在工作”

没有任务时只给一句空状态，不用仪表盘填满空间。
真实 PTY
保留上方对话 一条分隔线 动态底部提示

应该保留

Running / Library 的稳定位置；一句直接的空状态；当前状态对应的键盘提示。

不应该增加

总览卡片、统计数字、空洞插图、第二层边框，以及为了“高级感”添加的面板装饰。

仍需后续验证

真实运行任务的行密度、状态词、耗时呈现，以及任务等待用户输入时如何突出。

State comparison

Library · 创建在前，定义按来源分组

这是“选择要用谁”的清单，不是 Agent 管理后台。
真实 PTY
Create first 按来源分组 模型是次要信息

用户看到什么

第一项是 Create new agent；往下是项目内可用的 Agent，再往下是随时可用的内置 Agent。

用户怎么操作

左右键换 Running / Library，上下键选行，Enter 进入；不需要先理解“资源管理器”等术语。

Pi Stuff 的边界

最终分组名称要由 Pi Stuff 的来源模型决定；Claude 的 Project / Built-in 只证明“按来源分组”有效。

03
State comparison

Agent actions · 在原地向下走一层

选中 Agent 后，列表原地变成动作；Esc 返回上一层。
真实 PTY
Same-body drilldown Esc 返回一层 危险动作保持普通密度

层级规则

第一次 Esc：动作 → Library。第二次 Esc：关闭 Agents → 回到输入。每次只返回一层。

动作规则

最常用动作在第一行；View / Edit / Delete 保持文字清单。真正执行删除时再单独确认。

视觉规则

焦点只靠游标、文字色和轻量强调表达。不要用 GUI 式按钮、阴影、圆角面板或浮层堆叠。

由此形成的 Agents UI 建议
01
它属于对话，不是独立应用
打开时暂时替换 editor；上方 transcript 和下方 Host 状态仍然存在。
建议采用
02
Running / Library 是两个稳定入口
分别回答“谁正在工作”和“我可以启动谁”，不混成一个总览页。
建议采用
03
状态变化发生在同一块正文里
列表、动作、创建、查看与编辑逐层替换正文；Esc 一层层返回。
建议采用
04
键盘提示始终解释“现在能做什么”
提示随当前页面变化，不做一条塞满所有快捷键的永久帮助栏。
建议采用
05
视觉服从终端密度
使用分隔线、缩进、字色和空行建立层级；禁止 GUI 式卡片、阴影和窗口装饰。
建议采用
06
Claude 提供骨架，Pi 决定最终外观
颜色、字重、状态词、Agent 来源分组和真实运行态仍需用 Pi fixtures 单独确认。
