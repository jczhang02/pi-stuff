# Subagent decision review

[简体中文](i18n/zh-CN/subagents-decision-review.md) · English is normative.

Review date: 2026-09-14. Baseline: the accepted interview record at [`1c75955`](https://github.com/jczhang02/pi-stuff/blob/1c75955b50b05330280d08586f2789befa2069ce/docs/subagents-design.md). The maintainer requested this source review before UI. This document covers Q1-Q60, retains all F01-F33 capabilities and proposes corrections; it is not a new approval or a runtime acceptance report.

The main defect was coupling things that have different lifetimes: an agent's continuing context, one assignment's result, a live execution slot and a workspace. The revised [design](subagents-design.md), [acceptance scenarios](subagents-acceptance.md) and [glossary](../CONTEXT.md) now distinguish them. Keep arhen as the fork source. Borrow mechanisms selectively rather than reproduce an entire Codex or Claude orchestration system.

## Changes that matter in use

These are design counterexamples, not executed tests. Source IDs refer to the evidence register below; the recommendations are our inferences and product choices.

| Situation                                                                        | Earlier rule                                                             | Review proposal and cost                                                                                                                                                                                     | Evidence   |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| The same implementer makes three successive fixes.                               | New worktree on every follow-up, then automatic removal when inactive.   | Keep its workspace and configuration, record each task's fixed commit/result, and reclaim only after workspace release. Less rebinding and environment setup, more retained disk usage.                      | G1, L1, P1 |
| A repair agent says it could not fix the bug, then returns normally.             | Completion language risked treating normal execution as fulfillment.     | Record execution end, declared outcome and acceptance separately. Dependents require a settled fulfilled declaration; the declaration still can be wrong. No automatic correctness detector is claimed.      | C1, A1     |
| Two leads wait for children while another tool is still testing.                 | Any explicit wait releases a slot.                                       | Release only when no execution remains in that task; retain identity and quota counts, reacquire on resume. Resident-context limits cannot substitute for this scheduler.                                    | C2, G2     |
| A child is spawned inside a turn containing unfinished tool calls.               | Copy the complete visible history without a protocol boundary.           | Produce valid call/result pairing, preserve completed content and label fork-control records. Tools, permissions and files remain independently resolved.                                                    | L1-L2, P1  |
| A role allows one tool from an extension that registers several tools and hooks. | Initialize only the needed extension tools and assume child-owned state. | Select entrypoints, initialize per child, then filter exposed tools. Validate shared globals and reject unsupported entries; an allowlist cannot undo factory side effects.                                  | P1, G2     |
| A legitimate implementation needs more than thirty minutes.                      | Stop every task at thirty minutes unless overridden.                     | Keep configurable execution deadlines, disabled when unconfigured. This avoids an unsupported universal cutoff, but has no default task-duration cost ceiling. 8/64/3 remain trial limits, not measurements. | A3         |

Codex also contains V1 and V2 collaboration paths with different limits and controls. In the inspected V2 path, ordinary messages and turn-triggering follow-ups are distinct, while the wait tool keeps the running turn's execution guard. Pi's cooperative wait-slot release and per-agent durable assignment queue therefore need their own implementation. We do not transfer V1 depth/close behavior or Agents API defaults into V2 claims. See C2-C4.

Configuration stability is a deliberate choice, not an upstream consensus: the Claude mirror reselects the agent definition on resume, and arhen resolves role files when execution starts. Freezing our retained agent's configuration avoids a reviewer silently changing tools/model because a file changed. Explicit supported overrides and current permission restrictions still apply.

We also keep choices that the references do not uniformly implement: default isolated Git writers and stable read-only code, no silent parent-directory fallback, branch cancellation with confirmed stopping, ordinary messages that cannot resume ended tasks, held queues after abnormal outcomes, and immutable old graphs. These suit the accepted workflow; none is justified merely by another product's defaults.

## Evidence register and confidence

U is the accepted baseline linked above and the maintainer's current review request. Official project source and versioned npm distributions are direct implementation evidence; static inspection does not prove runtime acceptance or that every gated branch is enabled. Versions below identify evidence, not compatibility requirements.

Claude evidence needs special care. The mirror at `6f6f12b37f529488b10e53928dd5508bb93535c7` is a community-modified repository with internal stubs and feature shims. Its private package version `1.0.0` does not identify an authenticated Claude Code release. L1-L3 are structural clues from that snapshot, not verified product guarantees. No mirror source is imported into this repository. A local official 2.0.76 bundle supplied no usable source map and was not used to authenticate the mirror.

D1: current official [subagents](https://code.claude.com/docs/en/sub-agents), [agent teams](https://code.claude.com/docs/en/agent-teams) and [worktrees](https://code.claude.com/docs/en/worktrees), checked 2026-09-14. Named agents, teams and fork mode are separate paths. The current subagent page documents explicit resume through SendMessage and optional worktree isolation; this does not mean ordinary messages must auto-resume our ended tasks, or that every Claude child uses a worktree. Current version-conditioned documentation cannot authenticate the older mirror or its feature flags.

## Verification still required

The review used three read-only research contexts for Codex, Claude and Pi packages, followed by owner checks of the decisive source paths and the complete decision inventory. It did not run imported products, install dependencies, implement a scheduler or execute acceptance scenarios.

The next implementation evidence must resolve valid Pi history forks, safe extension initialization, dirty-baseline capture, actual process stopping and state recovery after interruption. Retained contexts need measured memory/disk costs; 8/64/3 have no calibration evidence. B01-B12 now include mixed wait/tool activity, explicit recovery before a held queue, unchanged old commits, optional-observer versus core-storage failure and false fulfillment declarations. These requirements remain unverified.

The source review is ready for overall discussion. UI remains deferred until this revised behavior proposal and its acceptance coverage are understood; another round of mechanical per-question approvals is not required to read or assess this report.
