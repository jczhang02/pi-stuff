### Public renderer interfaces

Pi 0.85.1 exposes `setStatus`, keyed `setWidget`, `setHeader`, `setFooter`, `setEditorComponent`, `registerMessageRenderer`, `registerEntryRenderer` and per-tool `renderCall`/`renderResult` in its [extension API](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/core/extensions/types.ts). A custom message fixture only proves the renderer for that custom type. It does not replace ordinary assistant text, thinking, or a native `read`/`bash` card.

Native built-in cards do have a public route: register the same tool name, delegate to Pi's `create*Tool` implementation, preserve its exact result/details shape, and override only the render slots needed. Pi documents per-slot renderer inheritance in [the built-in override guide](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md), so this is a documented implementation path for native tool cards. Ordinary assistant and thinking components have no equivalent public renderer hook. `registerMarkdownTransformer` can see `assistant-thinking`, but only transforms Markdown before Pi renders it; theme colors and the hidden label remain the supported control points.

`setStatus` is additive. `setFooter` and `setHeader` replace Pi-owned surfaces, and `setEditorComponent` replaces the editor, so each needs one explicit owner and a restore path. The early candidate replaced header/footer. The current prototype only replaces the header and leaves the footer native. Production coexistence with other packages remains a decision; additive status is the safer integration when another footer owner exists. The old custom UI remains the reference, and these package rows do not create requirements.

The sample preview uses fixture messages and static states only. It has not executed a live provider, tool call, test command or repository mutation, so its screenshots do not establish native runtime behavior.

## Terminal palette finding

The original foreground launcher at 2184119 emitted OSC 10/11 color setters into the outer terminal. The current launcher emits neither setters nor resets; only isolated capture PTYs set deterministic colors. [Ghostty dynamic colors](https://ghostty.org/docs/vt/osc/1x) and [reset semantics](https://ghostty.org/docs/vt/osc/11x) explain why resets cannot restore arbitrary previous overrides. Terminal Control [v1.2.1 session.rs](https://github.com/anomalyco/terminal-control/blob/v1.2.1/src/session.rs) mirrors child bytes. Its [shot.rs](https://github.com/anomalyco/terminal-control/blob/v1.2.1/src/shot.rs) answers palette queries with fallback colors, so hosted auto-detection does not establish the outer Ghostty palette. The retained foreground verifier checks six inherited/explicit/legacy-Esc/Kitty-Esc paths. Actual window/compositor behavior remains outside that evidence.
