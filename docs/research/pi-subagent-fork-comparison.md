# Pi subagent fork bases: a source-led comparison

[简体中文](../i18n/zh-CN/research/pi-subagent-fork-comparison.md)

**Research date:** 2026-09-10

**Scope:** public Pi subagent packages and the official Pi example only. All old `pi-stuff` research, including `pi-stuff-old`, is excluded.

**Target:** a future `pi-stuff` used for ordinary development: fresh-context scouting and read-only review, true background delegation, status/wait/steer/stop/result collection, and an explicit `cwd` pointing at an existing stable-main or development worktree. The target host is a Linux Pi 0.85.1 binary compiled with Bun; the repository uses Bun 1.4.0, TypeScript 7.0.2, and Effect 4.0.0-rc.112.

This is a research comparison, not an adopted design or an implementation plan. “Read-only” below means a tool or policy restriction only when the source actually enforces one. A prompt saying “do not edit” is not a technical read-only boundary. A worktree separates files; it does not sandbox shell, network, or ambient user permissions.

## Executive finding

The first fork validation should start with `ogulcancelik/pi-extensions` at its `packages/pi-codex-subagents` package. It is the narrowest candidate that already combines the requested shape: an OS child process, detached execution, durable task/session artifacts, explicit `cwd`, status and wait tools, steering, interruption, ownership checks, and recovery. Its fit is conditional. The package is still a large `core.ts` with loose types, no discovered CI workflow, a startup `SYSTEM.md`, disabled context-file loading, and an incomplete timeout boundary. It must pass a real Pi 0.85.1 Bun-compiled-host acceptance before it can be treated as a sound base.

This recommendation is about the first experiment, not a global ranking. `nicobailon/pi-subagents` is the strongest standalone and recovery reference: it has a detached runner, persistent artifacts, parent-reload recovery, an actual Linux standalone matrix, and explicit separation of result completion from process exit. Its standalone smoke evidence uses deterministic providers rather than a paid live-model end-to-end path, so it validates process/session integration more directly than provider behavior. Its cost is breadth: missions, workflow, scheduler, worktree, external jobs, intercom and TUI are intertwined with the useful slice. If durable detached execution and recovery dominate the product, nicobailon is a credible alternative and may be the better source to study before choosing a fork.

`goofansu/pi-subagent` is the strongest same-Effect reference. Its typed lifecycle and Pi backend are valuable if the new project chooses an in-process, session-scoped runtime, but it is a roughly 25k-line dual-backend runtime and its result store is memory-only. It should not be rejected because Effect is release-candidate software; the actual issue is migration scope and the absence of a target-host standalone gate. `j0k3r` is a strong middle-sized in-process persistent-history alternative. `everyx` is a concise persistent RPC design but targets a Pi peer range that excludes 0.85.1 and leaves extension inheritance and nested delegation broad. `tintinweb` is a capable in-process manager, but its workflow/worktree/UI surface is broad and stop is not an LLM tool. `mjakl` provides a foreground RPC reference and `aefreedman` a foreground JSON-print reference, but neither implements true background jobs. The official Pi example and HamdiMaz confirm the simple foreground baseline; andrea-tomassi and giuseppecrj are useful but solve materially different problems.

The key product distinction is lifecycle, not persistence alone. A foreground wrapper keeps the parent tool call waiting. An in-process background manager returns a task ID while retaining the child session in the host. A background RPC manager returns an ID while a separate child process runs. A detached SDK runner adds an independent process and artifact recovery boundary. goofansu, tintinweb and j0k3r implement in-process background forms; everyx and ogulcancelik implement background RPC forms; nicobailon implements the detached runner form. mjakl, aefreedman, HamdiMaz and the official example await child completion inside the tool call.

## Lifecycle and background semantics

### Foreground subprocess baseline

The official Pi extension example creates a child with `--mode json -p --no-session`, appends a system prompt from a temporary file, sends a task, parses JSON lines and waits for process close. It supports single, parallel and chain execution, but has no task registry, durable result artifacts or cross-call status; it also does not establish a restrictive extension/tool environment. Its source is useful because it shows Pi’s intended child invocation seam, not because it solves background orchestration. [Official example](https://github.com/earendil-works/pi/blob/12f59336afa67af6e996cdb6f220f0bf4cbd571a/packages/coding-agent/examples/extensions/subagent/index.ts#L249-L426).

HamdiMaz is a small variation on this baseline: it uses JSON/no-session, intersects the child tool set with parent active tools, accepts task input over stdin, and terminates a direct child with TERM/KILL. It caps parallel and chain work at eight and depth at one, but it has no independent runner or result registry. [Source](https://github.com/HamdiMaz/pi-sub-agent/blob/f1c0ae29f4cf370255530d3d126ec71b0d7a6194/extensions/index.ts#L39-L58).

mjakl is a substantially hardened foreground implementation. It accepts up to eight calls and runs four concurrently. A call may select `empty` or exceptional `parent` context, a logical named session, a cwd, inactivity timeout or absolute timeout. [Contract](https://github.com/mjakl/pi-subagent/blob/8e1b40b51440804246e312ef2a27a6399ded3186/contract.ts#L25-L83). Its child is detached into a Unix process group; cancellation and timeout signal the group, then escalate to SIGKILL. It captures RPC settlement events, bounds assistant capture at 5 MiB, and limits model-facing output to Pi’s 50 KB/2,000-line convention. [Runner](https://github.com/mjakl/pi-subagent/blob/8e1b40b51440804246e312ef2a27a6399ded3186/runner.ts#L491-L518), [termination](https://github.com/mjakl/pi-subagent/blob/8e1b40b51440804246e312ef2a27a6399ded3186/runner.ts#L585-L705), [capture](https://github.com/mjakl/pi-subagent/blob/8e1b40b51440804246e312ef2a27a6399ded3186/runner-events.js#L90-L150). Yet `executeCalls()` still awaits each `runAgent()` through bounded concurrency, so this is a reliable foreground call rather than a detached task system. Named sessions are persisted and locked, but they do not give a caller a task ID that survives the parent invocation.

aefreedman has a richer frontmatter and governance story than the official example: single, parallel and chain modes, output contracts, package agent registration, project trust fallback, and child-extension containment. Its execution path is JSON print, not RPC: it builds `--mode json -p --no-session`, spawns with ordinary pipes, parses message events and awaits close. [Execution](https://github.com/aefreedman/pi-subagents/blob/dab12e3f13c47d054dd41b6a91c6f315c1215fe2/extensions/index.ts#L477-L705). The child process is not detached and cancellation kills only the direct process. There is no source evidence for descendant cleanup, timeout watchdog, persistent child session or cross-call background task registry. Its model set is hard-coded to three OpenAI Codex GPT-5.6 variants, a major fork change for a provider-neutral stable Pi. [Model policy](https://github.com/aefreedman/pi-subagents/blob/dab12e3f13c47d054dd41b6a91c6f315c1215fe2/src/execution-profile.ts#L1-L76).

### In-process background managers

tintinweb keeps each child as an independent Pi `AgentSession` inside the parent process. `AgentManager.spawn()` returns an ID, has separate foreground/background pools, queues when the background pool is full, and settles records only once cleanup is complete. [Manager](https://github.com/tintinweb/pi-subagents/blob/e955e29c51b7a6cce37e1108cd2d6c57a77e151c/src/agent-manager.ts#L430-L705). It persists sessions and transcript files and keeps tombstones for resume. This is a credible in-process background design, but parent process failure takes down the session; the worktree feature starts from HEAD and therefore does not expose the parent’s uncommitted diff. [Worktree](https://github.com/tintinweb/pi-subagents/blob/e955e29c51b7a6cce37e1108cd2d6c57a77e151c/src/worktree.ts#L1-L117). Stop exists through UI/RPC, while the LLM-facing tools expose result and steer rather than a direct stop tool. Its workflow, mentions, scheduler, FleetView and dynamic-extension surface make an entire fork unnecessarily wide for the first slice.

goofansu is a full Effect runtime, not a thin extension. The Pi backend holds a long-lived `AgentSession`, supports prompt, steer, abort, idle waiting and terminal transcript snapshots, and uses a typed backend seam. [Backend session](https://github.com/goofansu/pi-subagent/blob/74dc62c5827ed727223fe533f656e35b329b48c2/extensions/subagent/backend/pi/session.ts#L21-L59). `agent_start` and `agent_resume` return IDs while execution runs in a background Effect fiber. Admission caps active runs at eight, bounds controls and observations, and limits in-memory result storage. [Runtime policy](https://github.com/goofansu/pi-subagent/blob/74dc62c5827ed727223fe533f656e35b329b48c2/extensions/subagent/runtime/policy.ts#L53-L128). Its weakness for a recovery-oriented product is explicit: `ResultStore` is in-memory and shutdown clears it; a host restart loses the runtime task index and stored results, including undelivered completions. [ResultStore](https://github.com/goofansu/pi-subagent/blob/74dc62c5827ed727223fe533f656e35b329b48c2/extensions/subagent/runtime/result-store.ts#L1-L24). It is the best same-Effect reference for lifecycle arbitration, not automatically the best first fork.

### Detached and durable task managers

ogulcancelik is the narrowest direct match. `spawnAgent()` creates a task UUID, session JSONL, info JSON and log under a parent-session scope; the child uses explicit cwd and detached `--mode rpc`. [Task creation](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L1135-L1219), [launch](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L1222-L1251). It exposes task listing, wait, wait-all, steering and interrupt; settled sessions can hibernate and restart from the same JSONL. Process info includes owner token and Linux identity checks to reduce PID-reuse mistakes. [Ownership](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L620-L667). This is the best narrow first experiment, but current source has no explicit depth cap if templates re-enable delegation extensions, uses many `any` boundaries, creates a private default root but does not consistently set file modes explicitly, and has a model-response timeout that does not cover tool execution. Its `process.execPath`/`argv[1]` launcher is not verified against a Bun-compiled Pi binary.

Four other gaps need focused validation. The RPC decoder has no line-size limit, and the manager has no active-agent capacity limit. Interrupt writes the terminal status before process termination is confirmed. Process cleanup runs on `exit` and destroys stdout listeners, so the final-event/drain ordering needs a regression check. These observations establish resource and state-contract gaps; they do not establish a reproduced loss of output on the target host. [Decoder](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L931-L955), [manager/admission](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L995-L1008), [interrupt](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L1788-L1850), [process cleanup](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L1286-L1346).

nicobailon is the strongest operational reference. A parent writes runner configuration and status sidecars, starts a detached runner, performs startup/ack handshakes, then returns while the runner creates the child session, writes status/events/transcript/output and publishes a result. Watchers and pollers deliver completion; canonical artifacts permit reload recovery. [Async execution](https://github.com/nicobailon/pi-subagents/blob/aa75b3353836f7868898e3bd58234d21eaff1463/src/runs/background/async-execution.ts#L398-L448), [runner lifecycle](https://github.com/nicobailon/pi-subagents/blob/aa75b3353836f7868898e3bd58234d21eaff1463/src/runs/background/async-execution.ts#L540-L748). It has fork/fresh context handling, bounded control messages, stale-run reconciliation and a clear distinction between process-terminal proof and execution success. The package also has the strongest observed host evidence: the exact-head CI run passed Linux standalone tests with checksum-pinned binaries and Pi 0.85.0/0.85.1 smoke steps. That evidence is upstream CI, not acceptance on the new project’s host.

The price is integration surface. More than 2,000 lines in `async-execution.ts` and more than 1,000 in the extension entry are surrounded by missions, workflow, scheduler, external jobs, intercom, TUI and worktree logic. The right use is to extract a single-level background runner, artifacts, control protocol and recovery rules, not to combine its whole runtime with another candidate. Its read-only policy is also a host decision: reviewer/scout plans can fail closed, but tool allowlists must be enforced by the fork.

everyx has a clean detached RPC/process model and a useful persistent continuation story. Root calls can set `run_in_background`; completion uses a wait chain and follow-up notification. Persistent children remain idle and `agent_send` steers the same context. [Background return](https://github.com/everyx/pi-extensions/blob/6cdaae394c0458fbce7947a7e8c95c51a9721a8e/packages/pi-subagent/index.ts#L634-L655), [persistent process](https://github.com/everyx/pi-extensions/blob/6cdaae394c0458fbce7947a7e8c95c51a9721a8e/packages/pi-subagent/agent-process.ts#L195-L215). Its request correlation, UTF-8 framing and bounded 1 MiB JSON line/64 KiB stderr are useful seams. The package peer range is `^0.84.0`, which excludes Pi 0.85.1; children also load Pi’s normal extension environment without a narrow inherited-extension policy, and nested delegation has no depth or concurrency cap. It is a good protocol reference after compatibility and policy work, not a drop-in base.

j0k3r offers the most explicit task API among the in-process candidates: run, continue, send message, status, result, list and cancel. It models `queued`, `running`, `stopping`, `completed`, `failed`, `cancelled` and `interrupted`, persists task/attempt/event history in SQLite, and supports `task` versus `background` mode. [Tools and states](https://github.com/j0k3r-dev-rgl/pi-subagents-j0k3r/blob/ccde60b51e5ab9ae5ff9ea0bd3eb6bae1eae7c73/src/types.ts#L1-L4), [history](https://github.com/j0k3r-dev-rgl/pi-subagents-j0k3r/blob/ccde60b51e5ab9ae5ff9ea0bd3eb6bae1eae7c73/src/history.ts#L21-L39). Its bounded steering bridge and two-stage cancel are strong. It explicitly filters `subagent_*` tools to prevent nested delegation; `continue` is a later continuation of the same task, not nested delegation. It does not create an OS runner or worktree; cwd is passed to the Pi nested session, which is appropriate when the host owns existing worktrees. Read-only remains a policy gap because an allowed `bash` tool can write. The open Issue #25 reports a possible CJK/emoji completion-card width failure on Pi 0.85.1; this is an unverified user report, not a confirmed defect. [Issue #25](https://github.com/j0k3r-dev-rgl/pi-subagents-j0k3r/issues/25).

## Additional source screenings

`andrea-tomassi/pi-open-agents` (0.1.22, MIT, [`9273b55`](https://github.com/andrea-tomassi/pi-open-agents/tree/9273b556726a5b86cce9159891094f8c4b3ecc8b)) is a foreground executor with primary-agent and OpenCode permission routing. Its executor has a narrow permission whitelist, while its default runner spawns a child and only sends SIGTERM; session-dir/resume flags exist, but the tool call awaits the runner. It is useful for permission vocabulary and routing, not for the requested background lifecycle. [executor](https://github.com/andrea-tomassi/pi-open-agents/blob/9273b556726a5b86cce9159891094f8c4b3ecc8b/src/subagent/executor.ts#L152-L179).

`giuseppecrj/pi-herdr-agents` (1.7.0, MIT, [`371265e`](https://github.com/giuseppecrj/pi-herdr-agents/tree/371265e74fb7485afbfbc7c028d60dc4f98d2779)) delegates to the external Herdr CLI and provisions panes/worktrees through shell commands. It has real-Pi/fake-provider integration material, but its pane/mux and worktree assumptions add an environment the target does not require. It is a quality reference for live lanes and process integration, not a narrow Pi fork base. ## Context, tools, worktrees and nested limits

Fresh context is not synonymous with safety. mjakl’s default empty context and aefreedman’s fixed no-session child avoid parent transcript authority, but both inherit enough Pi environment to need explicit tool policy. nicobailon’s fork context filters orchestration artifacts; ogulcancelik disables extensions, skills and context files by default, but its templates can explicitly load tools/extensions; j0k3r’s lean resource mode narrows handlers but still permits bash; everyx inherits normal Pi extension discovery. The official example uses its ordinary child runtime and does not itself impose a restrictive extension/tool policy. These are materially different policies and should not be merged by accident.

For the first `pi-stuff` vertical slice, reviewer and scout definitions should be fail-closed against a host inventory such as `read`, `grep`, `find`, and `ls`. The policy should reject missing tools and reject `edit`, `write`, shell-capable `bash`, arbitrary extension loading, and nested delegation. This is a host-enforced decision. None of the candidates provides a complete OS sandbox, and no review prompt can establish one.

A reviewer restricted to file-reading tools still needs an explicit review input: base/head identifiers and a supplied diff or an approved read-only Git access path. Removing bash without supplying that input would prevent useful diff review. A fresh conversation also needs the applicable project instructions deliberately loaded; ogulcancelik’s `--no-context-files` default makes this an integration requirement.

The requested existing-worktree behavior also argues against importing worktree creation into the first fork. tintinweb and its related workflow features create worktrees from HEAD; this is useful for implementation agents but hides staged and unstaged changes. nicobailon has worktree and task integration, while ogulcancelik and j0k3r naturally accept a caller-provided cwd. The caller can pass the absolute path of the existing task worktree; no new worktree manager is needed. A review of uncommitted changes should deliberately use the current checkout or an explicit patch; a fresh worktree from HEAD is the wrong source.

For an initial single-level feature, preserve an explicit recursion boundary. mjakl has depth/cycle guards; aefreedman and j0k3r filter delegation tool names; goofansu suppresses its own child-load registration; everyx permits nested delegation without a depth cap. tintinweb supports explicit nested permissions. ogulcancelik disables child extensions by default, but templates can re-enable them; the official example also leaves ordinary extension loading available. Continuation of an existing session is a separate capability from creating grandchildren.

Wait cancellation, run cancellation, conversation continuation and crash recovery need separate contracts. goofansu explicitly bridges wait abort signals without cancelling the Run and coordinates result consumption with completion delivery. Its result store disappears with the session, although an answer already delivered to the parent may remain in Pi's own transcript. ogulcancelik persists final info and can resume a completed child conversation; owner-death reconciliation is not a promise that an active child keeps working through parent shutdown. nicobailon separately records execution completion and observed process close. [goofansu wait](https://github.com/goofansu/pi-subagent/blob/74dc62c5827ed727223fe533f656e35b329b48c2/extensions/subagent/host/tools.ts#L194-L223), [ogulcancelik shutdown](https://github.com/ogulcancelik/pi-extensions/blob/9f2cae165dabf66a62f1579c3422bce21133bb9d/packages/pi-codex-subagents/core.ts#L1853-L1890), [Pi abort/queue contract](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/docs/rpc.md#L109-L141).

## Model and provider portability

The target is a stable Pi host, so provider selection must remain a host/catalog concern. mjakl inherits the parent effective provider/model and accepts per-call overrides. j0k3r, tintinweb, everyx and nicobailon similarly resolve through Pi configuration or caller profiles. aefreedman hard-codes only three OpenAI Codex GPT-5.6 identifiers and rejects all other selections before launch. That policy is unsuitable as inherited fork behavior. goofansu’s dual backend is architecturally interesting, but a Pi-only fork should not import the Claude surface merely because it exists. ogulcancelik’s explicit provider/model template fields are useful, while launcher and catalogue behavior still need target-host validation.

## Tests and CI: what is known

No candidate dependencies or candidate tests were installed or executed locally. “Tests” below means tests present in the source tree; “CI” means upstream workflow status queried during research. Neither means that `pi-stuff` has passed.

nicobailon has the strongest observed upstream CI signal: exact-head unit and integration jobs, Bun workflow parity, Pi 0.85.0/0.85.1 smoke and an official standalone Linux matrix all succeeded in the queried run. goofansu’s exact-head run passed Node22/npm checks but had no Bun matrix in the observed workflow. tintinweb’s run was successful, with latest Pi compatibility marked `continue-on-error`. j0k3r’s test files include real-process cancellation, history, status/result/cancel/continue tools and Bun SQLite fallback, but its CI is Node24 and no target acceptance was observed. everyx’s tests cover fake RPC framing and persistent lifecycle; they do not exercise real Pi. mjakl has Node tests covering runner, events, locks and rendering but no discovered GitHub workflow. aefreedman validates across Ubuntu, Windows and macOS with Node 22.19, npm test and package packing.

## Selection and next validation

The recommended order is conditional and deliberately narrow:

1. Fork or isolate `ogulcancelik/pi-codex-subagents` as the first validation candidate. Preserve its task artifacts, detached runner, process ownership, wait/result, interrupt and session resume seams. Remove overlay and broad template features from the first slice.
2. Build a host-owned launch adapter for the Bun-compiled Pi binary. Do not assume `process.execPath` plus `argv[1]` works after compilation; support an explicit verified launcher and record the child command without leaking credentials.
3. Decode the consumed fields at JSONL RPC, Pi event, task-info and result-file boundaries with strict TypeScript and Effect 4 decoding. Replace `any` at the boundary and make malformed or oversized input a typed failure.
4. Accept an explicit absolute `cwd` for the existing task worktree. Do not create a new worktree in this slice. Preserve the distinction between current working-tree review and a clean HEAD checkout.
5. Enforce the read-only profile in runtime tool registration. Prove that reviewer/scout children cannot load edit/write/bash-capable tools or the delegation extension. Keep nested delegation disabled.
6. Verify background spawn while the parent continues, status, result retrieval, steering, interrupt, parent reload and parent exit. Cancelling a wait must have a documented effect independent of cancelling the child. Test queued steering during abort, kill failure, and a short-lived child whose final event arrives just before process exit.
7. Bound RPC lines, active agents and result artifacts; preserve ownership reconciliation and add whole-run timeout coverage where required. Verify private file modes, malformed EOF and long-output behavior.
8. Verify the chosen slice in an existing task worktree while the stable installation remains on main. Consider nicobailon or goofansu only if the first experiment exposes a structural mismatch.

The acceptance question is not “which repository has the most features?” It is whether the chosen narrow core can return immediately with a durable task identity, operate in the correct existing cwd, enforce a real read-only policy, survive cancellation and parent reload, and collect a bounded result on the actual Bun Pi host. At present, ogulcancelik is the most direct first experiment, nicobailon is the strongest standalone/recovery comparator, and goofansu is the most relevant Effect-native alternative. None has yet been adopted.
