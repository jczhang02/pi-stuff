# Future UI from the current Pi Stuff inventory

[简体中文](../i18n/zh-CN/research/future-ui-2026-09-21.md)

The requested deliverable is the future UI for current capabilities. The previous native-output catalogue established coverage but did not answer that design question. The [main gallery](../../prototypes/ui-direction/gallery.html) now shows proposed whole conversations and per-type designs. Native screenshots remain on a separate [reference page](../../prototypes/ui-direction/current-reference.html).

## Scope and decisions

The product baseline remains `cd0f174`, with installed Pi 0.85.1. The preview revision starts at `c5813d9`. Current Web/RTK and native Pi message/tool output determine the content. This is an offline UI proposal, not production implementation or adoption.

The proposal retains the old welcome, user ``, assistant/tool `•` and result `⎿` prefixes. Tool headers show the action and target; the next line gives the result. Read/Write/Edit use syntax highlighting. Retrieval separates location from content. Web promotes query/URL and readable output while retaining content identifiers and paging metadata. Tools expand in place. No inspector, Todo, Agents, Goal, background work, BTW or session naming is added.

The primary catalogue covers 37 states from the previous native inventory. Optional custom-message/entry renderers and conditional announcements stay in the reference page. Existing diagnostic messages and compaction/branch summary messages remain covered as transcript output, without designing a notification or session-management subsystem. The old welcome and three A/B/C diff comparisons are retained. A/B/C are alternatives, not selected product requirements.

## Evidence and limits

The new renderers consume the same offline inputs as the native catalogue. Four additional scenes compose those items into complete conversations. The actual Pi editor and viewport constrain the layout; model/cost/status values are fixture content. A proposed presentation may change the order and styling of result fields, but must retain failure, truncation and paging information.

The prototype's custom message and mouse-region route demonstrates the proposed appearance and expansion only. It does not install production overrides for native user/assistant messages or tool renderers. Live providers, streaming event order, image protocols and session replay remain outside this preview. The tool image case demonstrates the text fallback only. Proposed spans do not establish a general word-diff algorithm.

Previous [coverage research and primary sources](conversation-coverage-2026-09-20.md) remain the implementation evidence. Old Pi Stuff supplies the visual reference, while the current product inventory supplies the scope. Future code lives in `future-scenes.ts`, `future-extension.ts`, `future-messages.ts` and `future-tools.ts` under the prototype directory. The existing runner captures the new scenes.

## Capture verification

The final capture pass produced 45 PNG/ANSI/text sets: 37 individual scenes, five overview variants and three Read interaction states. Every capture passed its expected-text and palette checks. Read mouse collapse/expand and Ctrl+O preserved the editor draft. The main gallery contains 52 image cards, including the retained welcome and nine diff comparisons. These results verify the offline prototype, not production providers or streaming.
