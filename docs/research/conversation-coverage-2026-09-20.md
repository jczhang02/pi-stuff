# Conversation coverage and syntax-highlighted diff alternatives

[简体中文](../i18n/zh-CN/research/conversation-coverage-2026-09-20.md)

This revision answers two questions: which current outputs need conversation UI coverage, and how an edit can preserve syntax highlighting without losing the change structure. It extends #99 and draft PR #100. These are review artifacts, not an accepted production specification.

## Baseline and scope

Current main is `cd0f174`, matching the product baseline of the retained preview branch. Installed Pi is 0.85.1 and Bun is 1.4.0. `index.ts` registers Web and RTK. Pi owns the native user/assistant/tool and session-summary presentation. Old Pi Stuff and external packages provide references; their presence in research does not make their features current Pi Stuff capabilities.

Todo, subagents, Goal, background jobs, BTW and session naming remain excluded from design work. Existing in-conversation errors and diagnostic notices are included as current output, not as a new notification subsystem. There is no independent tool inspector. Native per-tool click expansion remains the intended production detail path.

## Diff alternatives

All three views show the same five-line function becoming seven lines: one line replaced by three, `+3 −1`. The previous-page ID set filters already seen results after within-page deduplication. File path, request, surrounding explanation and test state stay identical. Each option has 120-column light/dark and 80-column light captures in the [gallery](../../prototypes/ui-direction/gallery.html).

| Candidate        | Structure                                                                                         | Useful for                                | Cost                                             |
| ---------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------ |
| A: unified       | Old/new line-number gutters, colored signs, syntax-colored content, selected new logic underlined | Continuous reading and narrow terminals   | Replacement pairs require vertical comparison    |
| B: split         | Old and new columns with aligned wrapped rows; unified below 110 columns                          | Comparing nearby fields or signatures     | Requires width; adds blank rows to align changes |
| C: paired blocks | Complete before block, then complete after block; only changed lines carry signs                  | Reading the resulting function as a whole | Repeats context and consumes more height         |

A is the most conservative starting point for conversation density. B and C remain alternatives, not automatic feature requirements. The screenshots are the decision material.

The preview uses Pi `highlightCode` on complete before/after blocks and keeps the resulting ANSI tokens through wrapping. Gutter colors carry add/remove meaning; syntax colors are not replaced by whole-line red/green. Underlined ranges are fixture-selected semantic changes. This is not a production diff parser, automatic word matcher or large-file performance test. Read excerpts in the retained candidate conversation also use syntax highlighting.

## What the references contribute

Pi's current `renderDiff` colors whole added/removed lines, and only uses word-level inverse emphasis for a one-line deletion followed by a one-line addition. Its `filePath` option is unused. Its exported syntax highlighter and ANSI-width helpers provide the necessary building blocks without new dependencies.

Codex and Gemini combine line numbers, syntax spans and wrapping. OpenCode selects split/unified according to available width; its checked threshold is greater than 120 columns, while this prototype tests its own 110-column fallback. pi-tidy-tools contributes compact transcript blocks and width-aware rendering, but its diff colors alone do not supply syntax highlighting. C's complete before/after grouping is a local proposal, not a claim about an upstream default.

## Current-output evidence boundary

The catalog is organized by render path and meaningful state, not every tool multiplied by every error. Built-in Read, Write, Edit, Bash, Grep, Find and Ls each have their own image. Powershell shares the shell renderer and is not a separate Linux default tool. Web's three tools use the generic tool card; RTK changes Bash arguments/results and uses the host error notice path. Neither extension currently supplies a custom conversation renderer.

The host also renders user and assistant Markdown, thinking, response termination, direct `!`/`!!` shell output, skill invocation, compaction/branch summaries and command status/error text. Optional extension custom messages/entries and conditional host announcements are reference capabilities, not features that current Pi Stuff registers. In-session summaries are output coverage, not a proposal for session naming or management.

Images mount native components with deterministic input. Internal host-only text compositions, where needed, are reconstructed with the same Pi Text/Markdown primitives and identified as such in the image caption. These verify appearance of the supplied state, not live providers, streaming event order, mouse expansion, history replay or every terminal image protocol. Images are real terminal exports; their message content and execution results are fixtures.

Current source: [product entrypoint](https://github.com/jczhang02/pi-stuff/blob/cd0f174f65bdbacdca265646b4e191943063d0ac/index.ts), [Web tools](https://github.com/jczhang02/pi-stuff/blob/cd0f174f65bdbacdca265646b4e191943063d0ac/src/web/tools.ts), [RTK registration](https://github.com/jczhang02/pi-stuff/blob/cd0f174f65bdbacdca265646b4e191943063d0ac/src/rtk/register.ts), [Pi conversation dispatch](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/modes/interactive/interactive-mode.ts), [native renderer map](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/core/tools/renderers/index.ts).

Old Pi Stuff was checked at `21b636eaccc487a08362165ec69ffe364e8730fb`. Its boxed welcome, transcript prefixes and tool hierarchy inform the candidate section. Its grouped retrieval, apply_patch, Goal/Todo/subagent/background and inspector components are historical references, not current-output coverage. External Pi packages contribute diff techniques only; they do not expand this product's inventory.

User image blocks are not inline transcript images in this version: `getUserMessageText` extracts text blocks only. Clipboard paste inserts a temporary image path into the editor; that path may later appear as ordinary user text. Tool-result image fallback is a separate render path. The catalog must not present a fabricated user-image card.

Web fixtures pass the actual current createWebTools definitions to Pi, without calling execute. This registered-tool fallback shows ten result lines when collapsed; the no-definition history fallback is a different path. The extension-error image exercises the real host error handler with a fixture message and stack in an isolated temporary extension. Activity indicators are frozen Loader samples, not evidence of their live transcript position.
